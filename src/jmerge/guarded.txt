# The paths jmerge merges a change to only under a stricter gate: its check has a start time,
# its review is finished at the head with every finding ended, main has not changed one of
# its paths or a CI path (ci-paths.txt) since its check started, and main is still that
# commit at the merge. jmerge's own copy of these rules must be main's. What falls short is
# printed as `wait <number> <url>: guarded (touches <path>), <reason>`. The paths jmerge
# never merges are in protected.txt, and a change to this file is one of them.
#
# One pattern per line. A line that starts with # is a comment.
# - A pattern that ends in / is a directory, and covers everything under it. With another /
#   in it, or one at its start, it is a path from the root of the repo. With none, it is a
#   directory of that name at any depth.
# - Any other pattern is a file. With no / in it, it is a file name at any depth. With one,
#   it is the whole path from the root of the repo: src/jbus/merge.py, /Makefile.
# - * matches any run of characters between two /, and never a / itself.
# - jmerge refuses to run on a pattern it cannot read: **, a leading !, a \, an empty part.
#
# The list is empty, on the user's word of 2026-10-12 ("drop the guarded merge guards"): no
# path is guarded, and a ready pull request merges with no proven safety fact at its head.
# Until then it listed acceptance/, .github/workflows/, src/jmerge/, src/jbus/ and skills/.
# The gate's code stays, and tests/test_jmerge_guarded.py runs it over a list of its own. A
# path is guarded again by a line below with its pattern and no # before it. That is a
# change to this file, so jmerge holds it and the user merges it. The tests whose names
# start with test_the_shipped_list_guards_no_path say the list is empty, and they change
# with the line: one in tests/test_jmerge_guarded.py merges a change to skills/, src/jbus/
# and src/jmerge/ with no proof, and one in tests/test_crew_skill.py asks no scoped review
# for a fix to skills/.
