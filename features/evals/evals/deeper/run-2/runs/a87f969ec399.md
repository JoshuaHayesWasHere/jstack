# parallel-tests: Run the test suite in parallel

Task: "run the test in parallel"
Done when:
- The suite's normal test command runs tests across multiple workers, for example `pytest -n auto` via pytest-xdist, set as the default in config or in the documented command.
- The full suite passes in parallel mode, run at least twice in a row with no flaky failures.
- The parallel run collects and runs the same number of tests as a serial run (`-p no:xdist` or `-n 0`).
- Any test that fails only in parallel is fixed by isolating its shared state, such as temp dirs, ports, env vars or files under `~/.claude`, and never by skipping or deleting it.
- The command for running tests serially, for debugging, is still documented.
Where: test config (`pyproject.toml` / `pytest.ini` / `conftest.py`), dev dependencies, `tests/`, any CI or Make/just target that runs the tests, and the README or CONTRIBUTING section on running tests
Do not touch: the skills, playbooks and Python commands under test, beyond fixing the shared state in fixtures that blocks parallel runs; the assertions of existing tests
Decisions: none
Design: none, it is a test-runner configuration change with no effect on how jstack itself behaves
Pull request: open one when done
Review: review
Playbook: none
