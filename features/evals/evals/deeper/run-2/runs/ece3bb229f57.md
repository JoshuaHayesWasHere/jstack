# parallel-tests: run the test suite under pytest-xdist with results identical to the serial run, and a shorter CI time
Task: "Run the test in parallel."
Done when:
- The parallel run's junit results match the serial `--junitxml=/tmp/serial.xml` record exactly across 5 randomly seeded runs (`pytest-randomly`), with no flakes
- hyperfine's median for the parallel run is at most max(serial ÷ cores × 1.3, longest test + 5 s), with under 10% spread
- The CI test job passes with `-n auto` and logs a correspondingly shorter time than its serial log
Where: `tests/`, `conftest.py`, the pytest config (addopts, plugins), the test dependencies (pytest-xdist, pytest-randomly), the CI workflow's test job
Do not touch: what any test asserts; do not skip, delete, xfail or serialize tests to meet the timing or match checks
Decisions: "Start from a serial baseline: `pytest --durations=0` saved to `/tmp/serial-durations.txt`, a `--junitxml=/tmp/serial.xml` record, `nproc` here and on the CI runner, the CI test job's own log, and a grep of `tests/` and `conftest.py` for shared tmp files, ports, databases, env vars and session/module fixtures." "Make the suite run under pytest-xdist (`-n auto`)." "Choose `--dist` (loadscope, loadfile or worksteal) by `hyperfine --runs 5`, not by guess." "Isolate any shared state that `pytest-randomly` with `--count 3` exposes, and watch `pidstat -u 1` so the tail is not a single straggler."
Design: none, the user already set the method and the measurements that pick `--dist`, so no design call is left open
