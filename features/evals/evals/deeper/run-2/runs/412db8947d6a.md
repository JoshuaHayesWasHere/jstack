# ci-chrome-hang: Find and fix why the first public check hangs at 92–95% with Chrome left running
Task: "jstack's first public check never finished: two attempts on `ubuntu-latest` hung after the dots reached 92% and 95% and were cancelled at the job's 15-minute limit, with Chrome processes still running." Find and fix the cause of that hang, and nothing beyond it.
Done when:
- The single test isolated by halving the suite's tail hangs before the fix and passes after it.
- The check on `ubuntu-latest` is green on 20 consecutive runs, each under 4 minutes.
- A final `pgrep -a chrome` step finds no Chrome left on any of those 20 runs.
- The report lists the run IDs and the stack dump that named the cause.
Where: `.github/workflows/*.yml`; the `conftest.py` fixture that starts and quits Chrome; the test that hangs alone and whatever code that test exercises.
Do not touch: anything beyond the cause of the hang. That includes other tests, other flakes, unrelated workflow jobs and refactors. Do not raise the job's 15-minute limit as a fix. The capture tooling (faulthandler/pytest-timeout, watchdog, log artifact, `pgrep` step) is there for diagnosis and proof, not as the fix itself.
Decisions: "Start from the raw runs, not the summary. Read both cancelled attempts with `gh run view <run-id> --log`. Map 92% and 95% to test IDs with `pytest --collect-only -q`, in CI's order and with CI's plugins. Read `.github/workflows/*.yml` and the `conftest.py` fixture that starts and quits Chrome." "Capture the hang before changing code. Set `faulthandler_timeout` (or `pytest-timeout --timeout-method=thread`) so the hung test dumps every stack. Add a watchdog step that records `ps -eo pid,ppid,etime,stat,cmd --forest` and `py-spy dump` of pytest. Keep Chrome's and chromedriver's logs as an artifact under `if: always()`. Reproduce on the runner's shape with `act` or an `ubuntu:24.04` container, and halve the suite's tail with `-k`/`--deselect` until one test hangs alone."
Design: none, this is a diagnose-and-fix of one hang whose method the user has already laid out, so there is no design choice to make up front.
