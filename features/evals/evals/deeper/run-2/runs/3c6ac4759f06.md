# home-limit-overruns: make homes stop before the action that would cross any of their limits

Task: "Fix the homes running past their limits." Start from the raw record, not from impressions: the homes' session transcripts in `~/.claude/projects/*/*.jsonl` (per-turn `usage` and timestamps), jbus's log of launches and stops, the `Result` sections of `tasks/*.md`, and the code where each limit is declared and enforced (`rg -n 'limit|budget|max_|deadline'`). With `jq`, build a table of every recorded run: which limit, the amount over, and the turn or launch that crossed it. Then map each limit's check against the place it is spent, and find why the check lets the spend through. Measure the whole process tree with `/usr/bin/time -v` and `pidstat`, and use `git bisect run` if the overruns began at a commit. Before changing anything, write a test that runs a home under a tiny limit of each kind and fails on today's code. Fix the enforcement so a home stops before the action that would cross its limit. Done when that test passes, and when a replay of the overrun table over the last N real runs shows zero overruns: 0 tokens and 0 seconds over, a target that is reasonable here. Show the before-and-after table so I can check it myself.
Done when:
- An overrun table built with `jq` from the transcripts, the jbus log and the `tasks/*.md` `Result` sections lists every recorded run with the limit crossed, the amount over, and the turn or launch that crossed it.
- Each limit's check is mapped to the place that limit is spent, with the reason the check lets the spend through.
- Process-tree measurements from `/usr/bin/time -v` and `pidstat` are recorded, and `git bisect run` names the first bad commit if the overruns began at one.
- A test that runs a home under a tiny limit of each kind exists, was committed before any fix, and fails on the unfixed code.
- After the fix, that test passes.
- A replay of the overrun table over the last N real runs shows 0 tokens and 0 seconds over for every limit.
- The before-and-after tables are both in the task's `Result` section, with the `jq` commands that build them, so the user can rerun them.
Where: the code where each limit is declared and enforced (found with `rg -n 'limit|budget|max_|deadline'`); the home thread's run loop and the jbus launch and stop paths; `tests/`. Read-only inputs: `~/.claude/projects/*/*.jsonl`, jbus's log, `tasks/*.md`.
Do not touch: the transcripts, jbus's log and the existing `Result` sections of `tasks/*.md` (they are the raw record; read them, never edit them); the limit values themselves (do not raise a limit to make an overrun go away).
