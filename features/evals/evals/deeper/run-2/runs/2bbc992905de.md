# parallel-tests: Run the test suite in parallel with pytest-xdist, isolation bugs fixed, CI green and faster
Task: "run the test in parallel"
Done when:
- The junit XMLs from the serial run (`pytest --durations=0 --junitxml=serial.xml`) and the parallel run (`pytest -n auto --junitxml=parallel.xml`) show the same pass/fail/skip set.
- 20 consecutive `pytest -n auto -p randomly` runs pass, each with a different seed.
- `hyperfine --runs 5` comparing serial and parallel shows parallel wall time at or under 1.5× max(longest single test + its setup, serial time ÷ `nproc`). If it does not, the durations profile names the test or fixture that sets the floor.
- The CI test step's log shows the shorter, green parallel run.
Where: `tests/` and every `conftest.py`, including all session- and module-scoped fixtures. Also the pytest config (`pyproject.toml` / `pytest.ini` / `setup.cfg`), the test dependency list (add pytest-xdist and pytest-randomly), and the CI workflow's test step.
Do not touch: Do not mark tests serial or skip them to get a green run, unless a test truly needs exclusivity. Fix the shared state instead. Do not change application code except where it hard-codes a shared temp path, port, database, env var or `chdir` that a test cannot isolate.
Decisions: "Start from the raw material, not from impressions": the serial `pytest --durations=0 --junitxml=serial.xml` run, `conftest.py` and every session- or module-scoped fixture, a grep of `tests/` for shared temp paths, ports, databases, env vars and `chdir`, the CI test step's own log, and `nproc` / `free -h`. "Use pytest-xdist (`-n auto`, with `--dist` chosen from the durations profile), pytest-randomly over several seeds to flush out order and shared-state dependencies, `hyperfine --runs 5` to compare serial and parallel wall time with its spread, and `/usr/bin/time -v` to size the worker count to memory." "Fix the isolation bugs you find rather than marking tests serial, unless a test truly needs exclusivity."
Design: none. The user has already fixed the tools, the method and the pass bar. What remains is measuring and fixing per test, not an architecture call.
