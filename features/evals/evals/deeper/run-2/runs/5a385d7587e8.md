# make-check-slowness: find what slows down `make check` and why
Task: "figure out what is slowing down make check and why"
Done when:
- A clean `make check` run is timed end to end, with the wall time recorded and how it was measured (machine, cold or warm caches).
- Each target and step `make check` runs is timed on its own, and the steps are listed from slowest to fastest.
- For each step that takes a large share of the time, the cause is named and backed by evidence: profiler output, per-test durations (for example `pytest --durations`), or a repro that runs it alone.
- Each cause is marked as either a regression or inherent. For a regression, the commit or change that brought it in is named if it can be found.
- A short write-up gives the findings and possible fixes, ordered by expected time saved. No fix is applied.
Where: the `Makefile` and its `check` target, plus the lint, type-check and test commands it calls and their config files (for example `pyproject.toml`, `setup.cfg`, `conftest.py`, `tests/`).
Do not touch: any source, test, Makefile or config change outside a scratch copy. This task is to find causes, not to fix them. Also leave CI settings and installed tool versions as they are.
Decisions: none
Design: none, this is an investigation and makes no design call
