# public-readiness-audit: Audit jstack against every public-repo check and fix what fails before it goes public

Task: "We should not take jstack public until it passes every single audit that we could potentially throw at it for what would make a good public repository"

Done when:
- A secret scan of the full git history (gitleaks and trufflehog, every branch and tag) reports no findings, or each finding is listed with its commit and the fix it needs.
- No personal or machine-specific data is left in tracked files or history, such as email addresses, `/home/<user>` paths, hostnames, tokens, or private repo or Slack URLs. Anything that is only in history is listed rather than rewritten.
- `LICENSE`, `README.md`, `CONTRIBUTING.md`, `SECURITY.md` and `CODE_OF_CONDUCT.md` exist at the root.
- The README covers what jstack is, install, quick start, requirements (Claude Code, Python version) and the skills, playbooks and commands, with a link for each.
- Every dependency's license is compatible with the chosen `LICENSE`, and `pip-audit` (or the equivalent for the lockfile) reports no known vulnerabilities.
- Lint, type check and the full test suite pass from a fresh clone that follows only the README's install steps.
- CI runs those checks on pull requests, using pinned action versions and least-privilege `permissions:`.
- `.gitignore` covers caches, venvs, local state and logs, and no large binaries or generated artifacts are tracked.
- Issue and pull request templates exist, and an OpenSSF Scorecard run (or a manual pass over its checks) has each failing check either fixed or listed with a reason.
- No skill, playbook or command runs destructive or outward-facing actions by default without a confirmation step, and anything that does is documented.
- A report at `docs/public-readiness.md` lists every audit run, the tool and command used, the result, what was fixed, and what still needs a decision from the user.

Where: the whole repo, including its git history, and in particular `README.md`, the root community files, `.github/`, Python packaging and lockfiles, skills, playbooks, commands and `.gitignore`.

Do not touch: the repo's visibility and remotes (never make it public or push to a public remote), and git history (no rebase, filter-repo or force-push; list what history rewriting would need instead). Do not change skill or playbook behaviour beyond what an audit finding requires.

Decisions: "We should not take jstack public until it passes every single audit that we could potentially throw at it for what would make a good public repository"

Design: none, because this is a checklist of standard audits plus fixes for what they find, with no architectural change. Any finding that needs one goes in the report as an open decision.

Pull request: ask first

Review: review

Playbook: none
