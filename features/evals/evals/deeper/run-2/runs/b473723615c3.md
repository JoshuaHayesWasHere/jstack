# make-check-slowdown: find what slows `make check` and why, especially what changes on GitHub's runners
Task: "Figure out what is slowing down make check and why", specifically what changes at the flip to GitHub's runners.
Done when:
- There is a table of per-target times for `make check`, with at least 5 runs per runner kind (self-hosted and `ubuntu-latest`), each with median and spread.
- The named causes account for at least 90% of the difference between the self-hosted and `ubuntu-latest` medians.
- A prediction of the `ubuntu-latest` median was made from the core-scaling curve and the cold/warm cache deltas, recorded before measuring, and lands within 10% of the measured median.
- Every second by which `make check` on `ubuntu-latest` (warm cache) exceeds the current self-hosted median is attributed to a cause.
Where: the `check:` target in `Makefile` and the files it includes; `.github/workflows/*.yml`; past runs on both runner kinds via `gh run list --json …` and `gh run view <id> --log`, with their per-step timestamps and junit XML; a new `workflow_dispatch` debug job that runs on both runner kinds.
Do not touch: what `check` runs, and the tests themselves (this task measures, it does not speed up); the triggers and behavior of the existing workflows (add the debug job beside them); which runners CI uses.
Decisions: "Start from the raw runs, not memory." Capture each runner's `nproc`, `lscpu`, `free -m`, `df -h` and `/proc/pressure` in a debug step. "Profile before explaining": time each recipe with `make --trace check | ts -s`, each test with `pytest --durations=0`, and each phase as CPU, I/O or wait with `pidstat -u -d 1`. Measure core scaling locally with `hyperfine --runs 5 'make -jN check'` for N = 1, 2, nproc. "Compare cold and warm cache in a `workflow_dispatch` job on both runner kinds." "Predict the `ubuntu-latest` median before measuring it."
Design: none, this is a measurement and attribution task that changes no design
