# check-slowdown: find what is slowing down `make check` and why

Task: "figure out what is slowing down make check and why"

Done when:
- `make check` has been timed end to end on this machine, with the wall-clock total recorded
- Each step the `check` target runs (lint, type check, tests, any skill or playbook validation) has its own timing, ranked slowest first
- The slowest steps each have a cause backed by evidence, such as profiler output, `pytest --durations`, or a before-and-after timing, not a guess
- The findings are written up in the crewmate's report: what is slow, why, and what change would speed each one up, with an estimated saving

Where: `Makefile` (the `check` target and everything it calls), the test suite and its config, lint and type-check config, and any scripts `check` invokes

Do not touch: the `check` target's coverage. Do not drop, skip or weaken any check. Do not commit any changes. This task is diagnosis only, and any fix comes later as its own task.

Decisions: none

Design: none, this is an investigation that produces findings, not a change to the code

Pull request: ask first

Review: none

Playbook: none
