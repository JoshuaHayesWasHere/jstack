# fix-home-limit-overruns: make homes stop at their token, turn, wall-clock and memory limits
Task: "Fix the homes running past their limits."
Done when:
- A new test launches a home with limit N and asserts it stops at or below N, with overshoot no more than one step.
- That test fails on the old code and passes on the new.
- Re-running the census over the homes after the fix shows zero past their limit.
Where: the code where home limits are enforced (the home's own limit checks and jbus's); the limits as written in the home and jbus config; the raw record for the census: home transcripts in `~/.claude/projects/*/<thread-id>.jsonl`, jbus's event log per home thread (`jbus log <slug>` / its sqlite store), `journalctl`, and cgroup `memory.events` / `cpu.stat` for anything killed or throttled
Do not touch: the limit values themselves; no wrapper around homes
Decisions: "Start from the raw record, not from reports." "First make a census with jq/sqlite3: every home in the past week that went past a limit, which limit (tokens, turns, wall-clock, memory), and by how much. Classify each overrun as never checked, checked too late, or counted wrong. Reproduce the worst class with a throwaway home that has an absurdly low limit. If overruns began on a date, git bisect run the repro. Fix it where the limit is enforced. Do not raise limits or add a wrapper."
Design: none, the user already set the path: census, repro, bisect, then fix at the enforcement point
