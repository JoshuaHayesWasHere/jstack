# parallel-tests: Run the test suite in parallel

Task: "run the test in parallel"
Done when:
- The test command runs tests across several workers at once, for example `pytest -n auto` through pytest-xdist.
- The full suite passes under the parallel run with the same pass, fail and skip counts as a serial run.
- Three parallel runs in a row all pass. This shows no test depends on order or on state another test shares, such as temp dirs, fixed ports, or files under `~/.claude`.
- A serial run still works, for example `pytest -p no:xdist` or `-n 0`.
- The command the repo documents for running tests is updated to the parallel form.
Where: the test config (`pyproject.toml`, `pytest.ini` or `conftest.py`), the dev dependencies, the `tests/` fixtures that share state, and the docs or scripts that state the test command.
Do not touch: what the tests assert, the skills, the playbooks, the Python commands under test, and any CI or release setup beyond the test command itself.
Decisions: none
Design: none, adding a parallel test runner and isolating shared fixtures is a settled, local change with no architecture to choose.
