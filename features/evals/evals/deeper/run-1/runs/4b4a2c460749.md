# parallel-tests: Run the test suite in parallel

Task: "run the test in parallel"
Done when:
- The project's standard test command runs tests across multiple workers by default, for example through pytest-xdist with `-n auto`.
- The parallel run passes with the same number of tests collected as a serial run.
- Three parallel runs in a row pass with no flaky failures from shared state such as temp dirs, files, ports, env vars or global config.
- A serial run (`-n 0` or equivalent) still works for debugging, and the docs or test config say how to use it.
Where: test runner config (`pyproject.toml` / `pytest.ini` / `setup.cfg`), dev dependencies, the test suite and its fixtures under `tests/`, and any CI or script that invokes the tests.
Do not touch: the skills, playbooks and Python commands' runtime behaviour. Change only test isolation and test setup.
Decisions: none
Design: none, it is a test-runner configuration change with no architectural choice to make.
Pull request: ask first
Review: review
Playbook: none
