# check-workers-fit-room: size `make check`'s pytest workers to the room the machine has, so parallel tests stop starving pbus

Task: "I want to push my machine as hard as I can without going over the edge" (2026-10-10), and "run the test in parallel" (2026-10-12)
Done when:
- `make check` no longer runs a fixed six pytest workers. It picks its worker count from the same load and core measure `room` uses, and runs fewer workers when the machine is busy.
- With the machine idle, `make check` still runs tests in parallel, with at least as many workers as #339 gave it.
- Three concurrent `make check` runs on 12 cores, plus normal crew load, keep the one-minute load under the line where `room` says wait. A pbus gate like `gate pp-doctor` can still find room for its passes during that time.
- A test covers the worker-count choice: idle, busy, and over the line, where it falls back to one worker rather than refusing to run.
- `make check` passes.
Where: the `check` target in the Makefile, the pytest/xdist settings that #339 (tests-parallel) added, and `room`'s load measure, which this work reads and reuses.
Do not touch: `room`'s thresholds and pbus's gate logic. The fix is to make the tests fit the room, not to loosen the room. Don't revert the parallelism #339 added.
Decisions: "run the test in parallel"; "push my machine as hard as I can without going over the edge"
Design: none, the change is one bounded knob (the worker count) read from a measure `room` already computes.
