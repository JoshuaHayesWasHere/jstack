# check-workers-fit-room: size `make check`'s pytest workers to the room left on the machine, so parallel tests stop starving pbus
Task: "I want to push my machine as hard as I can without going over the edge" (the user, 2026-10-10), and "run the test in parallel" (2026-10-12): since tests-parallel (#339) `make check` runs pytest on six workers, and three runners plus the crews' own runs put the one-minute load at 14 to 15 on 12 cores for over ten minutes on 2026-10-12 at 21:35 ET, so `room` said wait and pbus could launch nothing (`gate pp-doctor: no room for 10 passes`)
Done when:
- `make check` no longer hard-codes six workers. It picks its worker count from the room left on the machine (load against cores, the same measure `room` uses), and never goes below 1.
- On an idle machine, `make check` still runs in parallel and keeps the speedup #339 gave.
- With three runners and crews running at once, the `make check` runs together keep the one-minute load under the line where `room` says wait. A pbus gate such as `gate pp-doctor` can still find room for its passes. Show it with a run, or with a test that simulates the load.
- The worker count can still be set by hand (an env var or make variable), and the default is documented where `make check` is described.
- `make check` passes.
Where: the `check` target in the Makefile; the pytest-xdist settings (`-n`, in the Makefile or pytest config); the `room` command, reading only its load measure and threshold, or making them reusable
Do not touch: `room`'s thresholds and pbus's gate logic (do not loosen them to make room); the tests themselves; turning parallel tests off
Decisions: "run the test in parallel"; "push my machine as hard as I can without going over the edge"
Design: none, the change only replaces a fixed worker count with one taken from the load measure `room` already has
