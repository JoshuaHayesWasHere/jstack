# ci-chrome-hang: find and fix the test that hangs jstack's first public check on `ubuntu-latest` with Chrome left running
Task: "jstack's first public check never finished: two attempts on `ubuntu-latest` hung after the dots reached 92% and 95% and were cancelled at the job's 15-minute limit, with Chrome processes still running." Start from the raw logs of both cancelled runs (`gh run view <run-id> --log`). Use their line timestamps and the dot counts, set against the runner's ordered test list, to name the test or tests that never reported. Then read the workflow in `.github/workflows/` and the code that launches and closes Chrome. Make the hang self-reporting: switch to a per-test reporter, give each test a timeout, wrap the run in `timeout --kill-after`, and add an `if: always()` step that prints `ps -eo pid,ppid,etime,stat,cmd --forest` and `pgrep -a chrome`. Reproduce the hang in a `ubuntu:24.04` container (or with `act`), running the suspect test alone in a loop. Use `strace -f` or a backtrace to see what the stuck process waits on before you change anything. Fix the cause, not the timeout. It is done when a hang fails the job fast and by name, when a post-test `pgrep chrome` step finds nothing, and when the check passes on `ubuntu-latest` 5 runs out of 5, each in under 5 minutes.
Done when:
- The test or tests that never reported in both cancelled runs are named, from the logs' line timestamps and dot counts set against the runner's ordered test list.

- A post-test `pgrep chrome` step finds nothing.
