# usage-ledger: count tokens and context per task and per home automatically from raw transcript usage

Task: "i can montior every single aspect of work in a digestable format": today tokens and context per task and per home are counted by hand; make that automatic.

Done when:
- One day's totals match the Anthropic Console usage export (or Admin API usage report) for that day within 1%.
- The same day's totals match `npx ccusage daily` exactly.
- A task the user counted by hand reproduces the user's number.
- Zero calls in the calls table are left without a slug and a home.
- Any task's cost and peak context can be read from the view in under 10 seconds.
- The per-task and per-home views refresh on their own when transcripts change, with no manual step.

Where: the raw assistant lines in `~/.claude/projects/*/*.jsonl` (their `message.usage`, `sessionId`, `cwd`, `timestamp`, `model` and `message.id`); the project directory names, which give the home; jbus's thread log and `tasks/<slug>.md`, which map session → thread → slug; the Console usage export or Admin API usage report for one recent day; a new jq extraction step, a sqlite3 database and a refresh trigger added under jstack's Python commands.

Do not touch: the transcripts in `~/.claude/projects/`, jbus's thread log and `tasks/*.md`, which are all read-only inputs. Make no write calls to the Anthropic Console or Admin API. Commit no Admin API key and no raw usage export to the repo. Don't build the counts from existing counts or summaries, including ccusage output or the hand tallies. Those are for checking against only.

Decisions: "Start from the raw usage records, not from counts or summaries". "Extract with jq into one sqlite3 table of calls, deduped on message.id, joined to a table of session → slug → home". "Define context per turn as input + cache_creation + cache_read tokens, and report its max and last value per task as a share of the model's window". "Produce one per-task and one per-home view (tokens by type, calls, peak context %), refreshed on its own when transcripts change". Pull "the Anthropic Console usage export (or the Admin API usage report) for one recent day as the bill to reconcile against".

Design: none, the user already fixed the design: the sources, jq into sqlite3, the calls table deduped on message.id, the session → slug → home join, the context formula and the two views. Only the refresh mechanism is left to choose.
