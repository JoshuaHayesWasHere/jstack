# The verbs

`jbus` takes one verb.
`--project <name>` goes before the verb, as in `jbus --project demo queue show`, and names a project of the config.
Without it, `jbus gate`, `jbus answer`, `jbus done`, `jbus plan` and `jbus link` act on the project whose repo they are run in.
`jbus events`, `jbus t3 launch-test`, `jbus failover` and the `jbus queue` verbs take the config's one project, or, when the config has several, the one whose repo they are run in.

Each verb that jbus's help lists is in one of the three tables below.

## The verbs you type

| Verb | What it does |
|---|---|
| `jbus status` | Prints what the last pass left: the status file and the record of the pass. |
| `jbus events [--slug <slug>] [--since <time>]` | Prints the project's event log as JSON, one event a line, oldest first. `--slug` keeps the events of one slug, and `--since` keeps those sent at or after a time. |
| `jbus digest --json [--since <time>]` | Prints what waits and what moved over every project, as one JSON object. `--json` is required, since JSON is the one form there is. `--since` sets the time it counts merges from, and is a day ago when you do not give it. |
| `jbus flow [--since <time>] [--until <time>] [--json] [--rows] [--jobs] [--no-github] [--no-journal] [--journal <file>]` | Prints how work flowed in a window over every folder of jbus's state with an event log, from the event logs, jbus's journal, the jobs `jbus ci` kept, and GitHub: each row's time from approved to merged, split into working and waiting, the waits ranked by hours lost, what the hours behind a `depends` waited on at the head of the chain, how long main and each other workflow of main was red and what it held up, how long the machine had no room and why, the share left unexplained, and apart from it the share before any record of a row. It writes nothing. `--since` is 7 days ago and `--until` now when you do not give them, and both read a time with no zone in your zone. `--rows` lists every merged row with each span and the record that opened it. `--jobs` asks GitHub for each run's jobs, a call per run, for their queue time, and is refused where those calls would spend more than half of GitHub's hourly budget. `--no-github` and `--no-journal` leave out those sources, and `--journal` reads the journal's lines from a file instead. |
| `jbus budget [--calls <n>] [--wait <seconds>]` | Prints `ok` and ends 0 while GitHub's API budget, which jbus and every thread share, leaves more than its floor of 1,000 calls in each window after `--calls` more, and otherwise prints `held` and ends 75, asking again every 30 seconds for up to `--wait` seconds first, so that a skill's loop of `gh` calls waits or refuses where a pass of jbus asks GitHub nothing but its merges. |
| `jbus view [--port <port>]` | Serves the bus as a page. The page writes only your answers, your go or hold for a row or an item, and the bot's acts on `POST /act`. [The view](the-view.md) has the rest. |
| `jbus view usage [--since <time>]` | Prints how many times the view opened, showed each route, opened each item and took each action, over the last 7 days by default, from the lines the view keeps on this machine. [The view](the-view.md) says what a line holds. |
| `jbus view pace` | Prints, for each route and action, the median seconds from page load to its first time in a page this week against last week, and the change, from the same lines. [The view](the-view.md) says what a line holds. |
| `jbus view-shot <route> --out <png> [--width 1440\|390] [--home <home>] [--port <port>]` | Has headless Chromium load the route of the running `jbus view`, such as `'#/'` or `'#/<project>'`, at 127.0.0.1 and the view's port, waits for the page's first draw, writes a PNG 1440 or 390 wide and prints its path. `--home` adds `home=<project>/<home>` to the route's query, the board's key for one home, and a bare home is one of the project `--project` names or of this repo's, as `jbus link` finds it. A bare name for `--out` goes into `$XDG_RUNTIME_DIR`, or `/tmp`, and a path in a state directory is refused. With no view running it prints `no shot: jbus view is not running`, with no Chromium on `PATH` `no shot: no chromium`, and exits 1. A route that does not start with `#` is refused. Chromium runs on a temporary profile of its own, in its sandbox, and draws again once without it where it cannot make the sandbox, as in a container that gives it no namespaces. The command writes nothing but the PNG, while the page it loads counts its route in the view's `view-usage.jsonl`, as any visit does. |
| `jbus queue show\|add\|approve\|hold\|remove\|apply\|verify` | Prints or changes the queue table, or prints a row's approval record. [The queue](the-queue.md) has each verb. `jbus queue remove` takes your own words, `--message <thread id>/<message id>` or `--page <session key>/<entry id>`, or typed `--by <user> --at "<YYYY-MM-DD HH:MM zone>"`. A scout's request is a row too, launched as a read-only scout: [What a pass launches](what-a-pass-launches.md#a-scout). |
| `jbus item propose\|approve\|drop\|show\|list` | Proposes, approves or drops a work item, or prints one or every one. [Work items](work-items.md) has each verb. |
| `jbus plan [--scope <scope>]`, `jbus plan close <entry>`, `jbus plan go <entry> --message <thread>/<message>`, `jbus plan stop <entry>` | Prints each entry of a home's `plan.md` with its status, moves a finished entry out, or keeps and stops your go for an entry. [The plan](the-plan.md) has the rest. |
| `jbus word --to <project> --message <thread id>/<message id>` | Sends your word to a project's home. With `--all` in place of `--to`, it sends the word to every home. With `--scope <scope>` or `--scope every`, the root carries it to those scoped homes, each as a word of its own. jbus reads the words and their time from your message, and takes no typed word. `--from <thread id>` names the thread running the command, so jbus does not post a word that a project's home recorded back to that home. [Your word to a home](your-word-to-a-home.md) has the rest. |
| `jbus answer <number> --message <thread id>/<message id> --default` | Closes a question with your answer. `--default` says the answer is the default the thread took, and `--differs` in its place says it is not. One of the two is required. To type the answer yourself, give `--by <user> --at "<YYYY-MM-DD HH:MM zone>" <words>` in place of `--message`. |
| `jbus clear [--scope <scope>]` | Clears a home's blockers and prints one line for each: a decision that waits on you, a fix to brief or one at work. [Decisions](decisions.md) has the rest. |
| `jbus out --scope <scope>` | Prints what a scoped home still has out, one line for each: a queue row of its briefs that is not over, a crew or reviewer thread of theirs that is not settled, a question jbus holds for it, an open gate of its `gates.md`. It prints nothing when nothing is out, and the handoff closes the scope only then. It prints `unknown:` and ends 1 when jbus's last pass is over 10 minutes old. |
| `jbus decide <slug> --question <what> --reply <reply>` | Raises one decision for you by hand, such as a scope change, with the reply you can send as it is. |
| `jbus project add <name> --checkout <path> --project-id <id>` | Adds one project's table to the config. [Add a project](add-a-project.md) has the rest. |
| `jbus bot key` | The bot's key: makes the bot a new key, prints it once, and keeps only its hash. |
| `jbus wakes` | Says whether the wakes of this repo's project are failing. |
| `jbus t3 login [--wait <seconds>]` | Signs jbus in to the T3 Code server. `--wait` is how long it waits for your approval, 600 seconds when it is not given. |
| `jbus health` | Prints one line for each check of the machine (disk, timeouts, the relay and the usage quota), with its number and its limit, and exits 1 when one is over. It pages nothing. A pass runs the same checks and pages. [The health check](the-health-check.md) has the rest. |
| `jbus ci [--days <n>] [--report] [--each]`, `jbus ci --notice <field=value>...` | Records the project's Actions jobs and pull requests of the last `--days` days, 14 by default, in `ci.jsonl` and `ci-prs.jsonl`, and prints the nine CI targets with how each was counted. `--report` also writes the week's report and alerts on a missed target. `--each` runs the command for every project with `ci_report = true`, as `jbus-ci.service` does. `--notice` is for a CI job, and prints the annotation that gives the collector its telemetry. [Measure the CI](measure-the-ci.md) has the rest. |
| `jbus steps` | Prints the steps of a pass in the order they run: each one's slot, its rank and its name, with what the pass must have for that step to run. Each feature declares its steps as `STEPS` in its module, and a pass skips a step whose needs it does not meet. |
| `jbus failover --replay <items.json> --thread <id> [--dry-run]` | Replays one recorded usage limit for one live thread, makes the move a pass would make, and prints that move. It keeps the cap out of the ledger. `--dry-run` prints the move and writes nothing. [A usage limit](../working-on-jbus/tying-a-crewmate-to-its-thread.md#a-usage-limit) has the rest. |

## The verbs the units run

A systemd unit runs each of these on Linux, and a launchd agent on macOS ([The units](the-units.md)).

| Verb | What it does |
|---|---|
| `jbus poll` | Runs one pass over every project. `jbus.service` runs it each minute, and you may run it by hand. |
| `jbus alarm [--stale <limit>]` | Counts a pass that did not finish. `jbus-failed.service` runs it. With `--stale 2h`, which `jbus-stale.timer` runs, it checks that a pass ended within that time. [When jbus fails](when-jbus-fails.md) says what the count is for. |
| `jbus snapshot [--why <text>]` | Commits the homes' state tree and pushes it. `--why` puts what changed in the commit message after the time, as a home does after each edit to a `standing.md`. A snapshot that did not finish raises its own alert. [Back up the homes' state](back-up-the-homes-state.md) has the rest. |
| `jbus relay` | Takes what blocks, which jbus posts on 127.0.0.1:4390, spools it, and sends it on to the webhook of a chat bot of your own. It pages you when the chat bot is silent. `jbus-relay.service` runs it, where you set the relay up. [The relay](the-relay.md) has the rest. |

## The verbs the skills run

A skill runs each of these inside a thread, and you do not type them.

| Verb | What it does |
|---|---|
| `jbus gate <slug>` | Keeps a question for you, with its lines on stdin, and gives it a number. A crewmate or a scout runs it ([Questions](questions.md)). |
| `jbus done <slug>` | Sends a thread's result now, with its lines on stdin. |
| `jbus stop <own row> --on <row or #pr> --from <thread id> <what the root must clear>`, `jbus stop answer <scope> <own row> <answer> --from <thread id>` | A scoped home's only way to reach the root home: a stop on its own open row that another home's open row holds, or with `--outside <what>` in place of `--on`, something no home owns. jbus refuses it unless `--from` is a scoped home's thread, the row is that scope's and not merged, done or removed, the `--on` row is another home's open row, and the same stop is not open already. It keeps the stop in `stops.json` and sends it once to the thread in the root's `home-id`, read when it goes; a stop that cannot go waits, and each pass tries it again. The root answers with `jbus stop answer`, `--from` its own thread and last, which closes each open stop of that row and sends the scope one message. A stop whose row merges or is removed closes itself, and the digest counts each scope's `--outside` stops. |
| `jbus playbook <role> <brief> [--name <name>] [--named]` | Opens the playbook a brief, a request or a plan names on its `Playbook:` line, for the role that runs it: `crewmate`, `scout`, `reviewer`, `home` or `expert`. For a crewmate or a scout it prints the playbook's path and its numbered steps. It also prints a `has` or `lacks` line for each line the playbook's `Run by:` asks the brief to have, and each principle the playbook cites, in full. For the home it prints the path and an `asks of its brief:` line for each such line. For an expert it prints the path alone. For a reviewer it prints the playbook's name and each cited principle's first paragraph. With no playbook to open, it prints one line that says why, `no playbook`, or `not <role>'s` for a playbook of another role. `--name` names the playbook in place of the line, and `--named` prints the line's name and opens nothing. It is the one way a skill opens a playbook. |
| `jbus home [--directory] <brief>`, `jbus home --keep <directory>` | Prints the thread id of the home that a brief or a scout's request belongs to. It reads the id now, from that home's `home-id` file, and prints nothing between a handoff and the next start. `--directory` prints the home's directory instead. `--keep` reads lines of `<brief>` and a tab and a text on stdin, and prints the text of each line whose brief belongs to the home at `<directory>`: a home's start asks of all its rows and Results in one process. The skills, jbus and `jmerge` share this one rule (`jbriefs.home`). The `Home:` line in the brief's head, before its first `## `, names a scope by its name or by an id. Only the first word of a `home-id` file counts. |
| `jbus link` | Prints the address of this repo's project page in jbus view: at the first origin in `JBUS_VIEW_ORIGINS`, else at the first name in `JBUS_VIEW_NAMES`, else at `JBUS_VIEW_HOST`, and last at 127.0.0.1, at the view's port. The home skill ends a status reply with it. A repo the config does not name is refused. |
| `jbus forget [--dir] <path>...` | Deletes the files a skill's step names, so that no step holds an `rm` for Claude Code to stop on. It deletes a path only inside the homes' state (`JBUS_HOME_DIR`, `~/.local/state/home`) or the git directory of the repo it runs in, and checks every path before it deletes any. Any other path is refused with a line that names it, nothing is deleted, and it exits 2. A directory is refused too, but with `--dir`, which removes it when it is empty. A path that is not there is no error. It prints each path it removed. |

## Times, projects and stdin

A `<time>` of `--since` is written in ISO 8601, such as `2026-10-12T15:00` or a day alone.
A time with no zone is in your time zone.
In `--at`, `<zone>` is your `timezone_label`, or the word your time zone prints for that time, such as `CEST`.
`jbus` refuses any other word.

`jbus poll`, `jbus alarm`, `jbus health`, `jbus relay`, `jbus snapshot`, `jbus ci --notice`, `jbus status`, `jbus digest`, `jbus flow`, `jbus budget`, `jbus view`, `jbus view-shot`, `jbus steps`, `jbus playbook`, `jbus home`, `jbus forget`, `jbus project add` and `jbus t3 login` read no project, and `jbus word` takes its own from `--to` or `--all`.
`jbus gate`, `jbus done`, `jbus queue add` and `jbus queue apply` read stdin, and wait for it when nothing is piped in.
