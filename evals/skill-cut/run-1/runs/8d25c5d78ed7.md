### Intent
> P6 of the audit: in `skills/crew/SKILL.md` "A conflict", once a crewmate has written `fixed and green`, a third rebase forced by main is not made. The crewmate writes one stop line in its Result and pipes a gate, and jbus shows the pull request as waiting. The count lives where jbus or jmerge can read it. A suite test drives three rebases and finds the stop on the third. `make check` and `jgauge test-slot -- make check` pass. How a rebase is pushed (`--force-with-lease`) is untouched.

### Act On

1. **The held pull request reads as waiting on its crewmate, not the user** (A1, B1). `REBASE_HELD` maps to the `rebase` step, which `work.py:287` draws as "Rebase, its crewmate".
   - The crewmate is forbidden to act until a `Rebase hold lifted:` line exists. The added skill text (SKILL.md:118) says the opposite of what the board shows.
   - It is right only while the gate is open and outranks it. Once the gate is answered or never parked, the row is wrong for good.
   - The repo already routes user-only waits to `hold` (`NOT_UPHELD`, `UNRULED_DROPS`).
   - Fix: move the pattern to the `hold` rule in `src/jbus/merge.py:97` and change `tests/test_jbus_merge.py:288` to `"hold"`. This is the done-when line "jbus surfaces it as waiting", met in letter but not in meaning.

2. **The cap counts from any `Fixed:` line, not from "fixed and green"** (A2, B3). The first done-when line names `fixed and green`.
   - `Fixed:` is written before any check passes, and `Fixed: none needed` is written regardless of CI.
   - Rebases a red pull request needs in order to go green use up the cap, so it is held before it was ever green. That inverts the cap's purpose: stopping churn on work that is already done.
   - The PR's reason (the green signal is only sent, never written) points to the cheap fix inside **Where**. Have the crewmate append a line such as `Green: <head>` to its Result when it sends `fixed and green`, and count from that.
   - If the home prefers to keep `Fixed:`, the PR must say plainly that it deviates from the done-when line. Leaving the deviation unstated is not acceptable.

3. **Re-running the block on a held head tells the crew to park a second gate** (A3).
   - The block prints `hold:` on every run, and the prose says to park a gate on `hold`.
   - `mainmoved.py` wakes red pull requests once per main commit, and a held pull request is usually red. So this is a real path, not a hypothetical: each wake would put another identical question to the user.
   - Fix: print a distinct word (`held:`) when the line already exists, and gate only on the first `hold:`. This is the "run twice" check the review asks for.

4. **The count reads the whole brief, not the last Result** (B2).
   - SKILL.md:159 says every block reads the last result.
   - After a follow-up round writes a new `Fixed:`, the old `Rebased after fixed:` lines still count, so the new round's first conflict is held at once.
   - Fix: reset the counters on `/^## Result/`, or count only after the last green marker from item 2. Both fixes touch the same awk and should land together.

### Consider

- **The tests don't exercise jmerge's `waits()` path or the stopped-rebase count** (A5, B4).
  - The required three-rebase test exists and runs the shell, so the "Proves it" line is met.
  - But the new ordering and early return in `src/jmerge/cli.py:703` are untested, and so is the `counted` call on a conflicting rebase (SKILL.md:443). Either could be deleted and the suite would stay green.
  - Tradeoff: two small cases (one where main touches the branch's file, one assertion through `waits()`) for code that is new in this PR. Cheap enough that I lean toward doing it.
- **The hold is recorded at local `HEAD`, while jmerge compares GitHub's head** (A4).
  - It only bites after a refused push followed by another main move. In that case the gate is still parked, but jmerge reports some other reason.
  - The block already has the pushed head from `gh pr view`, so the fix is one word. Worth taking if the awk is being touched anyway.

### Noted

- **The test helper's `home` argument also switches the slug** (A6). Test-local coupling that breaks nothing today.
- **The block's de-dup and `rebase_held` disagree on what "the current hold" is** (B5).
  - The path needs a lift and then a return to the exact same head, which is contrived.
  - If item 3's fix is written, have it de-dup against the last hold-or-lift line, as `rebase_held` does, and this goes away for free.
