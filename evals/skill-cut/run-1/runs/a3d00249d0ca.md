### Intent
> Add a `Proves it:` line to `templates/brief.md`, right after `Done when:`. The brief parser and jbus's pre-launch checks accept it only when it names something outside the agent: a test, metric, dataset, external judge or the user. They refuse empty lines, the template text, and proofs by the crew, crewmate, reviewer, agent, "self", "the model" or a review alone, giving a one-line reason. Briefs missing the line are grandfathered or refused without stranding approved rows. Tests cover every accepted and refused kind, and the docs and home skill name the line.

### Reviewers
- Reviewer A: 7 findings (3 warnings, 4 nits)
- Reviewer B: 6 findings (1 critical, 2 warnings, 3 nits)
- Both reviewers answered the review skill's questions. They agreed on four of their issues: loose `_OUTSIDE` patterns, the duplicated head loop, the unused `Brief.proof`, and the Done-when items that can't be checked from the diff.

### Act On

**1. `_OUTSIDE` keywords accept self-referential proofs, and the tests don't cover it** (A1, B1, B2)
`proof()` returns success on the first `_OUTSIDE` match and never consults `_SELF`. The patterns are bare keywords: any backticked text, `make \w` (which matches "make sure"), `\btests?\b` (which matches "self-test"), any `%`, "judge", "eval", and "his word". As a result, "the crewmate will make sure it works", "the reviewer is 100% sure" and "`self`" all pass. These are exactly the proofs the task names as refused. `dispatch._ready` launches whenever `proven()` returns `""`, so this regex is the whole gate.

Both reviewers found this independently and gave concrete inputs that pass today. B2 explains why it slipped through: every `REFUSED` case is a short phrase with no trigger word, so the suite only tests the happy side of the precedence rule. The fix:
- Make the outside patterns specific: a path or `test_\w+`, backticks only around a known tool (`make <target>`, `uv`, `pytest`, `jbus`), and `%` only near a metric word.
- Add executing `REFUSED` cases for each example both reviewers gave.

### Consider

**2. Grandfathering by absence lets new briefs skip the line** (A2)
`proven()` passes any brief with no `Proves it:` line, whenever it was written. The Done-when asks for *existing queued* briefs to be handled without stranding them, so a new brief that omits the line goes around the gate. The only thing stopping that is prose in the home skill.

The tradeoff: the Done-when says to handle this "as the Design line was introduced". If `designed()` grandfathered by absence too, this matches the precedent and the template already carries the line. Check how Design did it. If a cut-off on the row's `approved` time is cheap, it closes the loophole without stranding anything.

**3. Design and proof faults raise two gates in sequence** (A3)
A brief that fails both checks costs the user two edit-and-approve rounds, because `proven()` only runs once `designed()` passes. Collecting both faults into one gate keyed by the brief sha is a small change to lines this PR already touched. It is worth doing if both failing at once is plausible. It probably is for briefs written before either line existed, but those are grandfathered, so the real frequency is low.

**4. Template-text detection by a leading `<`** (A6, B5)
The check fails in both directions:
- B5: a real proof like `<= 50 ms p95 from jgauge` is refused as template text.
- A6: the guide text with its brackets removed is accepted as "a test".

Matching `^<[^>]*>$`, or comparing against the template's actual line, is trivial and exact. The impact is low, but the fix costs almost nothing.

### Noted
- **Duplicated head-scanning loop, and `proven` as a pass-through** (A4, B3). The duplication is real, but the proper fix (a shared `head_line` helper, moving `designed`) touches code under "Do not touch". Note it for later. With only two checks, the `(kind, check)` tuple loop is premature.
- **`Brief.proof` and `Proof.said` have no consumer outside the tests** (A5, B4). This is a small amount of dead surface. Drop it if it's convenient, but it isn't blocking.
- **The Result statement and the real queued-brief launch run can't be seen in the diff** (A7, B6). Correct, but there's nothing to fix in code. Verify both in the crewmate's Result before closing.

### Dismissed
