### Intent
> Task: sections 1, 2, 5 and 6 of the /deeper design. It adds a manual `/deeper` skill that answers the four questions and returns a rewritten prompt. It adds the 25th principle, `depth-over-breadth`, registered in jdrift and counted everywhere, and credits Felix Rieseberg in `THIRD_PARTY.md`. It adds a blind, rerunnable eval in `evals/deeper/` over about 10 past briefs, whose committed result says honestly whether /deeper won. A loss is a finding, not a reason to tune the eval.

### Reviewers
- Reviewer A: 5 findings
- Reviewer B: 8 findings
- They converged on three issues: the eval's "outside" measure and verdict, the uncontrolled `raw` measure, and the destructive `write()`. B alone covered the skill, the principle card, jleak redaction and jdrift.

### Act On

1. **The eval's "won" verdict is not supported by its own evidence.** (A1, B1, merged)
   - A rescored the committed run-2 briefs. With the backtick branch of `OUTSIDE` removed, plain scores 0.34 and deeper scores 0.33. So the whole deeper gain on "proof outside" comes from inline code, which the skill tells writers to use.
   - B showed that run 1 lost under the rule (4 up, 6 down). The only change before run 2 was the rewrite's output format, from a fence to a block quote. Run 2 then "won" on the very measure that flipped sign in 8 of 10 cases.
   - Together these mean "lost on none" rests on a formatting proxy and on run-to-run noise. The task said a loss is a finding, not a prompt to rerun until it passes.
   - **Fix:**
     - Restrict the backtick branch to commands that are actually run, or drop it.
     - Rescore the committed briefs. This needs no model calls.
     - State the Result as "won on raw and instruments in both runs; proof outside not shown; the no-loss condition held in one run of two", or apply the rule to both runs pooled.
     - If the fence-to-block-quote change was needed for `rewritten()` to parse at all, the README should say so. That makes run 1's numbers suspect rather than a clean loss.

2. **The `raw` measure has no control for the skill's own example list, yet the README claims it does.** (A2, B2, consensus)
   - Seven of the twelve `RAW` keys match question 2 of `skills/deeper/SKILL.md` almost word for word.
   - Despite that, "What holds" says the gain is "not only by copying the skill's own examples". Only instruments are backed by a `beyond` count.
   - **Fix:** add a `beyond` for raw, mirroring `SKILL_EXAMPLES`, and rescore. Otherwise, narrow the README sentence to instruments.

3. **`write()` deletes the committed `runs/` and `deeper/` before the first `claude -p` call.** (A3, B3, consensus)
   - Any failure leaves a partial `runs/` behind:
     - a missing `claude` binary
     - a non-zero exit
     - a timeout
     - a missing block quote
   - That partial `runs/` sits next to a stale `key.json` that `report` then refuses. Nothing can resume, so recovery is only from git.
   - "Rerunnable by one command" is a Done-when line. A rerun that can destroy the results does not meet it.
   - **Fix:** write into a temp directory and swap it in after `key.json` is written. Add a `shutil.which("claude")` precheck as well.

4. **Redaction silently turns off when the jleak config isn't at `~/.config`.** (B4)
   - `_private` ignores `XDG_CONFIG_HOME`, which `jleak.cli` honours.
   - It also swallows `jleak.Missing` and returns `()`. The eval then writes cases, briefs and model output into a public repo unredacted, with no warning.
   - This is a single-reviewer finding, but it is a security one and the failure is concrete.
   - **Fix:** resolve the path the way `jleak.cli` does, and fail closed when the patterns don't load.

### Consider

- **The `SELF` regex disqualifies any proof line containing "review".** (B5)
  - It penalises `rs-parallel-reviews` for its subject rather than its judge.
  - This belongs in the same rework as Act On #1, since it is the same measure. It is cheap to fix while rescoring, but it does not change the verdict on its own.
- **`not_held` counts a phrase across the whole brief and misses "did not hold".** (A4)
  - The README's "Seven of the ten…" outcome claim is read off this count, and the outcome half is a Done-when line.
  - Either scope the count to the Result section and match the tense variants, or relabel the column. Neither is costly.
- **The principle card's leans list `perf-issue` and `investigation`, and neither links the principle.** (B6)
  - On every other card, the leans match real references, so this card claims usage that does not exist.
  - Trim the list to `deeper` now. Linking from the playbooks is outside **Where** and is for later.
- **The gate placeholder `Context: <the four answers… in one line each>` reads as four lines.** (B7)
  - `mirror.field` keeps only the first line, so answers 2 to 4 would be dropped silently.
  - This is a one-line wording fix in a file inside **Where**.

### Noted
- **A5, test isolation:** importing `eval.py` leaves `evals/deeper` and `src` on `sys.path` and registers a bare `score` module for the rest of the test session. This is real hygiene, with no failure observed yet. It is worth a path-scoped import if the file is being touched anyway.
- **B8, `Pinned.own` default:** the default `= ()` is unused because the only constructor always passes `own`. It is harmless, so drop it in passing if convenient.

### Dismissed
- None. Every finding names a concrete changed line and a real effect. Even the nits are accurate, just low-stakes.

### Agreement Map
The two reviewers converged hardest on the eval, and that is where the PR is weakest.
- **Shared findings:** both independently caught the uncontrolled `raw` measure and the destructive `write()`.
- **Complementary angles on "outside":** A attacked the measure itself and B attacked the verdict process. A's rescoring shows the gain is a formatting artefact, and B's run comparison shows the verdict depended on a rerun. Each finding makes the other stronger.
- **B alone covered everything else:** the skill, the principle card, jleak and jdrift. Its non-eval findings are mostly nits, which suggests those parts are sound.

The pattern is clear. The skill, the principle and the jdrift wiring are in good shape. The eval's machinery works, but its headline claim does not hold up. The fix is honest re-reporting from a rescore of the committed briefs, plus making the rerun non-destructive. No new model runs are needed to fix the claim.
