### Intent
> Build /deeper from Felix Rieseberg's "four types of ambition":
> - a manual skill that answers the four questions and gives a rewritten prompt, which a home takes as the default behind a `jbus gate`;
> - the 25th principle, `depth-over-breadth`, listed by jdrift as a jstack source, with every count saying 25;
> - the credit in `THIRD_PARTY.md`;
> - a blind eval of about 10 past briefs, with and without /deeper, scored by something other than the writer on raw sources, instruments and outside proof. It is rerunnable by one command, its results are committed, and its Result says plainly whether /deeper won.
>
> `make check` and `jgauge test-slot -- make check` pass.

### Reviewers
- Reviewer A: 5 findings
- Reviewer B: 8 findings
- They agreed on two findings independently (the raw measure and the destructive `write()`). They reached the same weakness in the "outside" measure from two directions.

### Act On

**1. The eval's verdict "won" rests on an "outside" measure that is both a formatting proxy and run-to-run noise.** (A1, B1)
- A's rescore shows the backtick branch of `OUTSIDE` (`evals/deeper/score.py`) accounts for the whole plain-to-deeper rise in run 2. Without it, both arms are at about 0.33.
- B shows the same measure flipped sign on 8 of 10 cases between run 1 and run 2. The skill changed only its output format between them (fence to block quote).
- Together, "lost on none" is not shown, and the README's "won" on run 2 alone is not backed.
- The task names this exact trap: a non-win is a finding to report, not a reason to adjust and rerun.
- Fix:
  - Make a backtick span count only when it holds a command that is run, or drop that branch.
  - Rescore the committed briefs from both runs. This needs no model calls.
  - Rewrite the Result from what both runs agree on, e.g. "won on X in both runs; proof outside not shown."
  - Do not decide the new wording ahead of the rescore.

**2. The `raw` measure largely counts the skill's own example list, and the README claims the opposite.** (A2, B2, a consensus finding)
- Seven of the twelve `RAW` kinds match question 2 of `skills/deeper/SKILL.md` almost word for word.
- The README's "What holds … not only by copying the skill's own examples" is backed only for instruments.
- Fix: add a raw `beyond` count without the skill's listed kinds, as `SKILL_EXAMPLES` does for instruments. Rescore, then state what survives, or narrow the claim to instruments.
- This lands together with item 1, since the Result is rewritten once.

**3. The one documented command wipes the committed briefs before any model call.** (A3, B3, a consensus finding)
- `write()` runs `rmtree` on `runs/` and `deeper/` first, then makes 60 `claude -p` calls. It writes `key.json` only at the end.
- One failure, a timeout, or a machine without `claude` leaves:
  - a partial `runs/`,
  - a stale key,
  - nothing that can resume.
- This breaks "rerunnable by one command", which is a Done-when line, and it is the crashed-halfway case.
- Fix: write into a temporary directory and swap it in after the key is written. Check `shutil.which("claude")` up front.

**4. Redaction silently turns off when the jleak patterns are not at `~/.config`.** (B4)
- `_private` (`evals/deeper/eval.py`) ignores `XDG_CONFIG_HOME`, which `jleak.cli` respects. It also swallows `jleak.Missing` and returns `()`.
- Cases and model outputs then go into a repo meant to be public, with nothing redacted.
- It was raised by one reviewer, but it is a concrete path to leaking private text, and the fix is cheap:
  - resolve the path the way `jleak.cli` does;
  - fail loudly when the patterns are missing.

### Consider

- **"Not held" counts a phrase** (A4).
  - Problem: it counts "does not hold" anywhere in the brief and misses the tense variants. Yet the README reads "seven of the ten" off it as a per-brief fact about how each merged brief turned out.
  - Tradeoff: scoping the search to the Result section is small work. Relabelling the column as a phrase count is the cheaper honest fix.
- **`SELF` disqualifies any proof line containing "review"** (B5).
  - Problem: the regex matches the subject of `rs-parallel-reviews`, not who judges the result. That pulls that case to the bottom of the tables.
  - Tradeoff: it affects one case of ten. Since the outside measure is being rescored anyway (item 1), tightening it now is nearly free.
- **The principle card lists `perf-issue` and `investigation` as leans, but neither links the principle** (B6).
  - Problem: this is a false claim on the explained page.
  - Tradeoff: trimming the list to `deeper` is a one-line fix inside the Where line. Linking the playbooks is outside it and is for later.
- **The gate's `Context:` placeholder invites four lines, and jbus keeps only the first** (B7).
  - Problem: answers 2 to 4 would be silently dropped from the gate record. The test fills in a single line, so it never covers this.
  - Tradeoff: it is a wording fix in `skills/deeper/SKILL.md:67`. Optionally, add a test that writes the placeholder as worded.

### Noted
- `eval.py` leaves `evals/deeper` and `src` on `sys.path` and registers a bare `score` module for the rest of the test session (A5). It is real hygiene, but nothing collides today. Use a path-scoped import if the file is touched again.
- `Pinned.own = ()` is a default no caller uses (B8). Making it required is fine but optional.

### Dismissed
None. Every finding names a concrete path. The two nits in Noted are valid, only low-impact.

### Agreement Map
- **Where they agreed:** both reviewers independently found the raw-measure gap and the destructive `write()`. Those are the strongest signals here.
- **Where they converged:** on "outside" they came from different angles. A rescored the briefs and found a formatting proxy. B compared the two runs and found the measure flipping sign. The two views reinforce each other: the one measure the verdict depended on is not measuring a judge.
- **Where only B looked:** B alone covered redaction, the principle card and the gate text. A stayed inside the eval's scoring and its tests.
- **What the pattern says:** the skill, principle and wiring look sound. The weakness is the eval's measures and the strength of the Result it claims.

What blocks is getting that Result honest:
1. Fix the two measures and rescore the committed briefs, which needs no model calls.
2. Restate the verdict from what both runs support.
3. Make the one command safe to run.
