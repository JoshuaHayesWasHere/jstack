### Intent
> Eliminate the Exec home, which the user said "can completely go, we are moving from this pattern." Sous Chef becomes the one orchestrator: escalations reach it through jbus's webhook, and the user's word comes down by `jbus word`. This PR is step 4 of `scouts/exec-home-removal.md`. It strips Exec from the new-home, home and handoff skills, from `jroles`, from jbus text and the retired cleanup, from the docs and README, and from the tests that pinned it. It is done when `rg` finds only shell `exec` and `make check` passes.

### Act On
- **The new home line adds a standing rule the brief did not ask for** (A5). At `skills/home/SKILL.md:98`, "A home sends no other thread a status" goes beyond the brief's one line. The brief also says not to touch home text it does not name. This file is instructions an agent follows, so an extra clause changes behaviour. It also contradicts the home messaging its own crewmates and scouts. Fix: use the brief's sentence as written.

### Consider
- **The `[exec]` table is no longer warned about or redacted** (A1, B1). The tradeoff: the brief's "keep any behaviour, renamed" cannot be met literally. The table key *is* `exec`, so any code that names it fails the `rg` Done-when line. The exposure is also low: nothing reads that table, so nothing prints its URL or key for redaction to catch, and the live config has no such table. Two cheap options:
  - Have `_ignored` flag any unknown top-level table generically. This keeps the "remove it" nudge and needs no Exec name.
  - Record in the PR that dropping this was deliberate.

  Either is fine. Shipping silently is not.
- **The party handoff machinery has no real party left** (A3). The point stands: experts carry a `CHARTER.md` and are never party homes, and the tests now invent a `desk` party to keep the path alive. That fits "we are moving from this pattern." But the brief scoped the handoff change narrowly: the `exec` role and case, and the pair-telling block. A whole-section removal belongs in a follow-up brief, not in this PR.
- **The `who()` doc line now describes Sous Chef's approvals wrongly** (B4). The changed `docs/jbus.md:279` says every session is "the `<directory>` home". With Sous Chef as the sole orchestrator running `jbus queue approve`, that is now the common case it gets wrong. The code mislabelled the Chef's runs before this PR too, but the doc line is new. Rewording it to "the name of the directory it ran in" costs nothing.

### Noted
- **The `exec-webhook` streak cleanup was deleted, not renamed** (A2, B2). The same `rg` constraint applies as for the `[exec]` table: the streak key names Exec. B confirmed the live `streaks.json` and project state directories hold no leftovers. Add one line to the PR description saying so.
- **Files changed outside the Where line** (A4, B3). `project.py`, the t3 fixture README, `test_jbus_view.py` and `test_home_on_bus.py` are wording changes the `rg` Done-when line forces, so they trace to the task. The one behavioural change, in `__init__.py`, is covered under Consider.
- **The gauge fixture still uses the removed pair-telling message** (A7, B5). This is harmless, since `t3_thread_send` is still a call the handoff makes. Swapping in a pass-on-shaped message is a nice touch while in the file.

### Dismissed
- **The roles test pins the tuple literal** (A6). The suggested fix, `exec: …` as the refused line, would put `exec` back into `tests/` and fail the `rg` Done-when line. `orchestrator` as the unknown role is fine, and the behavioural assertions already exist.

### Agreement Map
The reviewers converged on the key judgment call: two pieces of retired-Exec reconciliation (the `[exec]` table handling and the streak cleanup) were deleted rather than renamed. Neither noticed that renaming is impossible under the `rg` gate, because the retired names *are* the data keys. So the real question is whether to record the deletion or add generic handling, not whether to keep Exec code.

Where they diverged, each saw a different face of the same theme, the orchestrator pattern changing:
- A saw the leftover party machinery.
- B saw the orchestrator's approvals now mislabelled.

Nothing found is a correctness bug in live use. The PR is close: fix the extra home clause, record the two deliberate deletions, and it ships.
