### Act On

**1. The shell is drawn only when there is a project read, so the not-found page loses its sidebar and machine row** (A1, A7, B6)
- One root cause sits behind three findings.
- In `poll`, the `/stack.json` callback re-renders only `if (S)`. On a no-such-project route, `S` is null. If the 404 arrives first, the sidebar stays empty until the next poll, up to 15 s later.
- `machineOf` returns null whenever `PROJECT && !S`, even though `STACK.machine` has already been fetched.
- The not-found page is where the sidebar matters most, because it is how you get out. The new test docstring also promises the machine is "drawn once, on every view".
- Fix:
  - Drop the `S` guard on `render()`. `put` already skips unchanged parts.
  - Have `machineOf` fall back to `STACK.machine` when there is no `S`.
  - Add a test that loads `#/nope` and checks the sidebar items and the machine row on the first poll.

**2. The sidebar dot and the overview row judge health by two different rule sets, and they already disagree** (A2, B5)
- Both reviewers found this independently, and each gave a concrete divergence:
  - `troubles` ignores `h.blind`, so a project with only blind spots shows an amber "Blind N" chip but a green dot.
  - `troubles` prints "0 failed wakes, last error: X", a case the row chip guards against.
- The health dot is a "Done when" item, and a dot that contradicts the row beside it is wrong.
- Fix: one helper per health fact that returns state and tip. The chips and the dot (amber if any entry is amber) both read from it.

**3. "read HH:MM" shows the current time while the server is unreachable** (A3)
- When polls fail, `lost()` sets `NOW = Date.now()` and re-renders. The header then claims a fresh read that never happened, and the time advances on every failed poll.
- The task line is "the time of the last read". This is the one case where that time matters, and the new label makes a false claim.
- Fix: record the time of the last successful answer in `took`/`tookStack`, and show that value.

**4. The word-cap test was loosened by moving content out of what it measures, and the new shell cap only fits three projects** (A4, B1, B2)
- `words` now counts only `<main>`. The machine row used to be inside `<main>` on the overview and counted toward the 250. Now it falls under neither cap.
- This turns the user's explicit 250/150 decision into a proxy check.
- `SHELL = 30` is a fixed number, but the docstring says the shell grows with each project. The fixture already measures about 26, so two more projects fail the test for no real reason.
- Fix: hold the whole first screen (header, sidebar and main) to `WORDS`/`EVERY`. If a separate shell figure is still wanted, make it a base plus about 2 per project, and test it with more than three projects.

### Consider

**The jbus item's `unwell` on a project page comes from a stale or missing `/stack.json`** (B3)
- This is a real gap. When the stack request fails silently, `STACK` is null, `unwell` becomes `[]`, and the item reads "passing". The rest of the row is fresh.
- Tradeoff: the clean fix is to derive `unwell` from `S.sources`. That may need the server to add a `machine` flag, which is outside the "Where" line.
- A cheap step inside scope is to show "unknown" rather than "passing" when `STACK` is absent. The full fix is noted for later.

**`page.html` crosses 1,000 lines (979 → 1067)** (A5, B4)
- The shell renderers are a self-contained ~90 lines, and the `panels/` inlining pattern would keep the page one served file.
- Tradeoff: the user said "one vanilla file", and wiring a new panel may touch `__init__.py`, which is outside "Where".
- The PR should state which choice it made. If it splits, the split is noted for later.

**The sidebar's sticky offset is hard-coded to 50 px** (A6, B8)
- The header can wrap between 900 and 1100 px, and then the sidebar slides under it.
- A shared CSS variable is a few characters to add. It is not a blocker.

**The theme control became a single cycle button** (A8, B9)
- The task did not ask for this, and it is untested.
- Header space at 390 px may justify it. If so, say so in the PR and add a test that clicks through auto → light → dark → auto. Otherwise restore the three-button group.

**A stale comment** (B7)
- "One request a poll" is now false, because project pages also fetch `/stack.json`.
- It is a one-line fix and worth doing in passing.
