### Intent
> Section 4 of the /deeper design: add a `Proves it:` line to `templates/brief.md` right after `Done when:`. The brief parser and jbus's pre-launch checks accept it only when it names something outside the agent: a test, metric, dataset, external judge or the user. They refuse empty, template, self-referential and review-only answers, with one line saying why. Briefs without the line are either refused or grandfathered, whichever does not strand an approved row. The change needs tests for every accepted and refused kind, doc and home-skill updates, and green `make check` / `jgauge test-slot`.

### Reviewers
- Reviewer A: 7 findings
- Reviewer B: 6 findings
- Both reviewers found the same core defect: loose `_OUTSIDE` patterns are checked before `_SELF`. They also agreed on the duplicated head-line loop, the unused `Brief.proof`, the `<` template check, and the two Done-when items that can't be seen in the diff. Only A found the unbounded grandfathering and the double gate.

### Act On

**1. The gate accepts self-referential proofs** (A1, B1, B2, merged)
`proof()` passes on the first `_OUTSIDE` match and never consults `_SELF`. Bare tokens trigger that match:
- any backticked span
- `make \w` (which matches "make sure")
- `\btests?\b` (which matches "self-test")
- any `N%`
- `judge`
- `eval`
- `his word`

As a result, "the crewmate will make sure it works", "the reviewer is 100% sure" and "the model is the judge" all launch. This line is the whole purpose of the feature. `dispatch._ready` launches whenever `proven()` returns "", so this is a correctness bug on a concrete path, not a hypothetical. B2 is the same problem seen from the test side: `REFUSED` contains only clean short phrases, so the risky precedence rule is pinned only on its happy side.

Fix:
- Make the outside patterns specific:
  - a test path or name (`tests?/\S+`, `test_\w+`)
  - backticks around a known tool (`make <target>`, `uv`, `pytest`, `jbus`, `jgauge`)
  - `%` only near a metric word
  - "the user"/"the operator" rather than "his …"
- Add each reviewer example as an executing `REFUSED` case.

Keep "the crewmate runs tests/test_x.py" accepted.

**2. Grandfathering has no end date** (A2)
Any brief without `Proves it:` launches, including briefs written after this change. The Done-when allows grandfathering only for *existing queued* briefs so that approved rows aren't stranded. As written, leaving the line out bypasses the gate, and the requirement survives only as prose in the home skill. That is the "rule in prose" pattern the task warns against.

Fix: tie the exemption to data the queue already records. For example, exempt rows approved before the cut-over (or whose `brief_sha` was in the queue at that point), and gate a missing line on anything approved after it. No approved row is stranded, and new briefs must carry the line.

### Consider

**3. One gate per brief, not one per fault** (A3, plus the in-PR part of B3)
A brief that fails both `designed` and `proven` costs the user two edit/re-approve rounds, because the proof check runs only after the design check passes. Collecting both faults into one gate is cheap. It also replaces the `short, kind = …; if not short:` juggling with a loop over `(kind, check)` pairs.

The tradeoff: briefs failing both should be rare once old briefs are grandfathered. Even so, every extra round spends the user's approval, and the refactor is simpler than the current code.

**4. Drop `Brief.proof` (and `Proof.said` if it's only asserted on)** (A5, B4)
This is new surface with no consumer in `src/`. Either remove it or show it on the jbriefs page. Keeping it costs little, but the change created it, so it belongs in this change.

**5. Template detection by a leading `<`** (A6, B5)
The check fails in both directions:
- A real proof like `<= 50 ms p95 from jgauge` is refused.
- The guide text with its brackets stripped is accepted, because it contains "test".

Comparing against the template's actual line, or matching `^<[^>]*>$`, is exact. The impact is low: a false refusal is safe because it only raises a gate. Fold this in if the Act-on #1 tightening is already touching the code.

### Noted
- **Shared `head_line(text, label)` helper** (A4, B3). The duplicate loop is real, but moving `designed` into `jbriefs.parse` changes a "do not touch" rule's code, which is outside the Where line. Note it for later. The in-scope part is covered by Consider #3.
- **Result and real-brief run not visible in the diff** (A7, B6). Check the brief's Result for two things: the grandfather/refuse statement, and the printed launch-check line from one real queued brief. These are Done-when and Proves-it items, so their absence would block. They just can't be verified from the code.

### Dismissed
- None outright. Every finding was valid at some level. The buckets reflect weight, not correctness.

### Agreement Map
The reviewers converged independently on the central defect (A1/B1). Each listed overlapping concrete bypass strings, which is a strong consensus signal on a correctness bug in the feature's only purpose. They also agreed on the structure nits (duplicate loop, unused property, `<` heuristic) and on what the diff can't show.

A alone looked past the parser to the policy around it. A caught both the unbounded grandfathering (A2) and the double-gate cost (A3), and A2 is the second real blocker. B contributed the testing angle (B2), which explains why the core bug survived: the tests mirror the regexes rather than probing them.

The overall pattern: the scaffolding is sound, but the gate is porous on both edges. It is too loose about what counts as outside, and too lenient about briefs that omit the line entirely. Fix those two and the change ships.
