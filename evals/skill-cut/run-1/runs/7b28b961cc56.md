### Act On
- **The comment overclaims a security property** (A1, B2). "A public one never does: a stranger's pull request must not run here" is false. On `pull_request`, a fork can rewrite `runs-on` and land on a self-hosted runner that has access to the user's real home. Both reviewers found this independently.
  - In this PR: reword the comment to claim only what the line does.
  - Noted for later, outside "Where": unregister the runner before the repo goes public.
- **A scheduled `pstack-drift` run likely falls back to `ubuntu-latest`** (A2, B1). Cron payloads plausibly lack `github.event.repository`. If so, the weekly job keeps spending hosted minutes, which defeats the task. Neither reviewer could confirm this, but both flagged it independently, it names a concrete path, and the PR's own run cannot exercise it.
  - Verify with a scheduled run's `toJSON(github.event)`. A manual `workflow_dispatch` does not prove it, because its payload does carry `repository`.
  - If the field is absent, key the expression on something present on every event, such as `vars.*`.
- **The drift clone persists in the real `~/.cache`** (A3). There is a concrete failure: a run killed by the 10-minute timeout leaves a partial `.git`, and every later run reuses it. That cache is also shared with the user's local runs. Setting `XDG_CACHE_HOME: ${{ runner.temp }}` fixes it inside "Where".
- **The copied comment is false in `pstack-drift.yml`** (A6, B5). That workflow has no pull request trigger. It is cheap to fix, and it gets rewritten anyway with the first item.

### Consider
- **The uv cache and uv-managed Python persist in the service user's home** (A4). A content-addressed shared cache is a common, accepted tradeoff. However, it strictly contradicts a "leaves nothing behind" line. Either set `UV_CACHE_DIR` under `runner.temp`, or state in the Result that it is accepted.
- **The `PICK`/`runner` test layer models GitHub's evaluator without running it** (B3). It adds a regex, helpers and a test of the helper, and checks nothing beyond plain string equality. It also implies behaviour coverage it does not have: it cannot see the cron bug above. Replacing it with `jobs(text) == {"check": RUNS_ON}` deletes code. This is a real simplification, but not a blocker.

### Noted
- `.yaml` glob gap and `TypeError` on a job with no `runs-on` (A5, B4). No such workflow or job exists yet, so this is hypothetical. A one-character glob change if anyone touches the test.
- "Done when" run evidence is absent from the diff (A7, B6). By design it belongs in the Result, not the diff. B6's uv point is covered under A4.
