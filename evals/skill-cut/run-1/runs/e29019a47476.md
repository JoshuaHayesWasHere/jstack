### Intent
> Replace the two pr-review reviewer subagents (A/B) per pull request with one review thread. That thread reads the diff itself with the same intent, `SCOPE` and seven questions, keeps the blast-radius proof, sends one combined review, and writes one `## Review` section that jmerge's ready rule still passes (`Reviewers: 1`). jbus archives that thread on its next pass after the PR merges or closes, and never archives one whose PR is open. Skills and docs that say "two reviewers" are updated to say one. Tests cover the skill text, the archive on merge (and not while open), and jmerge reading the new section as ready. `make check` exits 0.

### Act On

**1. Archiving decides "closed" by absence from a list, which can archive the review thread of an open PR** (A2, B1)

`shut()` (`src/jbus/threads.py:164`) calls a slug closed when its Result's `Branch:` URL is not among the URLs in `world.open`. That list is capped at 100 and matched as raw strings. `watch.pull` already decides closed by a different rule, and the new `eta`/`pull/8` test shows the two rules disagreeing.

Before this change, the absence inference only kept a thread out of `tasks`. Now it drives an archive that jbus never undoes. That directly risks the Done when line "a review thread of an open pull request is never archived".

Both reviewers reached this independently, and each named a concrete path to the wrong outcome. The fix is to:
- define merged/closed in one place, reusing `watch.pull`'s rule;
- archive only on `world.merged`, or on a state GitHub actually reports as `CLOSED`;
- never archive on absence alone.

Add a test where an open PR is missing from `open.json`, and assert its review thread is not archived.

**2. The jmerge "new shape" test never lists a finding, so the findings-answered rule is untested** (A1)

Three things combine to defeat the test:
- The template line is `Findings:` with no trailing space, so the `": "` fill skips it.
- The `.replace` call is a no-op.
- The template's `- <severity>` item is filtered out.

As a result, jmerge sees `found == 0`, and the test would still pass if the matching between findings and answers broke. The fix is to:
- write the `Findings:` item into the section explicitly;
- add the negative case, where the same section without its `Finding:` line is not ready.

This is the Done when test that proves jmerge compatibility, so it has to execute the rule it claims to cover.

**3. `docs/flow.html:214` still says two reviewers** (A3)

The Done when line covers "any other skill or doc", and the change already edits `docs/flow.md`, `README.md` and `docs/jgauge.md` on that basis. This hand-written page was missed, and nothing catches it. It is a one-paragraph edit.

**4. `skills/pr-review/SKILL.md:232` claims an independent check that no longer exists** (A6, B2)

"Judge it against what the reading was not given: the brief's decisions…" was true when the readers were separate subagents. Now the same thread read the whole brief. Since this is the text the reviewer works from, a false premise here degrades every review.

Reword it to say the reading and the judgment are one thread. Point the judgment at re-checking each claim against the repo and the brief. Both reviewers raised this.

### Consider

**5. `"archive"` as a mode key inside a title-prefix map** (A4)

The rule is "a `review:` thread whose slug is closed or merged is also archived". That can be computed at the call site from `slug_of` and one `ended` set. Doing so removes the dict key, the `shelve` propagation, and the nested loop with `break`.

The tradeoff is small. Item 1 already rewrites this area, though, so fold the simplification into that fix rather than doing it as a separate pass.

**6. A merged PR keeps its review threads if the last Review is `not run`** (A5)

After a merge, nothing waits on the thread, and the Done when line says the review thread is archived on merge. The case is narrow: a later pass that stopped early. Either archive non-busy review threads for ended slugs regardless of verdict, or document in `docs/jbus.md` that they are kept on purpose.
