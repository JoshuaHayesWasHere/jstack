### Intent
> Run the brief checks (Proves it, Size, Playbook, and the required fields of `templates/brief.md`) at `jbus queue add` and refuse an incomplete brief, with the launch's checks kept as a backstop. Bind an approval to a deterministic meaning fingerprint over the scope and risk fields, so typos, formatting, reordering and edits to non-scope fields keep the go, and added, removed or changed Done-when lines, paths, numbers or values re-ask. Store the fingerprint, the full `brief_sha` and the basis in the approval record, print them for other bots to verify, and keep old full-sha rows working. State the method and its limits in the PR description and `docs/jbus.md`.

- Reviewer A: 9 findings
- Reviewer B: 8 findings
- The two independently agreed on the three most serious issues: template text passing `_filled`, negation through contractions, and the duplicated check lists. Both answered the review skill's questions.

### Act On

**1. `queue add` accepts unedited template text for Task, Done when, Pull request and Review** (A1, B1)
- `_filled` only catches values that start with `<`. The template's own lines for these four fields start with `"`, start with `-`, or contain `|` with no `<`.
- A brief copied straight from `templates/brief.md` therefore reaches the user for a go. This misses the central Done-when line ("an incomplete brief can't be queued").
- The docs and the home skill also claim more than the code does.
- `_template` already exists and is used by the neighbouring checks.
- Fix: strip quotes and list markers, then use `_template`.
- Test: run `queue add` on the unedited template and expect a fault for every required field. That test would have caught this.

**2. Contraction stripping lets a negation keep the go** (A3, B2)
- Deleting the apostrophe turns `shouldn't` into `shouldnt`, which is within two edits of `should`. So "the gate should fire" changed to "the gate shouldn't fire" keeps the user's approval.
- This is a concrete path in Done when and Do not touch, the fields the task says must catch "real changes to intent or scope".
- The two-edit rule is the spec's. Joining contractions is the author's own choice, and it is what pulls negation inside the allowance.
- Fix: tokenise `n't` as `not`, and add a test that `should` changed to `shouldn't` re-asks.
- Three other cases come straight from the spec and cannot be fixed without breaking it: near antonyms (`include`/`exclude`, `import`/`export`, `maximum`/`minimum`) and swapped direction after filler-drop plus sort. Name them in the known-limit section of the docs and the PR body, which today mention only `must`/`may` and `files`/`fixes`. The task explicitly asks for that limit to be stated honestly.

**3. The `queue add` checks and the launch checks are two hand-kept lists** (A4, B3)
- `faults` re-lists what `dispatch.CHECKS` and `ASKED` hold, and re-derives `proven` inline. "`queue add` runs every check a launch runs" holds only by convention.
- The next check added to dispatch would gate at launch and never refuse at add, which is exactly the bug this task exists to fix.
- The only parity test covers Design alone.
- One `(kind, check)` tuple in `jbriefs.parse`, consumed by both `faults` and `dispatch`, makes the backstop true by construction. Both files are in Where.

**4. The home skill discards the "its go does not hold" line** (A2)
- On a successful `queue add`, the skill prints only `added: the row <slug>` and drops `$said`. A scope change that voids the go therefore looks like a plain success to the home.
- The user is re-asked only when launch later gates `brief changed after approval`. That is the "queued, then gated" order the task removes, and it defeats the new GO_VOID signal.
- Cheap fix in a file inside Where: surface the line, and add a sentence saying the home re-puts the brief to the user.

### Consider

**5. `scope` and `holds` can disagree in the verify output** (A5)
- After a typo fix, `verify` prints a different `scope` with `holds: true`. A bot that compares `scope` hashes, as the docs suggest, would refuse a brief jbus launches. That undercuts the "other bots can check it" goal.
- At minimum, the docs should say `holds` is authoritative and that `scope` equality is stricter.
- Adding a fingerprint `method`/version field is cheap insurance against future `FILLER` or regex changes.
- Checking `scope` against the stored `meaning` would guard against hand-edits to `queue.json`. That threat is low, since hand-edits are already out of scope.
- Tradeoff: worth doing the docs line now. The version field is cheap but speculative.

**6. The CLI picks what to print by matching string suffixes** (A6, B5)
- `said.endswith((GO_HOLDS, GO_VOID))` silently breaks on any rewording.
- The fix is small: return the state as data, or always print the line.
- Tradeoff: it is new code and would be trivial to fix now, but it does no harm today.

**7. The PR description says the launch checks are unchanged, but the playbook check is stricter** (A8)
- The stricter crewmate-playbook check is intended by the task, but it can now gate rows that launched before.
- The description should state it. A one-line edit.

### Noted
- **Small redundancies** (A7, also in B3): `designed` runs twice, a `_filled` result is discarded for Size, and `ROUTING` is dropped twice. Harmless; clean up only if the code is touched anyway.
- **Re-adding to change priority needs a complete brief, which voids an old go** (A9): theoretical, since every row queued today is complete.
- **`approve` does not run `faults`** (B4): it only matters for pre-existing incomplete rows, of which there are none, and the launch backstop still catches them.
- **Greedy pairing in `_pairs` can re-ask spuriously** (B6): it errs only toward re-asking, which is safe. The docstring could be softened.
- **`src/jbus/asks.py` is outside Where** (B7): the queue verbs live there, so the Where line naming `cli.py` was simply inaccurate. The change is in the right place.

### Dismissed
- **The PR description cannot be confirmed** (B8): Reviewer A read the PR body and confirms it states the method and a limit. The real gap is the incomplete limit, covered under Act On item 2.
