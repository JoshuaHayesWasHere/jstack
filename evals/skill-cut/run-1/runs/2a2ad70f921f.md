### Intent
> Every gate is act-unless-stopped. The thread acts on its default at once, the user sees the question as already acted on, and a differing answer is carried back. An open plain question closes by silence at 2 hours on a basis that says it is not the user's word. Six irreversible cases (deletes data, rewrites history, spends money, touches prod or real users, changes access or secrets, publishes) must carry `Holds:` and a `Fail-safe:` line. These never act and never close by silence; they wait for the user with the dry-run, plan or bundle attached. `jbus gate` refuses a gate with no default, a default that is not the recommended option, a `Holds:` with no fail-safe, and an unknown case. The rule ships in the skills, the template and the docs, with fake-clock tests, in one pull request.

### Act On

**1. A held gate answered `--default` never reaches its thread (B1)**
- `tell` and the page skip every `keeps` answer, because before this change the default had always been carried out already.
- A `Holds:` gate breaks that assumption. A user who agrees with the recommended deletion or deploy sends nothing, and the held action parks forever.
- Only a *differing* answer moves a held gate. This defeats the whole hold design and the "no question parks work" line.
- docs/jbus.md:132 now states something false for held gates.
- **Fix:** carry a go-ahead when `holds` is set, fix the doc sentence, and add a test that a `Holds:` gate answered `--default` sends one message.

**2. A re-piped gate that now holds is told "already answered" by silence (A1)**
- `ask` treats any answered record as settled, and that now includes `closed_by: silence`.
- A thread that re-pipes with `Holds: deletes data` gets "already answered … Go by it" and the new `Holds:` lines are dropped. It proceeds with an irreversible action nobody approved.
- This is exactly the fail-safe the user said must not be skipped. The test at :768 asserts the bad reply.
- **Fix:** treat silence-closed records as open in `ask` (the PR already has `_open()`), clear the silence answer when `holds` arrives, and add the fake-clock test A suggests.

**3. Silence closes the link-conflict questions that ask the home (A2)**
- `_quiet` closes these as well. The home's `$LINKS` jq selects `.answer == null`, so after 2 hours the rebase line is never sent and the stack link sits.
- That is a concrete path to parked work, caused by the new pass.
- **Fix:** exempt home-directed questions from `_quiet`.

**4. "Shown as already acted on" and "with the fail-safe attached" are not shown anywhere (A4, B2)**
- `acted`, `holds` and `fail_safe` reach `waiting-on-user.json` and stop there:
  - `line` is unchanged.
  - The home's reader block (skills/home/SKILL.md:752, in Where) drops them.
  - `waiting._blocks` drops them.
- Two "Done when" lines are unmet. The only test reads the JSON file, which is a proxy.
- **Fix now:** put the state in `line` and add the fields to the home's jq and printf.
- **Noted for later:** the page panel, which is outside Where.

**5. Stale "only their name closes a question" (A6)**
- skills/home/SKILL.md:822 now contradicts the rule this PR must state in the same section. It is a one-line fix in Where.

### Consider

**Redundant `(default)` + `(recommended)` marks (A5, B5)**
- The brief does say "refuses one whose recommended option is not the default", and the change meets it literally.
- Reading `(default)` as the pick would delete two refusal branches and avoid rejecting old-skill `(default)` gates.
- Tradeoff: simpler and less breaking, but it reinterprets the brief's wording. Worth doing only if old-style gates are still being piped.

**Expert findings now self-dismiss after 2 hours (B3)**
- To pass, the fixture makes the expert "recommend" leaving its own finding alone, and silence then clears it.
- This is a real design consequence of applying the rule to every gate. It needs a decision about expert gates, and skills/expert/SKILL.md is outside Where.
- Note it for later, and don't let the fixture edit stand as the answer.

**The words panel shows a silence close as the user's answer (A3)**
- This contradicts the brief's "not their word" basis in the place the user reviews what they said. The panel is outside Where, so it is noted for later unless `questions.py` can mark it cheaply.

**Silence-closed questions vanish from the page (B4)**
- The CLI still accepts a later answer, so nothing is lost. The cheap in-scope fix is a docs/jbus.md line saying a later answer goes through `jbus answer`. A view state for these is for later.

### Noted
- `_held` duplicates `mirror.field` line scanning (B6). There is real drift risk, but the fix lives in mirror.py, outside Where.

None.

### Agreement Map
- **Agreed:** both reviewers flagged the display gap and the redundant marks. The display gap is a missed "Done when" line. The marks are a simplification call.
- **Diverged:** each reviewer independently found a critical bug on the `Holds:` path (A1 in `ask`, B1 in `tell`).
- **What it tells us:** the pattern matters more than either bug. The old invariant, "a gate's default has already been carried out", is still built into `ask`, `tell`, `_answer`, the page and the docs. The PR added `holds` and the silence close without revisiting those consumers. That is the redesign-from-first-principles gap, and the tests check JSON shape rather than these behaviors.
- **Before merge:** walk each consumer of `answer`/`keeps` for both held and silence-closed records.
