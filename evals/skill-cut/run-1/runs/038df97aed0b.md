### Intent
> The user's complaint: "there is no header or sidebars, navbars or helpers ... in general the UI / UX feels subpar". The PR must add:
> - A header with the name, where you are, and the time of the last read.
> - A sidebar with "All" first, then each project with its waits count and a health dot. Under 900 px it becomes a row of chips.
> - Room, jbus and Runners drawn once, as the machine's.
> - A Bus card that no longer wraps one letter per line, and no sideways scroll at 1440, 900 or 390 px.
> - Empty lanes folded.
>
> All of it in vanilla JS and CSS in `page.html` and its panels. `make check` and `jgauge test-slot -- make check` must pass. The user's decisions bind it: the 250/150 word caps, one vanilla file, hover tips on every mark.

### Reviewers
- Reviewer A: 8 findings
- Reviewer B: 9 findings
- Both reviewers raised six of the same issues independently: word caps, health-rule duplication, file size, sticky offset, machine row missing on no-project views, and the theme control. Neither reviewer said whether `make check` or the width tests were run and pass. That is still unverified.

### Act On

**1. The word caps were loosened by measuring less (A4, B1).**
- The user set 250 words for the overview and 150 for a project, meaning what the first screen shows.
- The machine row used to sit inside `<main>` and was counted. It now sits in the sidebar, and the probe counts only `<main>`. The test now allows 280 and 180 words.
- The content was not made to fit the cap. The cap was moved off the content. That is a proxy check against a user decision.
- Fix: count header, sidebar and main against `WORDS`/`EVERY`. If that total cannot fit, that is a gate: take the default, run `jbus gate`, and carry on. The test should not quietly redefine the cap.

**2. `SHELL = 30` describes today's fixture, not a limit (A4, B2).**
- The test's own docstring says the shell grows by about 2 words per project. The fixture's three projects already come to about 26 words, so two more projects fail the test with nothing wrong on the page.
- This goes away with the fix for item 1. If a separate shell count is kept, make it a base plus 2 per project and test it with more than three projects.

**3. Project health is judged by two diverging rule sets (A2, B5).**
- `troubles` (`page.html:670`) copies the row-chip mapping, and the two already disagree. A project with only blind spots gets an amber "Blind N" chip on its row and a green dot in the sidebar.
- `troubles` also prints "0 failed wakes, last error: X" when only `last_error` is set.
- These are concrete wrong outputs today, not a style point.
- Fix: one helper per health fact that returns state and tip, read by both the row chips and the sidebar dot.

**4. The header's "read" time shows now, not the last read (A3, `page.html:752`).**
- After `MISS` failed polls, `lost()` sets `NOW = Date.now()` and the header advances "read hh:mm" on every failed poll.
- That breaks the "time of the last read" Done-when line in the one case it exists for.
- Fix: keep a separate last-answer timestamp, set it in `took` and `tookStack`, and show that.

**5. The jbus item can show "passing" with no machine data (B3, `page.html:645`).**
- When `/stack.json` fails, the failure handler is silent, `STACK` stays null, `unwell` becomes `[]`, and the jbus item shows ok/passing. When the request succeeds, the value can be up to four polls old while the rest of the row is fresh.
- A false green is a correctness problem.
- Minimal fix in scope: when `STACK` is missing, show unknown, not ok. Better: derive `unwell` from `S.sources`. If that needs a server-side `machine` flag, the flag is outside the Where line and is noted for later.

**6. The sidebar stays empty for up to 15 s on a no-such-project link (A1, `page.html:1002`).**
- If the 404 arrives before `/stack.json`, the render runs with `STACK` null. The stack's own render is then skipped behind `if (S)`.
- That is a concrete, likely ordering in new code, on the "no such project" path the user asked for.
- Fix: render unconditionally (`put` already skips parts that did not change). Add a test that loads `#/nope` and checks the sidebar items at the first poll.

### Consider

**7. The machine row disappears on no-project views (A7, B6, `page.html:644`).**
- Both reviewers flagged this, and it contradicts the PR's own "drawn once, on every view".
- It is low impact: the first load and the not-found page.
- The fix is a cheap fallback to `STACK.machine`, and it fits naturally with item 6. Worth doing in the same pass.

**8. The theme control was redesigned from three buttons to one cycling button (A8, B9).**
- Both reviewers flagged it. It doesn't trace to the task, and the cycle and its aria-label are untested.
- Tradeoff: space in the header may have forced it.
- Either restore the three-button group inside the header, or say why in the PR and add a test that clicks through auto → light → dark → auto and checks the stored value.

**9. `page.html` goes from 979 to 1067 lines (A5, B4).**
- The user chose "one vanilla file", but the panels mechanism already inlines scripts server-side. A `shell` panel under `src/jbus/view/panels/` would keep one served file and stay inside the Where line, if inlining picks up new panels without touching `__init__.py` or `state.py`.
- If it does need those files, it is noted for later.
- Not a blocker: the shell code is cohesive, and the split is mechanical.

**10. The sidebar's sticky offset is hard-coded to 50 px (A6, B8, `page.html:50`).**
- The header wraps, so at about 900–1100 px with long crumbs the sidebar slides under it.
- Real but narrow. A shared CSS variable is a cheap fix.

**11. A comment now contradicts the poll code (B7, `page.html:994`).**
- "One request a poll" is false now that a project page also fetches `/stack.json`.
- A one-line fix. A wrong comment costs more than a missing one.

### Noted
- Neither reviewer confirmed that the Done-when width checks (no sideways scroll at 1440, 900 and 390, and the Bus card no longer wrapping) are in the browser tests and pass, or that `make check` and `jgauge test-slot` pass.
- Both should be shown in the PR before merge. This is not a finding against a line.

### Dismissed
- None. Every finding traces to a changed line and names a concrete effect. Neither reviewer padded with style preferences.

### Agreement Map
- Both reviewers independently raised six issues: the word caps, the duplicated health rules, file size, the sticky offset, the machine row on no-project views, and the theme redesign. The consensus on the word caps and the health rules is the strongest signal. Both are places where the PR satisfies its tests by changing what is measured or by copying logic, not by fitting the design.
- Each reviewer's unique finds were concrete bugs in the new polling and render flow: A found the empty sidebar race and the moving "read" time; B found the stale or false-green `unwell` and the stale comment.
- The shell's data flow (`STACK` versus `S`, and `NOW` versus the last answer) is the least settled part of this PR. That is where a second pass should look.
