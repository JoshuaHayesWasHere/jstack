### Intent

Add the 25th principle, `depth-over-breadth`, as a jstack source in `jdrift`, and make every count say 25. Credit Felix Rieseberg in `THIRD_PARTY.md`. Back it with a blind, rerunnable eval in `evals/deeper/` over about 10 past briefs. The eval's Result says honestly whether `/deeper` won; a loss is a finding, not a reason to tune.

### Act On

**1. The "won" verdict rests on an "outside" measure that counts formatting, and it flipped between runs** (A1, B1, merged)
- A rescored the committed run-2 briefs. Without the backtick branch of `OUTSIDE`, the two arms are level (0.34 vs 0.33).
- The whole plain-to-deeper rise in outside comes from inline code, and the skill tells writers to use more of it.
- B shows the same measure changed sign on eight of ten cases between two runs of what is in effect the same skill. Run 1 lost under the rule, and run 2 won.
- So the "won" in the Result rests on a proxy and on noise. That is the outcome the task warned about: "that is a finding, not a reason to tune the eval."
- Fix:
  - Count a backtick span only when it holds a run command, or drop that branch.
  - Re-score both committed runs. This needs no model calls.
  - Restate the Result from what both runs agree on, for example: "won on instruments (and raw, see 2); proof outside the agent not shown."
- This is the "Done when" line about the Result saying whether `/deeper` won, so it blocks.

**2. The raw-sources measure largely counts the skill's own example list, yet the README says it doesn't** (A2, B2)
- Both reviewers found it independently. Seven of the twelve `RAW` kinds match the list in question 2 of `SKILL.md` almost word for word.
- `beyond` controls for this on instruments only, but README "What holds" claims the control for both.
- Fix: add a raw `beyond` count that excludes the skill's listed kinds and re-score, or narrow the sentence to instruments. Either way the claim in the README must match the evidence.

**3. `write()` wipes the committed results before the first model call** (A3, B3)
- Both reviewers traced it concretely:
  - `rmtree` runs on `runs/` and `deeper/` first.
  - `key.json` is written only at the end.
  - Any failed call (or no `claude` on the machine at all) leaves partial runs, a stale key, and a `report` that refuses to run.
- This is the "crashed halfway" case the review asks about, on the one documented command.
- Fix: write into a temporary directory and swap it in once the key is written. Add a `shutil.which("claude")` preflight before anything is touched.

**4. Redaction silently turns off when the jleak patterns aren't at `~/.config`** (B4)
- `_private` ignores `XDG_CONFIG_HOME`, which `jleak.cli` respects. It then swallows `jleak.Missing` and returns no patterns.
- Cases and model outputs drawn from private task state then go into a public repo unredacted.
- It comes from one reviewer, but it is a security finding with a concrete path.
- Fix: resolve the path the way `jleak.cli` does, and fail closed when the patterns are missing.

**5. The principle card claims two playbooks lean on it, and neither does** (B6)
- The `leans` field lists `perf-issue` and `investigation`, but only `skills/deeper/SKILL.md` references the principle.
- Other cards' `leans` match real links, and this text renders on the explained page.
- Fix: list `deeper` only. Linking the playbooks is outside "Where" and is for later.

**6. The gate's `Context:` placeholder invites four lines, and jbus keeps one** (B7)
- `mirror.field` reads only the `Context:` line, so a home that follows the wording literally loses answers 2 to 4 without notice.
- The test covers only the semicolon-joined form.
- Fix: change the placeholder to "on this one line, separated by semicolons", and add a test case that shows the multi-line form is not what the skill asks for.

### Consider

**7. The `not_held` column is a phrase count, read as a per-brief fact** (A4)
- The README's "seven of the ten" comes from it. It counts every "does not hold" anywhere in a brief, including the Review and repeats, and misses "did not hold".
- Tradeoff: it is a small fix (scope it to the Result and match the tense variants), but this is the merged-outcome part of the eval. Fix it while re-scoring for 1 and 2, or relabel the column as a phrase count.

**8. `SELF` disqualifies any proof line that mentions "review"** (B5)
- It distorts `rs-parallel-reviews`, where reviews are the subject of the task, not the judge.
- Tradeoff: it touches the same outside measure as finding 1, so it is cheap to fold into that rework. On its own it affects one case.

### Noted
- **A5**: importing `eval.py` leaves `evals/deeper` and `src` on `sys.path`, plus a bare top-level `score` module, for the rest of the test session. It is real hygiene and could bite later through name shadowing, but nothing breaks today. A path-scoped import is the easy fix if someone is already in the file.
- **B8**: `Pinned.own = ()` is a default nothing uses. Dropping it makes the field required like the others. It is trivial.
