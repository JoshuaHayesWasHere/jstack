### Intent
> Replace pr-review's two reviewer subagents (A/B) with one scoped review thread. That thread reads only the PR's diff, posts one combined review, and writes one `## Review` section that jmerge's ready rule still accepts, with `Reviewers: 1`. When the PR merges or closes, jbus archives that review thread on its next pass. A review thread of an open PR is never archived. The docs and skills that described two reviewers now say one. Tests cover the skill text, the archive on merge (and not while open), and jmerge reading the new section as ready. `make check` passes.

### Reviewers
- Reviewer A: 8 findings
- Reviewer B: 4 findings
- They agreed on three issues: the absence-based "closed" rule, the stale Step 4 sentence, and the out-of-`Where` files. The review skill's seven questions were asked; both readers tagged findings with principles.

### Act On

**1. "Closed" is inferred from absence, and the action it drives is an archive** (A2, B1)
- `shut()` (`src/jbus/threads.py:164`) treats a slug as closed when its Result's URL is missing from a 100-item open list.
- `watch.pull` already decides merged/closed by a different rule, and B showed a case where the two disagree.
- Any of these gets an open PR's review thread archived, which the Done when line forbids outright:
  - the 101st open PR;
  - a URL that differs in form;
  - a branch not named after the slug.
- The archive is destructive and jbus never undoes it.
- This is a concrete path, not a hypothetical, and both readers found it on their own.
- Fix: drop `shut()` and derive "ended" from `watch.pull(...) in (MERGED, CLOSED)`. That defines merged/closed in one place. If `pull`'s CLOSED is itself absence-based, confirm CLOSED from GitHub's real state before archiving. Archiving on merged alone is safe.

**2. The jmerge "new shape" test never lists a finding** (A1)
- The template line is `Findings:` with no trailing space, so the `": "` fill never applies and the list stays empty.
- jmerge therefore sees `found == 0`, and the "findings answered" half of the ready rule is never exercised.
- This is the test the Done when line asks for, and as written it would pass even if the findings/answers matching broke.
- Fix: write the `- warning …` item explicitly. Add the negative case: the same section with no `Finding:` line must not be ready.

**3. `docs/flow.html:214` still says "Two reviewers … then settles itself"** (A3)
- This directly misses the Done when line "any other skill or doc that tells pr-review to start two reviewers says one".
- The page is hand-written, not generated, so no sweep will catch it.
- The fix is a one-line edit.

**4. Step 4 claims an independent check that no longer exists** (A6, B2)
- `skills/pr-review/SKILL.md:232` says to judge "against what the reading was not given: the brief's decisions".
- In one thread, the reading *was* given the brief.
- In a skill, the text is the behaviour. This sentence tells the reviewer it has a cross-check it doesn't have, which is exactly the false confidence the lead step exists to prevent.
- Fix: say the reading and the judgment are the same thread, and point the judgment at re-checking each claim against the repo and the brief.

### Consider

**`"archive"` as a mode key inside a prefix-keyed map** (A4)
- The special case, the second `shelve` set and the nested loop with `break` are real complexity.
- Computing `ended` once in `settle` and deciding the archive from `slug_of` at the call site would remove all three.
- Tradeoff: the fix for item 1 rewrites this code anyway, so do it in that pass if it falls out naturally. It isn't worth a separate change.

**A merged PR whose last Review is `not run` never gets its review threads archived** (A5)
- The Done when line says a merged/closed PR's review thread is archived. The verdict gate made sense while the PR was open, not after it ends.
- Tradeoff: this is rare and leaves clutter rather than damage. Either archive non-busy review threads for ended slugs regardless of verdict, or document that they are kept on purpose.

- **Ambiguous `docs/jbus.md:108` sentence** (A8): this is a phrasing nit. The rule it describes changes with item 1, so rewrite the sentence then.

  - Already-settled A/B subagents from old-style reviews aren't archived. They are transitional leftovers from reviews already written, which the brief puts out of scope.
