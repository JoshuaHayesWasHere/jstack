### Act On

**1. The grandfather cutoff is a fixed time set before the merge, so rows approved in the gap get stranded** (A1, B1)
`SHAPED_SINCE = "2026-10-15 11:15 ET"` at `src/jbus/dispatch.py:60` is earlier than the PR's own commit (11:22). The sequence that breaks:
1. Until the merge, homes write briefs from the old template, which has no `Size:` line.
2. Any of those briefs approved after 11:15 is gated "no Size: line".
3. Adding the line changes the brief's sha.
4. `_ready` then gates the row again with "brief changed after approval".

That is the stranded row the Done-when rules out. Nothing is caught yet, because the latest live approval is 11:06. The window stays open until the merge, though, and the "live queue run through the check" proof only covers the moment it ran.

Fix: tie the cutoff to the actual landing time, or to a time safely after it. Add a test for a row approved after the constant but before the merge.

**2. The cutoff is compared as text against a hard-coded "ET" string** (A2, B2)
`at >= SHAPED_SINCE` (`dispatch.py:180`/`:189`) is only correct when jsettings is set to `America/New_York` with the label `ET`.
- With another zone, the cutoff shifts by hours.
- With no label, the stamp ends in `EDT`, and `"… 11:15 EDT" < "… 11:15 ET"` gives the wrong answer at the boundary minute.
- The docstring is the only thing that keeps this correct: a prose rule standing in for the real time.

It holds on today's config. It is still in Act On because finding 1 already forces an edit to this constant, so fixing both costs almost nothing extra. Make the constant an aware `datetime`, parse `ran_at` the way `digest.py:149` already does, and compare instants.

**3. Scout-written briefs reach launch with the template's `Size:` placeholder and are always gated** (A3)
In `skills/home/SKILL.md:494`, step 1 sends a scout's brief straight to step 2, which skips the new `Size:` paragraph at `:498`. The scout fills the brief from the template without setting `Size:`, so `parse.sized` rejects the leftover `S | M | L | XL`. Fixing that means editing the brief, which hits the same re-approval chain as finding 1. This is a concrete path that blocks every scout-written brief.

Fix, within "Where": have step 1 check `Size:` against the plan entry, as it already does for `Home:`. The matching change to the scout skill is outside "Where" and is noted for later.

**4. Any file in `playbooks/` passes, including playbooks a crewmate never runs** (A4)
The Done-when wording ("a file in `playbooks/`") is met. The user's goal is not: they wanted to stop briefs that "launch with no playbook". A brief naming `orchestrate`, `investigation`, `expert-*` or `opening-a-pr` passes the parser. The crew block then prints `not a crewmate's` and the crewmate runs with no playbook, which is the same failure in a new form. The fix is one `elif` in `playbook()` that reads the playbook's `Run by:` line, using the rule the crew block already uses.
