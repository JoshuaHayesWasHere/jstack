### Intent
> Give the jbus view a real shell: a header (name, where you are, time of the last read) and a sidebar ("All" first, then each project with its waits count and a health dot, chips under 900 px). Draw Room, jbus and Runners once, as the machine's. Fix the Bus card wrapping at 1440, with no sideways scroll at 1440/900/390 checked by browser tests. Fold empty lanes. Keep `make check` and `jgauge test-slot -- make check` green. Stay vanilla, inside `page.html`, its panels and the page test, and hold the 250/150 word caps the user set.

### Reviewers

### Act On

1. **The header's "read" time shows the current time once the server is gone** (A3). After `MISS` failed polls, `lost()` sets `NOW = Date.now()` and re-renders. The header then says "read <now>" and moves forward on every failed poll. This directly misses the "time of the last read" Done-when line, in the one case where that time matters. The fix is to keep the last answer's time as its own value, set in `took`/`tookStack`.

2. **The word caps were loosened by moving content out of what they measure** (A4, B1, B2; consensus).
   - `words` now counts only `<main>`. The machine row moved to the sidebar, so it falls outside the user's 250/150 caps.
   - The separate `SHELL = 30` is fixed. It fits only the fixture's three projects, and its own docstring says the shell grows with each project.
   - This is a proxy check: the new content was moved out of the measured area, not made to fit.
   - The fix is either of these:
     - hold the whole first screen to `WORDS`/`EVERY`; or
     - keep the machine row inside the capped count and make the shell limit a base plus a per-project allowance, tested with more projects than today.

3. **The sidebar dot and the overview row judge health by two different rule sets** (A2, B5; consensus). They already disagree in three ways:
   - `troubles` ignores `h.blind`, so a project gets a green dot but an amber "Blind 6" chip.
   - `threads == null` is treated differently by the two.
   - `troubles` prints "0 failed wakes, last error: X" when only `last_error` is set.

   Since the dot is a Done-when item, it has to agree with the row. One per-fact helper, read by both the chips and the dot, removes the duplicate.

4. **The sidebar stays empty for up to 15 s on a link to a project that doesn't exist** (A1). This has a concrete path: the 404 sets `S = null` before `/stack.json` lands, and the stack's `render()` sits behind `if (S)`. The user specifically asked that a retired or unknown link say "no such project", and it should do that with the sidebar drawn.
   - Fix: drop the `S` guard (`put` already skips parts that didn't change).
   - Test: load `#/nope` and check the sidebar items on the first poll.

5. **On a project page, the jbus item can say "passing" when the machine's state is unknown** (B3). `unwell` alone comes from `STACK`. That value is up to four polls old, and it becomes `[]` when the silent `/stack.json` failure leaves `STACK` null. The result is an `ok` jbus item beside fresh project data.
   - Fix inside "Where": when `STACK` is missing, show the item as unknown rather than ok.
   - Fuller fix, noted for later: derive `unwell` from `S.sources`. That may need a `machine` flag from the server, which is outside "Where".

### Consider

- **`page.html` goes from 979 to 1067 lines** (A5, B4; consensus). The shell renderers and their CSS are a clean, self-contained unit, and the panels mechanism could inline them as their own script. Against that, the user asked for "one vanilla file", and wiring a new inlined part may touch `__init__.py`/`state.py`, which is outside "Where". The trade-off is a split now versus the scope line. At minimum, the PR should say the overrun is deliberate. Otherwise the split is noted for a later PR.

- **The theme control changed from three buttons to one cycling button** (A8, B9; consensus). The task didn't ask for this, and the change has no test. Header space may well justify it, but then the PR should say so and add a click test (auto → light → dark → auto, plus the stored value). Otherwise, keep the three-button group inside the header.

- **The sticky sidebar assumes a 50 px header** (A6, B8; consensus). The header wraps (long crumbs between 900 and 1100 px, or "asking the server"), and when it does the sidebar slides under it. The width tests don't catch overlap. A shared CSS variable is a cheap fix, but this is a cosmetic edge case, not a blocker.

- **The machine row is missing when there is no project read** (A7, B6; consensus). This affects the first load and the no-such-project page, even though `STACK.machine` is available and the new docstring says the machine is drawn "on every view". The fix (fall back to `STACK.machine` without drawers) belongs with Act On #4, which touches the same path.

### Noted

- **A comment at `page.html:994` now contradicts the poll code** (B7). It still says "one request a poll", but a project page now also asks `/stack.json`. Update it while editing the poll for Act On #4.

### Dismissed

- None. Neither reviewer padded with style nits. Every finding names a concrete path or a measurable gap, and the nits that remain are real but small.

### Agreement Map

The reviewers converged on the structural issues: the loosened word cap, the duplicated health rules, the file size, the hard-coded sticky offset, the dropped machine row and the theme redesign. That consensus makes the cap and health findings firm.

They diverged on the runtime paths, and each caught something the other didn't:
- A traced timing and state bugs: the empty sidebar on a 404 and the header's "read" time while offline.
- B traced data freshness and the stale comment: `unwell` from an old or missing `/stack.json`.

Together, the pattern says the layout and Done-when shape are mostly right. The weak spots are:
- what happens when reads fail or arrive out of order;
- one health rule written in two places;
- a test that measures less than the user's cap meant.

Fix the five Act On items, settle the file-size and theme questions in the PR text, and this ships.
