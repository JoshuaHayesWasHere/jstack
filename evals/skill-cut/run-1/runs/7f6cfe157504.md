### Intent
> Section 3 of the /deeper design: a step inside the home skill's brief writing, not a separate file. It runs on its own for research, perf, analysis and outcome briefs, and carries its own copy of the four questions; `/deeper` stays manual. Answer 2 goes to the scout's `Read:` or the request's sources, answer 3 to the brief for the crew, and answer 4 to `Proves it:`. A mechanical fix, a docs change and a bug fix with a known cause skip the step. Tests on the skill text cover it, and `make check` and `jgauge test-slot -- make check` pass. Where: `skills/home/SKILL.md`, `templates/scout-request.md`, the home skill's tests. `skills/deeper/`, the principle, `templates/brief.md` and the parser are not to be touched.

### Reviewers
- Reviewer A: 6 findings
- Reviewer B: 7 findings
- Both reviewers independently found the same two core defects: the undefined or contradicted brief lines, and the playbook-keyed decision. The review skill's questions were asked; both reviewers answered against them.

### Act On

**1. The step names an `Instruments:` line nothing defines, and puts a `Read:` line on home briefs, which the template forbids** (A1, B1)
`SKILL.md:530,537` tells the home to write `Read:` (answer 2) and `Instruments:` (answer 3) on a brief it writes itself. Two things conflict with this:
- `templates/brief.md:17` says a home-written brief leaves `Read:` out.
- `Instruments:` exists nowhere in the template, the scout skill, the crew skill or the parser.

A home that reads the template first gets the opposite instruction. A scout following its own skill drops answer 3. The words "though the home wrote it" admit the clash without settling it.

The intent never asked for a new field. It asks for answer 2 in *the scout's* `Read:` and answer 3 "in the brief for the crew". Fix it inside "Where":
- Answer 2 goes in `Read:` only for scout-written briefs, plus the request's sources.
- Answer 3 goes in a line the template already has, such as the task body or a Done-when item, and the step says which one.
- `Instruments:` is dropped.

If a dedicated field is still wanted, record it in the Result as a follow-up for `templates/brief.md` and the scout skill, since both are outside "Where".

**2. The step is keyed on the playbook name, not on the kind of work, so it skips work the intent covers** (A2, A3, A4, B2, B3; one root cause, one fix)
- The kind of work is consulted only when the playbook is `none`.
- `bug-fix` always skips, though its row is for bugs whose cause is *not* yet known. The test at `tests/test_home_deeper.py:163` pins that wrongly as "known bug".
- Outcome work under `feature` or `autonomous-run`, and research run as a `swarm`, also skip.
- For a scout request (`:430`), the scout's own playbook decides. `investigation` and `trace-forensics` are always "deeper", so a request briefing a docs change or a known-cause fix gets the four questions.
- The ten-name list is a hand-kept copy that a new playbook silently falls outside. The test only checks the list in one direction.

Both reviewers converge on one remedy: the home states the kind of work for every task, including the task being briefed when it writes a request. The case runs on that kind: `research|perf|analysis|outcome` → deeper; `known-cause-fix|mechanical|docs` → skip. The playbook list then disappears instead of needing a sync test, and the `bug-fix` test becomes two cases: unknown cause runs the step, known cause skips it. All of this stays inside "Where". A marker in each playbook's front matter, the alternative, touches `playbooks/` and is noted for later only.

### Consider

**Report-only scout requests leave answers 3 and 4 with nowhere to go** (A5, B4)
`:537` only covers a request whose Deliver list asks for a brief. B4's remedy is cheap and uses lines the template already has: write 3 and 4 as `Questions:` items. That also replaces packing methods and the outside judge into a single Deliver bullet. Worth doing alongside fix 1, since you are rewriting that sentence anyway.

**The "Done when already names data, instruments and judge" skip lives only in prose** (B6)
The block prints `deeper` for these tasks, and a trailing sentence then overrides it. If you adopt the kind-of-work input from fix 2, this case could become an input value or a second check, so the block prints the skip itself. The tradeoff is a little more block for one less rule held in memory.

**The tests don't check that the brief lines the step names exist anywhere** (A6)
A test that takes each line the echoed text names and asserts it is in `templates/brief.md` would have caught fix 1. Add it once fix 1 lands; it should pass against the untouched template. This is cheap, and it protects the fix.

- **B7**: nothing shows that `make check` exits 0 or that `jgauge test-slot -- make check` passed. This is not a code defect, but the Result must show both runs. The Result must also say how the post-merge "one brief with the four answers" proof was checked, as the intent requires.
