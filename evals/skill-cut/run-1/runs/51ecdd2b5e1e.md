1. **Answer the question first.** "When to roll over" applies, since the context is past 300,000 tokens, but it says to answer the ask in hand first. So I start with "An ask", step 1, and run the block at the top in the same call as `ME='<my threadId>'; name='question'`. Its `is=$(cat "$E/home-id")` check confirms I am still the expert, and it prints the path of `expert-answer.md`.
2. **Answer and record it.** I follow steps 2–4 of "An ask": check the source at its current revision and answer in the four parts of `$T/expert-answer.md`. Then I write what was new into `$E`: a note with its line in `notes/INDEX.md`, a case, or a line in `unknowns.md`. Only the folder carries over.
3. **Check I still hold the expert.** I run the roll-over block with the block at the top and `ME='<my threadId>'`. It checks `home-id` and prints `launch: {"title": "expert: <name>", "workspaceStrategy": {"type": "root"}, "message": "/expert <name>"}` and a `rename:` line.
4. **Launch the next thread.** I call `t3_thread_launch` with that launch JSON exactly as printed. If the call fails or its reply is lost, I check `t3_thread_list` before launching again, so there are never two.
5. **Hand over.** I tell the user in two lines that the expert rolled over, with `[expert: <name>](t3-thread://v1/<new threadId>)`. Then I call `t3_thread_update` with `{"action": "rename", "title": "expert: <name> (rolled over 2026-10-16)"}`.
6. **Leave everything else.** I delete nothing and do not settle the thread. The new thread takes over `home-id`, the pin and the webhook.
