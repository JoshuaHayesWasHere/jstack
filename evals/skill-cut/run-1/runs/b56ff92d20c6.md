### Intent
> Section 4 of the /deeper design: a new `Proves it:` line in `templates/brief.md`, right after `Done when:`. The brief parser and jbus's pre-launch checks accept it only when it names something outside the agent (a test, metric, dataset, external judge or the user), and refuse empty lines, the template text, and proofs by the crew, crewmate, reviewer, agent, "self", "the model" or a review alone. Missing lines on already-queued briefs are grandfathered or refused without stranding an approved row. The change includes tests for each kind, an update to the home skill and docs, and passing `make check` and `jgauge test-slot`.

### Act On

**1. The `_OUTSIDE` patterns let self-referential proofs through (A1, B1).**
`proof()` accepts a line as soon as any `_OUTSIDE` pattern matches, and only then checks `_SELF`. Several patterns fire on ordinary words, so these lines are accepted:
- any backticked text, e.g. ``the `reviewer` says so``
- `make \w`, which matches "make sure"
- any percentage, e.g. "100% sure"
- bare `judge`, as in "the model is the judge"
- `test` inside "self-test"
- "his word", `eval` and `github`

Both reviewers independently built concrete lines that slip through, and each one is exactly what the task says to refuse. Per B1, this gate is the only check before `_ready` launches, so this is the feature's core contract failing.

Fix: tighten the patterns.
- A backticked span counts only when it holds a known command or a path.
- `make` counts only with a real target, never "make sure".
- A `%` counts only next to a metric word.
- Drop "his …" or tie it to "the user".

Alternatively, require that something outside remains after the `_SELF` matches are removed.

**2. The tests never try a near-miss (B2, also A1's evidence).**
The only mixed case in `REFUSED`/`PROOFS` is the passing "the crewmate runs tests/test_briefs.py". The precedence rule is the riskiest logic in the change, and only its happy side is tested. Add executing `REFUSED` cases for every example in item 1. They should fail now and pass after the fix.

**3. Grandfathering has no end date (A2).**
`proven()` returns `""` whenever the line is missing, for any brief, at any time. Omitting the line therefore skips the gate permanently, and the new requirement survives only as prose in the home skill. That is the "rule in prose" pattern the review checklist names.

The Done-when line asks to grandfather briefs that are *already queued*. It does not ask to exempt briefs written later.

Fix: tie the exemption to data the queue already records, such as the row's `approved` time or `brief_sha` before a cut-off. Rows approved after the cut-off that lack the line get gated. This change is small and inside `dispatch.py`.

### Consider

**4. One gate per fault, so two faults cost two approval rounds (A3).**
A brief missing `Design:` and also carrying a refused `Proves it:` produces one gate, then another after the user re-approves. Collecting both faults into one gate is cheap and also removes the `short, kind` juggling in `_ready`. The tradeoff is that the case is rare, but each extra round costs the user an approval.

**5. Template detection by a leading `<` (A6, B5).**
The test misfires both ways:
- It wrongly refuses a real line that starts with `<`, such as `<= 50 ms p95 from jgauge`.
- It wrongly accepts the template guide text once the brackets are stripped, because `test` matches it.

Matching `^<[^>]*>$`, or comparing against the template's actual line, is a one-line fix. Its impact is low, which is why it sits here and not in Act On.

### Noted

- **Duplicate head-line loop and the `proven` pass-through (A4, B3).** The duplication is real, but the clean fix moves `designed`, which falls under "do not touch the other brief lines and their rules". Note a shared `head_line` helper for later. A `(kind, check)` tuple in `_ready` falls out naturally if item 4 is done.
- **`Brief.proof` and `Proof.said` are read only by tests (A5, B4).** This is small dead surface. It is defensible as "the parser reads `Proves it:`", and it can be removed or surfaced on the jbriefs page later.
- **Two Done-when items can't be seen in the diff (A7, B6).** The Result must still state the grandfather-or-refuse choice and show one real queued brief run through the launch check with its line printed. Check the Result before merging. Nothing in the code needs to change for this.

### Dismissed

None. No finding was wrong or missing context. The nits that were weaker went to Noted rather than being thrown out.

### Agreement Map

**Agreement.** Both reviewers converged independently on:
- the loose `_OUTSIDE` precedence, the one substantive defect
- the duplicated loop
- the test-only property
- the `<` heuristic
- the unverifiable Result items

The consensus on the regex issue is the strongest signal in this review. B called it critical and A called it a warning, but both showed concrete bypasses, so I treat it as blocking.

**Divergence.**
- A alone found the unbounded grandfathering and the double gate. Both concern the dispatch flow and not the parser, which suggests A read `dispatch.py` more closely.
- B alone made the test gap a finding of its own and found the false-refusal side of the `<` check.

**Overall.** The parser's shape is fine, and the nits are genuinely minor. The real work is making the gate hold: tighter patterns, near-miss tests, and an exemption with an end date.
