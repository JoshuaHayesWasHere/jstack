### Intent
> The user: "there is no header or sidebars, navbars or helpers ... in general the UI / UX feels subpar." This PR adds a header (name, location, time of last read) and a sidebar ("All", then each project with its waits count and a health dot, turning into chips under 900 px). It draws Room, jbus and Runners once, as the machine's. It fixes the Bus card wrap and any sideways scroll at 1440, 900 and 390 wide, and folds empty lanes. All of this stays in vanilla JS and CSS in `page.html` and its panels, with `make check` and `jgauge test-slot -- make check` green. mockup-b is the design base, the user's word caps are 250 for the overview and 150 for a project, and the CSP, ports, unit and jbus writes are untouched.

- Reviewer B: 9 findings
- They agreed on six issues: duplicated health rules, the word cap, the file length, the sticky offset, the missing machine row, and the theme control. Each also found issues the other did not (A: the empty sidebar race and the read time; B: stale `unwell` and a stale comment). Both answered the review skill's questions.

### Act On

1. **The read time in the header shows "now" while the server is down** (A3). The new label claims "the time of the last read", but after `MISS` failed polls, `lost()` sets `NOW = Date.now()` and re-renders. The header then moves forward on every failure, which is exactly when the last-read time matters. This breaks a "Done when" line. Keep the time of the last successful answer as its own value, set in `took`/`tookStack`, and show that.

2. **The word caps were loosened by moving content out of what they measure** (A4, B1, B2; merged). `words` now counts only `<main>`, and the header and sidebar sit under a separate `SHELL = 30`. The machine row used to count toward the overview's 250 and now counts toward neither cap. The first screen can therefore carry about 280 and 180 words against the user's 250 and 150. This is a proxy: the content was moved outside the check rather than made to fit. On top of that, the docstring says the shell grows by about two words per project, yet the fixed 30 fits only the fixture's three projects. Both reviewers found this independently, and it goes against a decision the user made. Fix: hold the whole visible first screen to `WORDS`/`EVERY`. If a shell figure is kept at all, make it a diagnostic, or a base plus 2 per project tested with more than three projects.

3. **The sidebar dot and the overview row judge health by different rules** (A2, B5; merged). `troubles()` copies the row-chip mapping and already disagrees with it. It ignores `h.blind`, so a project gets an amber "Blind 6" chip on its row and a green dot in the sidebar. It also prints "0 failed wakes, last error: X", which the row chip guards against. Both reviewers found this, and it is a concrete wrong output today. Fix: one helper per health fact returning `[state, inner, tip]`, read by both the row chips and the dot/tip, with the dot amber if any entry is `op`.

4. **The jbus item on a project page can say "passing" when it knows nothing** (B3). `unwell` alone comes from `STACK.machine`, which is refreshed every fourth poll. The `/stack.json` failure handler is a silent no-op, so a null `STACK` gives `unwell = []` and the item shows ok. A health mark that reports green on missing data is a correctness bug. At minimum, show unknown (not ok) when `STACK` is null. Better: derive `unwell` from `S.sources` so one read feeds the whole row. If that needs a `machine` flag added on the server, that part is outside the "Where" line and noted for later.

5. **The sidebar stays empty for up to 15 s on a link to a project that does not exist** (A1). If the 404 for `/state.json` lands before `/stack.json`, the render runs with `STACK` null. The later stack answer is then dropped by `if (S) render()`, and nothing redraws until the next poll. This is a concrete, likely ordering on a route the user specifically asked for ("a link to one says there is no such project"). Drop the `S` guard (`put` already skips unchanged parts) and add a test that loads `#/nope` and checks `seen["side"]["items"]` at the first poll.

### Consider

- **The machine row is missing on the not-found view and before the first project read** (A7, B6; merged). `machineOf` returns null whenever `PROJECT && !S`, even though `STACK.machine` is available. The new test docstring says the machine is drawn "on every view". The impact is low, but the fix is one line and sits next to Act On #5, so do them together.
- **The theme control became a cycle button** (A8, B9; merged). Nobody asked for this. It costs an extra tap and is untested. If the header's space or mockup-b drove the change, say so in the PR and add a click test (auto → light → dark → auto, stored value). If not, keep the three-button group inside the header.
- **The sidebar's sticky offset hard-codes a 50 px header** (A6, B8; merged). The header can wrap at 900–1100 px with long crumbs, and the sidebar then slides under it. A shared CSS variable is a cheap fix. Nothing has been shown to break at the three tested widths, so this is not a blocker.
- **`page.html` grows from 979 to 1067 lines** (A5, B4; merged). The shell renderers are a self-contained unit, and `panels/` already provides inlined per-part scripts, so a split would not break "one vanilla file" as the browser sees it. The tradeoff: if registering a new panel needs `__init__.py`/`state.py`, that is outside "Where" and noted for later. Worth doing if it fits inside `panels/`, otherwise state the overrun in the PR.
- **A stale comment: "One request a poll"** (B7). The change made this comment false, since project pages now also fetch `/stack.json`. It is a one-line fix in the touched block.

### Noted
- None beyond the items above.

### Dismissed
- None. Every finding traces to a changed line and has a concrete basis. The nits were cheap and real, not padding.

### Agreement Map
The reviewers agreed on six issues, and where they overlapped they agreed on severity too. The two strongest signals are consensus: health rules split between sidebar and row, and the word cap moved rather than met. The issues each found alone are the most correctness-heavy. A traced timing paths (the empty sidebar race, the header read time while the server is down), and B traced data provenance (stale or missing `unwell`). Neither inflated findings. The overall pattern is that the shell's layout and markup are sound, while its data handling (what is shown when a read is missing, late or stale) and its test boundary need tightening before merge.
