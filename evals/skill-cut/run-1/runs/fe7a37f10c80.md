### Intent
> Retire the Exec home completely: Sous Chef is the one orchestrator, escalations reach the user through jbus's webhook, and the user's word comes down by `jbus word`. Remove every mention of Exec from the skills (`new-home`, `home`, `handoff`), the `exec` role from `jroles`, and Exec wording from jbus's queue, word and CLI code, the docs and the README. Re-pin the listed tests to the new text. Done when `rg -i '\bexec\b|_exec|exeggutor'` finds only shell `exec` and `exec-once`, and `make check` exits 0. Where a test still needs a behaviour, keep the behaviour and rename it.

### Reviewers
- Reviewer A: 7 findings
- Reviewer B: 5 findings
- The reviewers independently agreed on four points: the redaction loss, the streak cleanup, the files outside "Where", and the gauge fixture. All of the review skill's questions were asked.

### Act On

**A retired `[exec]` table is now read silently, and its webhook URL and key are no longer redacted.** Raised by A1 and B1.
- Before this PR, an `[exec]` table was already unread, but jbus did two things with it:
  - warned "remove them";
  - put its `webhook_url` and `webhook_key` into `secrets()`, so `jbus.redact` removed them from journal lines, gate text and the digest.
- The PR deleted both behaviours and their tests. It did not rename them.
- This is a security regression on a concrete path: any install whose config still holds that table will print the secret in clear. Both reviewers found it independently.
- The user's own config is clean, so this machine is not exposed today. That does not justify dropping redaction in software others can install.
- The fix should not name `exec`, because a string `"exec"` would trip the `rg` Done-when line. B's simpler suggestion is the right one:
  - `_ignored` flags any unknown top-level table;
  - any `webhook_url` or `webhook_key` found in an unread table goes into `secrets()`;
  - one test, renamed, plants a key in an arbitrary unknown table and checks that the key is redacted and the table is flagged.
- This replaces a one-name special case with a general rule. It is smaller and survives the next retirement too.

### Consider

**The `exec-webhook` streak cleanup and the `exec-sent.json` unlink were deleted.** Raised by A2 and B2.
- The brief's "keep any behaviour a test still needs, renamed" is circular here. The PR deleted the test that needed the behaviour.
- Keeping the cleanup also needs the literal `exec-webhook`, which the `rg` line forbids.
- B checked the live state: there is no streak and no file, so on this machine the reconciliation is dead code.
- Dropping it is defensible. What is missing is the record. The PR should state that the cleanup was dropped deliberately and that the live state was checked.
- Tradeoff: a one-line PR note, against an `exec-webhook` streak lingering forever on some other install.

**The party-handoff machinery has no real caller left.** Raised by A3.
- With Exec gone and the experts retired, nothing reaches the following through a real party:
  - `party_home`;
  - the "A party's home" close block;
  - the `expert` role used for non-expert parties.
- The tests keep this path alive with an invented `desk` party.
- A is right in substance, and the user's words ("we are moving from this pattern") point toward removing it.
- Removing it is a larger cut, though, and touches territory near `skills/expert/`, which the brief fences off.
- Recommendation: a follow-up task, or a `jbus gate` with "remove it" as the default. Do not do it in this PR.

**The new home line adds "A home sends no other thread a status".** Raised by A5.
- The brief gave the line's content exactly, and this clause is a new standing rule in a prompt that agents follow.
- It reads as if it contradicts a home messaging its own crewmates and scouts.
- If the scout's section 5c contains the clause, keep it. If not, cut it.
- Cheap to fix, but it needs a check against the scout's report first.

**The doc line now calls every session "the `<directory>` home".** Raised by B4.
- `who()`'s mislabelling of Sous Chef's approvals predates this PR.
- But the changed line at `docs/jbus.md:279` now asserts the label as universal, just as Sous Chef becomes the only orchestrator that approves.
- A wording fix in the doc is in scope: "the name of the directory it ran in".
- Making the code distinguish Sous Chef's approvals is follow-up work.

### Agreement Map
The reviewers converged on the one real defect: the deleted redaction for a retired table. That agreement, plus the fact that it is a secret-handling path, is why it is the only Act On item.

They also agreed on two side effects of the deletion:
- the streak cleanup was dropped rather than renamed;
- some files were changed outside "Where".

Both were explained by the same root cause: the `rg` gate makes "rename" impossible for anything keyed on the literal `exec`. The PR resolved that by deleting behaviour and tests together, without recording it. The pattern to fix is the missing judgement call: generalise behaviour that matters (redaction), and record what was dropped (the streak).

Where they diverged:
- A looked one level up and asked whether the party pattern itself survives the user's intent. That question is right, but it belongs in a follow-up.
- B traced who now calls `who()`. Its finding is a real but pre-existing modelling gap.

Neither reviewer found a fault in the skill text the brief named, apart from the extra clause in the home line. The core removal reads as complete.
