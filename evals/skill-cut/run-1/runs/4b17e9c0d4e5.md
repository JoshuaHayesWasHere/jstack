### Intent
> Every gate in every home carries a default that is also the recommended option, and the thread acts on it at once (act-unless-stopped). An open plain question is closed by its default after 2 hours of silence, with a basis that says it was not the user's word. A later differing answer is still taken. A gate whose default deletes data, rewrites history, spends money, touches prod or real users, changes access or secrets, or publishes must carry a `Holds:` line and a `Fail-safe:` line. Such a gate does not act and is never closed by silence. It waits for the user, with the dry-run, plan or bundle attached. The default change and the fail-safe rules ship together in this one pull request, tested with a fake clock.

### Act On

1. **A held gate answered with its default never releases the thread** (B1). `tell` skips every `keeps` answer, on the old assumption that the default was already carried out. A `Holds:` gate is the one kind whose default was *not* carried out. So when the user approves the recommended destructive step, nothing is sent, and the held action stays parked forever. The only way to unblock it is to disagree. This breaks the core of the fail-safe design.
   - Fix in `questions.py`: `tell` and `_answer` should carry a "go ahead with the default" message when `holds` is set.
   - Fix the sentence at `docs/jbus.md:132`.
   - Add a test: a `Holds:` gate answered `--default` sends exactly one message.
   - The page's `_carry` in `view/__init__.py` is outside **Where**. Note it for later, but the CLI path must work in this PR.

2. **A silence close masks a later `Holds:` on re-pipe** (A1). `ask` keeps any answered record, and a silence close now counts as answered. A thread that re-pipes the same question with `Holds:` added is told "already answered … go by it". Its holds and fail-safe are thrown away, and a destructive default can go ahead with nobody's yes. The path is narrow but concrete, and the fix is small.
   - In `ask`, when the existing answer was closed by silence and the re-pipe adds `holds`, reopen the record with the new fields.
   - Add the fake-clock test A1 describes.

3. **Silence closes the home's own link-conflict questions, so stacks park** (A2). `_quiet` closes every record without `holds`. That includes the "link of a stack has a conflict" questions, which the home reads with `.answer == null`. After 2 hours the rebase line is never sent, which directly contradicts "no question parks work".
   - Exempt questions that ask the home from `_quiet` (in **Where**), and add a test for it.
   - Moving them out of user gates entirely is the better long-term shape, but not needed here.

4. **"Shown as already acted on" and "with the fail-safe attached" are not met** (A4, B2; both reviewers). The new `acted`, `holds` and `fail_safe` fields reach only `waiting-on-user.json`. The item's `line`, the home's jq block and printf (`skills/home/SKILL.md:752`), and the page all drop them. The only test reads the JSON file, which is a stand-in for what the user actually sees.
   - Fix the in-**Where** parts: put the state in `line`, and add `.holds, .fail_safe` to the home block.
   - The page panel and `waiting._blocks` pass-through are noted for later if they fall outside **Where**. `waiting.py` is in **Where**, so do `_blocks` now.

5. **The home skill contradicts itself** (A6). `skills/home/SKILL.md:822` still says "only their name closes a question", in the same section this PR rewrote to say silence closes questions. The home is an agent following this text, so a contradiction in a **Where** file the task requires to state the rule is worth the one-line fix.

### Consider

- **Collapse `(default)` and `(recommended)`** (A5, B5; both reviewers). Since the two must coincide, the second mark and its two refusal branches carry no information. They also force every thread, and the ~12 rewritten fixtures, to spell both. Treating `(default)` as the pick and refusing `(recommended)` on any other option still meets the Done when line, with less code and less churn. The tradeoff: the PR as written is correct and already updated the skills, so this is simplification, not a fix. I lean toward doing it while the fixtures are open anyway.
- **Expert findings now dismiss themselves** (B3). The expert's gate defaults to "nothing changed". To pass, the fixture marks that default as recommended, so the expert now recommends against its own finding, and silence closes it in 2 hours. That follows the user's rule literally, but probably not what they wanted from advice. It needs a decision on how expert findings should gate: hold, or default to the change. `skills/expert/SKILL.md` is outside **Where**, so note it for later. Don't leave the fixture edit pretending the question is settled.
- **The words panel shows a silence close as the user's answer** (A3). The task requires the basis to say it is not their word, and the user's own record says the opposite. The fix is in the panel, outside **Where**, so it is noted for later. It belongs in the same follow-up as the page work from Act On 4.
- **After silence, a later answer only works through the CLI** (B4). The Done when line is met through `jbus answer`, but the page drops the question and the docs imply any path works. The cheap fix is a sentence in `docs/jbus.md` saying a later answer goes through `jbus answer N`. A "closed by silence, still answerable" state in the view is the fuller fix, for later.

### Noted
- `_held` re-implements `mirror.field` scanning (B6). The drift risk is real but small, and the remedy (`mirror.fields`) is outside **Where**. Note it for later.

### Dismissed

### Agreement Map
The reviewers converged on the two surface-level gaps: the display of the new fields, and the redundant mark. Each found a different critical, and both criticals sit in the same place. The PR added two new answer states, *closed by silence* and *held, awaiting a yes*. But the consumers (`ask`, `tell`, the home's jq, the words panel, the page) still read the old binary of `answer is None` versus answered-with-default-already-done. A1, A2, A3, B1 and B4 are all one bug in five places. The finding underneath them is model-the-domain: make the question's state an explicit type (open / acted / holding / closed-by-silence / answered) that every reader switches on, and these cases stop being special. That refactor is larger than this PR needs. The Act On fixes above patch the paths that break correctness now, and the type is the follow-up worth briefing.
