### Intent
> Make threads more obvious per project and let the user follow scouts and crewmates. Each project's row and page get a Threads band, grouped by role. Out threads come first with liveness and last write, threads that ended today are dimmed, and the rest are folded. The band reads from `pass.json` `projects[name].threads`. `#/<project>/thread/<role>/<slug>` opens a drawer showing what the thread works on: a task's step, or a scout's request. A task's drawer lists its threads. The server reads one new read-only source, each scout request's `## Report` and `Status:` line, to say researching, reported or blocked. A project whose last pass left no thread list shows a blind spot, never "none". The change has small-fixture tests and passes `make check` and `jgauge test-slot`. It stays vanilla, with no change to the CSP, ports or unit, and it writes nothing.

### Reviewers
- Reviewer A: 8 findings
- Reviewer B: 7 findings

### Act On

**1. An ended scout with no Report still reads "researching"** (A1)
`request()` derives the state from the file alone, and `threadChip` shows that state ahead of liveness. A scout that crashed or was settled early therefore shows a dimmed "researching 2h00", and its drawer says "researching" under an "ended" heading. This is the one case where the user most needs to step in, and the page tells them the work is still going. The task is to let the user follow scouts, and this gets the most important scout state wrong. Show "researching" only while the thread is out. Give an ended scout with no Report its own word and an amber chip. Add a fixture for it, since the current ended scout in `a_day_of_threads` has a Report.

**2. `Status: not done` is drawn as a green "reported"** (A2, with the case-folding part of B6)
Every Status other than `blocked` maps to `reported` and gets the `ok` chip. The scout template allows `done | not done | blocked`, and the scout skill's settle check treats anything but `done` as unfinished. The page would call a scout finished that jbus itself does not. Map `done` to reported, `blocked` to blocked, and anything else to a non-`ok` not-done state. Compare case-insensitively, because B6 notes that `Status: Blocked` currently shows as reported. Test a last Report whose Status is `not done` on its own; the `rye-tin` fixture currently masks this with a later `done`.

**3. The `scouts/` source can never say missing or unreadable, and an unreadable request reads as "missing"** (B1)
The blind-spot requirement exists so the page never reports absence as calm. The new source's `seen` passes neither `read` nor `path` to `_source`, so it is always "ok", even for a home with no `scouts/` directory. The new stack test's `larder`/`pantry` fixtures show exactly that. Separately, `request()` catches every `OSError` as "missing", so a permission error tells the user there is no such request. Pass `read`/`path`, treat only `FileNotFoundError` as missing, and add a no-`scouts/` test. B1's side point about directory mtime not moving on an append is fair but secondary: fix the state first. Taking `at` from the newest request file's mtime would be a cheap improvement.

**4. A project page whose pass listed zero threads draws no band** (A5, B2)
Both reviewers caught this independently. "Done when" says the row **and page** have a band. The overview row draws a calm "Threads 0 out" for the same data, but the page draws nothing, and only a prose comment explains the difference. Drop the conditional and let `band()`'s calm state handle zero. This deletes a special case rather than adding one.

**5. The thread row renderer and the role table each exist twice** (A3, B3)
Both reviewers raised this independently and with the same specifics. `about()` in the thread drawer copies `threadRow()`, differing only in the title cell. `ROLE` in page.html sits beside `ROLES` in threads/panel.js, with different column orders and already different words ("crews" vs "Crewmates"). `band()` reads one table only to index the other by position. This is new duplication that has already started to drift. Keep one ordered role list with named fields and one `threadRow(t, {title})`, and have the drawer call it. Where that shared code lives (page.html or threads/panel.js) is the author's choice. B's push to move `threadChip`/`LIVESAY` out of the shell is reasonable but optional.

### Consider

- **The `"threads"` magic tag in `health()`** (A4, B5). A fourth tuple slot is added only so `projectRow` can filter it back out, and the sidebar's `amber()` still needs the reason. The fix is small and removes a special case from a shared helper: have `amber()` add the threads reason itself, or have the band supply it. The tradeoff is touching `amber()`'s inputs in the same PR. I'd do it, since it lands next to fix 4 above.
- **`gates_inside=True` then `re.split` back at `## `** (A6). If A6 is right that the Report body without `gates_inside` already ends at the gate, then two lines and a docstring sentence go away. The tradeoff: B6 notes this mirrors `jbus.threads._scouts`, so diverging from jbus's own parse may be worse than a redundant line. Check that the output is the same before deleting.

### Noted

- **Unused defaults on `_threads(home=None, day="")`** (A7). Making them required removes two guards. Check first whether a test calls `_threads` without them; low impact either way.
- **New `panels/thread/` folder outside "Where", and an undocumented `adds.band` hook** (A8, B4). The drawer route is the second "Done when" line, so the folder traces directly to the task, and a stub `panel.py` for discovery is a plausible cost of the router. Say why in the PR description. Documenting `adds.band` in `panels/__init__.py` is outside "Where", so it is for later.
- **Three readers of the Status line with different rules** (B6). A shared "last Report and its Status" helper in `jbus.threads`/`mirror` is the right end state, but it is outside "Where", so it is for later. The case-sensitivity symptom is folded into Act On item 2.
- **Private `_mtime` imported by the threads panel** (B7). Moving the scouts `Source` into state.py beside `PASS_FILE`/`MERGE_LOG` would match the existing pattern. It is cosmetic and can go with fix 3 if convenient.

### Dismissed

None outright. Every finding either holds up or is a valid but low-cost note.

### Agreement Map

The reviewers converged on three things: the missing page band (A5/B2), the duplicated row and role tables (A3/B3), and the `health()` tag (A4/B5). They also agreed on the out-of-"Where" panel folder (A8/B4). That is strong signal that the page-shell and panel code carry real structural debt from this PR, and the fixes are deletions, not additions.

They diverged on the server side, and that is where the correctness bugs are. A read the scout status as a user would: ended-but-silent (A1) and not-done-as-green (A2). B read the plumbing: the source that can't report a blind spot (B1) and parse rules drifting from jbus (B6). Each found real bugs the other missed, and together they say the scout status, the PR's one new data source, is undertested. Every bug in Act On items 1–3 is a fixture the tests lack.

The severities disagree in places (A5 is a nit, B2 a warning, for the same issue). I weighted by the "Done when" line, not by either label. The line numbers for page.html differ between reviewers (:805 vs :163), probably file versus hunk numbering, so locate these by function name.
