### Intent
> Give the jbus view a header (name, where you are, time of the last read), a sidebar ("All" first, then each project with its waits count and a health dot, folding to chips under 900 px), and the machine's Room, jbus and Runners drawn once as the machine's and never inside a project. Fix the Bus card's one-letter wrapping and any sideways scroll at 1440, 900 and 390, with browser tests checking it. Fold empty lanes. Keep it vanilla, in the one page and its panels, inside the user's 250/150 word caps, with `make check` and `jgauge test-slot -- make check` green.

### Reviewers
- Reviewer A: 8 findings
- Reviewer B: 9 findings
- They agreed on six issues and each found one or two the other missed. Both answered the review skill's questions; B cites question 5 directly.

### Act On

1. **The word caps were loosened by moving content out of what they measure** (A4, B1, B2, merged). `words` now counts only `<main>`. The machine row, which used to be counted on the overview, now sits in the sidebar, and the header and sidebar have a separate `SHELL = 30` cap. The user set 250/150 for what the first screen shows, so this is a proxy check that lets the screen reach about 280/180. The fixed 30 also only fits three projects, which the docstring itself contradicts.
   - **Fix:** count the whole first screen (main, header and side) against `WORDS`/`EVERY`. The `SHELL` cap then goes away.
   - **If it won't fit:** that is a gate. Take the default (trim), pipe the options to `jbus gate`, and carry on. Do not quietly widen the measurement.

2. **The sidebar dot and the overview row judge health by two separate rule sets, and they already disagree** (A2, B5, merged). Raised independently by both reviewers. The concrete divergences:
   - `troubles` ignores `h.blind`, so a project gets an amber "Blind 6" chip on its row but a green dot in the sidebar.
   - It treats `threads == null` differently from the row.
   - It prints "0 failed wakes, last error: X" when only `last_error` is set.
   - **Fix:** one helper per health fact returning state, text and tip, read by both the chips and the dot.
   - This is a correctness issue, not style.

3. **The header's "read" time is wrong exactly when it matters** (A3). After `MISS` failed polls, `lost()` sets `NOW = Date.now()`, so the header claims a fresh read that never happened, and the time moves forward on every failure. The Done-when line asks for "the time of the last read".
   - **Fix:** keep the time of the last successful answer (set in `took`/`tookStack`) and show that.

4. **The no-such-project route renders an incomplete shell** (A1, A7, B6, merged). Both effects come from the same missing state handling and both fixes are one-liners.
   - **Sidebar:** if the 404 arrives before `/stack.json`, the sidebar stays empty for up to 15 s, because the stack callback only re-renders behind `if (S)`.
   - **Machine row:** `machineOf` returns null whenever there is no `S`, so the machine row is missing even though `STACK.machine` is there. That breaks "drawn once, on every view".
   - **Fix:** drop the `S` guard on the re-render, and fall back to `STACK.machine` when there is no project read.
   - **Test:** load `#/nope` and check both the sidebar items and the machine row on the first poll.

5. **The jbus item on a project page can say "passing" from stale or missing data** (B3). `unwell` comes from `STACK.machine`, which is refreshed every fourth poll, and the `/stack.json` failure handler is silent. When `STACK` is null, the item shows ok with nothing behind it. A health mark that reports ok when the answer is unknown is a correctness bug.
   - **In scope now:** show an unknown state rather than ok when `STACK` is missing.
   - **Noted for later:** deriving `unwell` from `S.sources` needs a `machine` flag server-side, which is outside **Where**.

### Consider

- **page.html grows from 979 to 1067 lines** (A5, B4). The shell renderers and their CSS form a clean unit, and the panels mechanism already inlines per-part scripts, so it would still be served as one file.
  - **Tradeoff:** the user asked for "one vanilla file", and registering a new panel may touch `__init__.py`/`state.py`, which is outside **Where**.
  - **Recommendation:** split only if it fits inside `panels/`; otherwise say so in the PR and note it for later.
- **The theme control became a cycling button** (A8, B9). This was not asked for, it is untested, and picking a look now takes up to two taps. If header width forced the change, say so in the PR and add a click test (auto → light → dark → auto, plus the stored value). Otherwise keep the three-button group inside the header.
- **The sidebar's sticky offset is hard-coded to 50 px** (A6, B8). The header wraps, so at 900–1100 px with long crumbs the sidebar slides under it. A shared CSS custom property is cheap. It is a nit, but both reviewers saw it and 900 px is a tested width.
- **A stale comment** (B7). "One request a poll" is now false on project pages. It is a trivial edit and worth doing while the poll code is open.

### Noted
- Nothing beyond the parts of B3 and A5/B4 that need changes outside **Where**, which are listed above as noted for later.

### Dismissed
- None. Every finding traced to a changed line and named a concrete execution path or a broken user decision. Neither reviewer padded with style preferences.

- **Agreed:** the reviewers converged on six issues: the word-cap loosening, the duplicated health rules, the no-such-project machine row, the file length, the sticky offset, and the theme redesign.
  - That consensus raises confidence on the two Act On items it covers (caps and health).
  - The two nits they share (offset, theme) are real but small.
- **A only:** the stale "read" time (A3) and the empty-sidebar race (A1). Both are concrete timing paths.
- **B only:** the stale `unwell` source (B3) and the comment drift (B7).
- **What this tells us:** the pattern points at one weak spot in the change, which is the states it didn't design for: server lost, project missing, stack not yet fetched. All four single-reviewer findings live there, and so does A7/B6. The happy-path layout work looks sound. The fix list is mostly about making the shell honest when data is absent or stale.
