### Intent
> Eliminate the exec home: remove every place Exec is named across the skills, `jroles`, jbus code, docs, README and tests. Sous Chef is the one orchestrator, and escalations go through jbus's webhook. The experts are retired with Exec. Wording follows the scout's section 5c. Done when the listed files no longer name Exec, the `rg` sweep finds only shell `exec` and Hyprland `exec-once`, and `make check` exits 0.

### Act On

**Retired `[exec]` secrets are no longer redacted, and the config no longer warns about the table** (A1, B1)

`src/jbus/__init__.py:42` and the removed `_unread` / `Config.unread` mean two things for a config that still has an `[exec]` table:
- It loads silently, with no "remove them" notice.
- Its `webhook_url` and `webhook_key` drop out of `Config.secrets()`.

The brief said "keep any behaviour a test still needs, renamed". The PR instead deleted the test that needed the behaviour, which skips the brief's condition rather than meeting it. A secret-handling regression flagged by both reviewers deserves weight, even though this machine's config is clean.

The cheapest fix that also passes the `rg` line: keep the retired-table handling under a neutral name and keep its test. That means warning on the retired table and redacting `webhook_url` / `webhook_key` from any unread table. If the drop is deliberate, the PR must say so, giving the reason, as `Finding: not fixed, ..., because`.

### Consider

**The `exec-webhook` streak cleanup was deleted, not renamed** (A2, B2)
- The removed lines are at `src/jbus/cli.py:451`.
- Same brief departure as above, but the cost is only a stale streak entry or an orphan `exec-sent.json`, not a leak.
- B checked that this machine has neither.
- Tradeoff: keeping a one-line `alert.retire(state_dir, …)` under a neutral constant costs almost nothing. Recording "checked live state, dead reconciliation, dropped" is just as acceptable. Either way, record it.

**The party-handoff machinery has no real caller left** (A3)
- The experts retired with Exec. Their folders carry a `CHARTER.md`, and `party_home` never handles a folder with one.
- So `party_home`, the party close blocks and `test_party_handoff.py` now exist only for an invented `desk` fixture.
- Asking for the `expert` role for parties that are never experts is a further sign the path is dead.
- This is the user's "we are moving from this pattern" applied fully, but it goes past this brief's "Done when" ("no longer has an `exec` role or case").
- Tradeoff: a bigger cut in a skill the brief scoped narrowly. Raise it as a follow-up brief rather than growing this PR.

**An extra rule in the new home line** (A5)
- `skills/home/SKILL.md:98` adds "A home sends no other thread a status".
- Skill prose is behaviour for the agents that read it. This clause reads as a standing rule that conflicts with a home messaging its own crewmates and scouts.
- Check it against the scout's section 5c. If the clause isn't there, drop it and use the brief's wording.

**Leftover pair-telling message in the gauge fixture** (A7, B5)
- `tests/test_home_gauge.py:330` and `:844` still use "the home of demo is another now", the text of the send this PR removed.
- The `t3_thread_send` entry should stay, since the mail pass-on still uses it, but its example should be a pass-on message.
- Both reviewers flagged it and it is a trivial fix, so it is worth doing in passing.
