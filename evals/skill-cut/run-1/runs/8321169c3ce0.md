### Intent
> Replace the two pr-review reviewer threads (A/B) per PR with one scoped review thread. That thread reviews only the PR's diff, posts one combined review, and archives itself when the PR merges or closes. Done when a new PR gets exactly one review thread and it auto-archives on merge. It must still satisfy jmerge's review-at-head requirement.

### Reviewers
- Reviewer A: 8 findings
- Reviewer B: 4 findings

### Act On

**1. `shut()` decides "closed" from absence in a 100-item open list, and the result is an irreversible archive** (A2, B1)
- **What:** `shut()` treats a slug as closed when its Result's `Branch:` URL string is missing from `world.open` (`--limit 100`). Nothing reads the pull request's actual state.
- **Why it breaks the brief:** the Done when line says "a review thread of an open pull request is never archived". Each of these archives the review of a live PR:
  - a 101st open PR;
  - a URL that differs only in form;
  - a renamed repo.
- **What changed:** before this change, the same inference only filtered a list. Now it drives a destructive action jbus never undoes.
- **Consensus:** both reviewers reached it independently. B adds that it disagrees with `watch.pull()`, which already defines MERGED/CLOSED. The `eta`/`pull/8` test case shows the two rules giving different answers today.
- **Fix:** take B's direction. Derive "ended" from `watch.pull(...) in (MERGED, CLOSED)` so the rule lives in one place. Where that rule itself rests on absence, confirm CLOSED from GitHub's state (A's `gh pr view --json state`, cached like `merged.json`) before archiving.

**2. The "new shape is ready to jmerge" test never lists a finding** (A1)
- **Why the test checks nothing:** the template's `Findings:` line has no `": "`, so the filled findings are dropped and the `.replace` is a no-op. jmerge then sees `found == 0`.
- **What it misses:** the rule that every listed finding has its `Finding:` answer is never exercised. The test would still pass if that matching broke.
- **Why it matters:** this is the Done when line guarding the jmerge requirement the user called out explicitly.
- **Fix:** write a real `- warning ...` item under `Findings:`. Add the negative case: the same section without a `Finding:` line is not ready.

**3. `docs/flow.html:214` still says "Two reviewers … then settles itself"** (A3)
- The Done when line requires every doc that tells pr-review to start two reviewers to say one.
- This page is hand-written, not generated, and no test catches it.
- It is a one-line fix. The Done when wording overrides its absence from `Where`.

**4. `skills/pr-review/SKILL.md:232` says the reading "was not given" the brief's decisions** (A6, B2)
- That was true with two `Explore` readers. In one thread it is false.
- The skill is the product here. Telling the reviewer it has an independent cross-check it does not have weakens the judgment step.
- Both reviewers flagged it.
- **Fix:** reword so the lead step re-checks each claim against the repo and the brief.

### Consider

**`finished()` puts an `"archive"` mode key into a prefix-keyed map** (A4)
- This forces a special case, a second `shelve` set, and a nested loop with `break`.
- Computing `ended` once in `settle` and deciding archive per thread would delete that machinery.
- **Tradeoff:** it is structure, not a bug. Fix #1 touches the same code, so do it then if cheap; otherwise leave it.

**A merged PR whose last Review is `not run` never gets its review threads archived** (A5)
- The Done when line says merge or close archives the review thread. After a merge, nothing waits on the thread, so the verdict gate has no purpose there.
- **Tradeoff:** it is rare (it needs a later pass that didn't run) and the cost is a leftover thread, not data loss. The easy fix is to drop the verdict condition for slugs in `ended`.

### Noted
- **Files outside `Where`** (A7, B4): `README.md`, `docs/flow.md`, `docs/jgauge.md` and `src/jbus/t3.py`. Every line traces to the task: the docs to the "any other doc" Done when line, and `t3.py` because `_held` refused `archive`. The brief should have listed `t3.py`; no change is needed.
- **`docs/jbus.md:108` reads awkwardly** (A8): it reads as if closing unmerged were a second verdict. Fix #1 will rewrite this sentence anyway, so make it say "over when the task ended or the PR closed, and the last verdict is clean/findings".
- **The fake T3 keeps archived threads listed** (B3): it does not model a T3 that hides them. Separately, A/B subagents settled under the old skill are never archived. That is a fake-fidelity point plus a one-time legacy leftover; neither affects new PRs, which is what the task scopes.

### Dismissed
None. No finding was wrong or a pure preference.

### Agreement Map
- **Where they agreed:** both reviewers converged on the most serious issue, the `shut()` closed-inference driving an archive, from different angles:
  - A came from the open-PR guarantee and the 100-item limit;
  - B came from the duplicate rule against `watch.pull()`.
- That convergence, plus the destructive and irreversible effect, puts it first. They also agreed on the stale step-4 sentence and on the out-of-`Where` files, which are harmless.
- **Where they diverged:** A went deeper on test and doc completeness: the hollow jmerge test, `flow.html`, the `finished()` structure, and the `not run` edge case. B alone looked at fake fidelity.
- **What it tells us:** the skill-text rewrite itself is sound. The risk sits in the new jbus archive path and in a test that looks like it guards jmerge but doesn't. Fix those four items and this ships.
