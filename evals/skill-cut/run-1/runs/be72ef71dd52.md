**1. The grandfather cutoff is a fixed time that is already in the past, so rows approved before the merge get stranded.** (A1, B1)
`SHAPED_SINCE = "2026-10-15 11:15 ET"` at `src/jbus/dispatch.py:60` is earlier than the PR's own commit (11:22). It is now 2026-10-16, so the gap is a full day and still growing. During that time, homes write briefs from the old template on main, which has no `Size:` line. Any such brief approved after 11:15 is gated as "no size". Adding the line changes the brief's sha, and that triggers "brief changed after approval". The row is then stuck until the user approves it again. This breaks "no approved row stranded" directly.

The proof run passed only because the latest approval was at 11:06. The run captures one moment and does not guarantee the property. Both reviewers traced the same concrete path.

Fix: tie the cutoff to the change actually landing. Either set it at merge, or grandfather any row approved before the first dispatch pass that runs the new code. Add a test for a row approved after the constant but before the merge.

**2. Briefs written by scouts keep the template's `Size: S | M | L | XL` placeholder and are always refused.** (A3)

**3. The cutoff compares text stamps, and those depend on the configured zone and label.** (A2, B2)
`ran_at` is written in whatever zone and label jsettings has. The constant is fixed ET text. On the user's config and in the conftest, the two agree, so the result is correct today. Tradeoff: there is no concrete failure on the current config. But finding 1 already requires reworking this constant. Making it an aware datetime and parsing `ran_at` the way `digest.py:149` does costs almost nothing extra. I recommend doing it as part of the finding 1 fix.
