### Intent
> Topic 10 of the user's re-homing (2026-10-15 22:31 ET): "A way to undo a bad merge into standing.md". The home skill (including `scoped-homes.md:7`) and the handoff skill run `jbus snapshot` right after any edit to `$H/standing.md`, so each edit becomes its own pushed commit in `~/.local/state/home`. The twice-daily timer stays. `jbus snapshot` gains `--why <text>`, which is appended to the commit message after the time. `docs/state.md` gets a short "Undo an edit to standing.md" section covering find, restore and re-snapshot. Executing tests use a temp tree with a bare remote and cover both the `--why` commit and the documented restore. `make check` exits 0.

### Act On

1. **`take` has no lock, and it now runs from many homes as well as the timer** (A1, B1). Before this change, the timer was the only caller. Now any home or scoped home can run `git add -A` / `reset` / `commit` / `push` on the same index at the same moment. There are two concrete failure paths:
   - An `index.lock` collision with the 08:30 or 17:30 run fails the unit, and `OnFailure` then fires `--alarm` at the desk and every project for a failure that isn't real.
   - One run's `git reset -q` between another's `add` and `diff --cached` silently drops that home's commit ("nothing changed"). That is exactly the "commit of its own" the task asks for.

   The fix is cheap and inside Where: take an exclusive `flock` on a file in the tree's `.git` across add, commit and push, so concurrent runs wait instead of failing. Add a test with two overlapping `take` calls if it's cheap. Otherwise, at least test that the lock is taken and released.

2. **The documented restore command empties the live `standing.md` when `git show` fails** (A2, B2). The shell truncates the target before `git show` runs. A mistyped hash, a root commit, or undoing the edit that *created* the file (rule 1 of a new repo) all leave the file empty. The doc's next step then snapshots that empty file. This is the user-facing deliverable of the task, and it can destroy the thing it exists to protect.
   - Document `git -C ~/.local/state/home restore --source=<commit>^ -- <repo>/standing.md`. It writes nothing on failure and reports a missing path.
   - Say what to do when the bad edit created the file.
   - Make the docs test run that case too.

3. **The handoff skill gains a new duty to write standing rules** (A5, B3). "One it did not write yet goes there now" is new behaviour the task didn't ask for. It contradicts the sentence just before it ("the home wrote it to `standing.md` when it heard it"). Cut it, and keep only "after any edit to `$H/standing.md`, run `jbus snapshot --why ...`". If that leaves the handoff hardcoding `added`, use the same `<added, changed or removed>` wording as the other two copies.

### Consider

- **`--why` commits sweep in the whole dirty tree** (A3; also the "mixed commits" and "two edits in one commit" parts of B1). The undo itself still works, because `log -p` and `show <commit>^:<path>` are path-limited. But in the live tree a commit labelled "jstack standing rule 28 added" will usually also carry briefs, `merge.log` and handoffs. Rarely, it will carry a second home's standing edit, which a blind undo would also revert.
  - The structural fix is for `--why` to take the path and run `git commit -- <path>`, leaving the rest to the timer. That stays within `snapshot.py`.
  - The tradeoff is a second commit mode in `take`. A lighter fix would be to keep whole-tree commits and have the doc tell the user to check `git show --stat <commit>` before restoring.
  - I lean toward the path-scoped commit, since it makes "each edit is a commit of its own" true by construction. But it's more than this Size S brief strictly needs.

### Noted

- **The rule exists in prose in three skill files with nothing enforcing it** (A4). The task explicitly asked for the instruction to live in those skills. The durable fix (`jbus standing add`, which writes and snapshots in one step) is outside Where, so it's noted for later. The wording drift between the copies is handled under Act On 3.
- **`docs/jbus.md` is edited, which is outside Where** (A6, B4). The edit is accurate and necessary, since otherwise `--why` would be undocumented on the commands page. The brief's Where line was incomplete. Keep the edit, and record it in the Result as a file outside Where.
- **A test name says less than the test checks** (B5). `test_a_snapshot_with_no_why_says_only_the_time` also checks the `why=` message, and its no-why half repeats the test at line 77. A rename and trim is cheap, but it doesn't block.

### Dismissed

- **`with_origin` duplicates the inline setup in older tests** (A7). Those tests weren't changed by this PR, and rewriting them is out of scope. Adding a helper for new tests isn't a legacy API kept alive beside its replacement.

### Agreement Map
Both reviewers independently landed on the same three real problems: the unlocked shared tree, the truncating restore, and the invented handoff duty. That consensus is strong. Two of the three are concrete execution paths, not hypotheticals. They diverged only on how to frame the concurrency issue. A treated locking and commit scope as separate findings; B folded them together. Separating them is the useful call, because the lock is a must-fix and the path-scoped commit is a design choice. Everything else from both reviewers is scope bookkeeping or test-hygiene nits, which suggests the core change (the flag, the message format and the tests that execute) is sound once the three Act On items are fixed.
