### Intent
> The user asked to eliminate the Exec home entirely ("they can completely go we are moving from this pattern"). Sous Chef is now the one orchestrator. jbus's webhook carries escalations to it, and the user's word comes down by `jbus word`. The experts are retired along with Exec. This PR is step 4 of `scouts/exec-home-removal.md`. It strips Exec from the new-home, home and handoff skills, from `jroles`, from `jbus` text and docs, and from the tests. It is done when `rg -i '\bexec\b|_exec|exeggutor'` finds only shell `exec` and `exec-once`, and `make check` exits 0.

### Reviewers
- Reviewer A: 7 findings
- Reviewer B: 5 findings
- Both independently found the two behaviour removals in `jbus` (the `[exec]` table's notice and redaction, and the streak cleanup), the files outside "Where", and the stale gauge fixture message.

### Act On

**1. A stale `[exec]` table now loads silently, and its webhook URL and key are no longer redacted** (A1, B1)
- **What changed:** `src/jbus/__init__.py:42` and around :178 no longer warn about a leftover `[exec]` table or `exec_watch`. `hooks()` at :122 no longer puts that table's `webhook_url`/`webhook_key` into `secrets()`. The test that pinned the redaction was deleted, not renamed, and the brief said "keep any behaviour a test still needs, renamed".
- **Why it happened:** a literal rename was impossible, because any string `"exec"` in `IGNORED` would fail the `rg` line. That explains the deletion but does not justify losing the behaviour.
- **Why it matters:** this is a security-adjacent regression. Both reviewers flagged it, and it departs from the brief.
- **Exposure:** the live config is clean, so this machine is not exposed today. jstack ships a README and is installable elsewhere.
- **Remedy:** B's generic form, which names no table and passes `rg`.
  - The `ignored:` line names any top-level table `load()` does not read.
  - Any `webhook_url`/`webhook_key` found in an unread table goes into `secrets()`.
  - Restore the deleted test against a neutrally named retired table.

**2. Drop the extra standing rule in the new home line** (A5)
- **What changed:** `skills/home/SKILL.md:98` adds "A home sends no other thread a status". The brief asked for one line with specified content. It also put home text it does not name under "Do not touch".
- **Why it matters:** skill text steers agent behaviour. This clause reads as forbidding a home from messaging its own crewmates and scouts, which it does routinely.
- **Remedy:** drop the clause, unless it is verbatim in the scout's section 5c. If it is, record that in the PR.

### Consider

**3. The `exec-webhook` streak cleanup was deleted, not renamed** (A2, B2)
- **What changed:** at `src/jbus/cli.py:451`, the cleanup and its test are both gone.
- **Why not Act on:** a rename cannot pass `rg`, since `exec-webhook` matches `\bexec\b`. B checked live state: there is no `exec-webhook` streak and no `exec-sent.json`, so the code was dead here.
- **Tradeoff:** restoring it costs a name that breaks a Done-when line, for no benefit on this machine. Recording the decision costs one sentence.
- **Remedy:** state in the PR that live state was checked and the reconciliation was dropped on purpose.

**4. Party handoff machinery with no remaining real party** (A3)
- **What changed:** with Exec and the experts retired, `party_home`, the "A party's home" close block and the `expert` role for non-expert parties appear to have no caller. `tests/test_party_handoff.py` keeps the path alive by inventing a `desk` party.
- **Why it's legitimate:** the user's words ("moving from this pattern") point toward deleting it.
- **Tradeoff:** the brief's Done-when only removes the `exec` role and case. Removing the whole section is a larger cut.
- **Remedy:** record it as a follow-up brief rather than widening this PR.

**5. Stale pair-telling message in the gauge fixtures** (A7, B5)
- **What changed:** `tests/test_home_gauge.py:330` and :844 still use "the home of demo is another now". That is the wording of the send this PR removed.
- **Why it's cheap:** `t3_thread_send` is still legitimately used by the mail pass-on, so only the example text needs changing. It is a one-line change each, and it stops the test from describing a step that no longer exists.

**6. `who()` doc line overstates what the label means** (B4)
- **What changed:** `docs/jbus.md:279` now says every session reads as "the `<directory>` home". Sous Chef also runs `jbus queue approve`, so its approvals carry a misleading label.
- **Scope of the problem:** the code behaviour predates this PR. Only the doc claim is new.
- **Remedy:** reword it to "the name of the directory it ran in".

### Noted
- **Files outside "Where"** (A4, B3): `project.py`, `tests/fixtures/t3/README.md`, `test_jbus_view.py` and `test_home_on_bus.py` are wording renames the `rg` Done-when line requires, so they trace to the task. `__init__.py` is the substantive one, and it is covered by Act On #1.

### Dismissed
- **`ROLES` tuple assertion and refusing `exec` specifically** (A6): the role list is what the `jroles` CLI accepts, so pinning it pins observable behaviour, not internals. Using `exec:` as the refused line would put `exec` back into `tests/` and fail the `rg` Done-when line.

### Agreement Map
- **Where the reviewers converged:** both found the same two `jbus` behaviour removals, and both traced them to the brief's "keep … renamed" clause. That consensus is real.
- **What neither said outright:** in both places the brief contradicts itself. You cannot rename a table or a streak key literally called `exec` and still pass `rg`. The crewmate resolved that by deleting.
  - For the redaction, a generic form recovers the behaviour, so it is Act on.
  - For the streak, B verified the live state is clean, so a recorded decision is enough.
- **Where they diverged:** A went structural (the whole party pattern is dead) and B went to audit labels. Both are follow-up material.
- **Overall:** the core removal looks sound. Neither reviewer found a skill, doc or Done-when line that was missed outright.
