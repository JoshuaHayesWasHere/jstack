### Intent
> Replace the two pr-review reviewer subagents (A/B) with one scoped review thread. It reads the PR's diff itself, posts one combined review, and writes one `## Review` section that jmerge's ready rule still accepts. jbus archives that thread once the PR merges or closes, and never archives one whose PR is open. Skills and docs that say "two reviewers" now say one. Tests cover the skill text, the archive on merge with open PRs left alone, and jmerge reading the new section as ready. `make check` passes.

### Reviewers
- Reviewer A: 8 findings
- Reviewer B: 4 findings
- Both reviewers answered the review skill's seven questions; they did not agree on everything (see Agreement Map).

### Act On

**1. The `shut()` archive rule infers "closed" from absence, and the result is destructive.** Raised by A2 and B1 (merged).
- `shut()` treats a PR as closed when its `Branch:` URL is not among `world.open`'s URLs.
- `world.open` is capped at 100 items and compared as raw strings.
- So the 101st open PR, or a URL that differs only in form, gets its review thread archived. That breaks "a review thread of an open pull request is never archived", and jbus never undoes an archive.
- `watch.pull()` already defines MERGED/CLOSED. `shut()` adds a second rule that disagrees with it, and B's `eta` case shows the disagreement.
- Fix: define merged/closed in one place by reusing `pull()`, as B suggests. Because archiving can't be undone, gate it on a confirmed state: `world.merged`, or GitHub reporting `CLOSED`, as A suggests. A guess from absence is not enough.

**2. The jmerge "new shape" test never lists a finding.** Raised by A1.
- The template's `Findings:` line has no `": "`, so the fill skips it.
- The `.replace` call is a no-op, and the `- <severity>` line is filtered out.
- jmerge therefore sees `found == 0`, and the "every finding answered" half of the ready rule is never exercised.
- This is the Done-when test for the new section, so it has to test that rule.
- Fix: write the `Findings:` item explicitly, and add a negative case where the same section without its `Finding:` line is not ready.

**3. `docs/flow.html:214` still says "Two reviewers ... settles itself".** Raised by A3.
- The Done-when line covers "any other skill or doc", and this page is hand-written, not generated.
- It is a one-paragraph fix, and it falls inside the Done-when line even though the file is outside `Where`.

**4. Step 4's "what the reading was not given" is false with one thread.** Raised by A6 and B2 (merged).
- The same thread reads the whole brief, so the sentence promises an independent cross-check that no longer exists.
- The line is in the changed skill text and steers every future review.
- Fix: reword it so the lead step re-checks each claim against the repo and the brief.

### Consider

- **The `"archive"` mode key inside a prefix-keyed map** (A4). It forces a special case, a second `shelve` set and a nested loop in `settle`. Computing `ended` once and deriving `("settle", "archive")` at the call site is simpler. The tradeoff: Act-on #1 will rewrite `shut()` anyway, so do this restructure in the same edit rather than separately.
- **A merged PR whose last Review is `not run` keeps its review threads unarchived** (A5). It is an edge case, but it is a literal gap in "archives its review thread on the next pass". The cheap options are to archive non-busy review threads of an ended slug regardless of verdict, or to document that they are kept on purpose.

### Noted
- **Files outside `Where`** (A7, B4). Each is required by the task: the three docs come from the Done-when line, and `t3.py` is needed because `_held` refused `archive`. The brief should have listed `t3.py`; that is not a defect in the PR.
- **The `docs/jbus.md:108` wording** (A8). It is a fair readability nit, but the sentence will need rewriting anyway once Act-on #1 changes the rule.
- **The test fake keeps archived threads listed, and pre-existing settled A/B subagents are never archived** (B3). How real T3 lists archived threads is unverified, so the first half is hypothetical. The second half concerns legacy reviews, while the task targets new PRs and leaves old reviews alone.

### Dismissed
- None. Every finding was grounded, and the low-value ones are low-impact rather than wrong.

### Agreement Map
- **Independent agreement on the archive rule.** Both reviewers flagged `shut()` (A2/B1). A came at it from safety (absence → irreversible archive) and B from duplication (a second definition of closed). Together they make it the strongest finding: the rule is both unsafe and redundant.
- **Agreement on the stale step-4 sentence** (A6/B2) and the out-of-`Where` files (A7/B4). On the files they also agreed the changes were justified.
- **A alone** found the hollow jmerge test (A1) and the missed `flow.html` (A3). Both are concrete Done-when gaps, which suggests A checked the Done-when list more literally.
- **B alone** looked at test fidelity against real T3 (B3), which is useful but speculative.

The core change, one thread with one review, looks sound to both reviewers. The real problems sit in the new archive path and in one test that doesn't test what it claims.
