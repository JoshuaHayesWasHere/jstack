### Intent
> Task: the user, on the grill page: "we need to make threads more obvious per project, also i want to be able to track the work of scouts and crewmates as well". Done when each project's row and page has a Threads band by role, a `#/<project>/thread/<role>/<slug>` drawer shows what the thread works on, the server reads each scout request's `## Report` / `Status:` to say researching, reported or blocked, a missing thread list is shown as a blind spot and never as none, small-fixture tests cover the band, drawer and scout status, and `make check` plus `jgauge test-slot -- make check` pass.

### Reviewers
- Reviewer A: 8 findings
- Reviewer B: 7 findings
- They agreed on four issues: the duplicated row and role tables, the page with no band, the `health()` tag, and the out-of-Where panel folder. Each also found something the other missed: A found the scout-state errors, B found the source-health error. The review skill's questions were asked.

### Act On

**1. An ended scout with no Report still reads "researching"** (A1)
`request()` judges the state from the file alone, and `threadChip` shows that state ahead of the thread's liveness. So a crashed or interrupted scout shows "researching 2h00" under an "ended" heading. This is a concrete path, and it is the exact case the user asked to be able to follow: a scout that stopped without reporting needs attention, and the page says it is working. The fix stays inside Where: say "researching" only while the thread is out, give an ended scout with no Report its own amber word, and add a test.

**2. `Status: not done` shows as a green "reported"** (A2, plus the capital-B point from B6)
Every Status except `blocked` maps to `reported`. The scout template allows `done | not done | blocked`, and jbus's own settle check treats anything but `done` as unfinished. The view therefore contradicts jbus. Two changes are needed:
- Map `done` to `reported`, `blocked` to `blocked`, and anything else to a non-`ok` "not done" state.
- Compare case-insensitively, so `Status: Blocked` stops reading as reported.

Test a last Report whose Status is `not done`. The current fixture only covers `not done` followed by a later `done`.

**3. One thread row written twice, and two role tables** (A3, B3)
Both reviewers found this independently. `about()` in `thread/panel.js` copies `threadRow()` line for line. `ROLE` in page.html sits beside `ROLES` in the threads panel, both as positional arrays, and they already disagree on wording ("crews" vs "Crewmates"). Fix it in this PR, since both are new code here:
- Keep one row renderer, with a parameter for the title cell.
- Keep one ordered role table with named fields, and derive the band and filter order from it.

Moving `threadChip`, `LIVESAY` and the role table out of page.html is a judgment call. Do it if it falls out of the merge naturally.

**4. A project page with an empty thread list draws no band** (A5, B2)
Both reviewers found this, and it fails the first "Done when" line ("row and page"). The row draws a calm "0 out" band for the same data, so the page should too. Drop the conditional and the comment explaining it, and add a test for the empty-list case.

**5. The `scouts/` source always reports "ok"** (B1)
This comes from one reviewer, but it is concrete. `seen` never passes `read` or `path`, so a home with no `scouts/` directory, or one it cannot read, shows "ok". In `request()`, any `OSError` becomes "missing", so a permission error tells the user the request doesn't exist. That breaks the intent's rule of saying blind, never none.

Pass `read` and `path`, treat only `FileNotFoundError` as missing, and add a test with no `scouts/` directory.

B1 also notes that the `at` value is the directory's mtime, which does not change when a Report is appended to an existing request. Fix that if it is cheap, for example by using the newest request file's mtime.

### Consider

- **The `"threads"` tag in `health()`** (A4, B5). Both reviewers flagged it. It is a magic string in a shared helper, filtered by one caller and explained in prose. The cleanest fix is for `amber()` to add the threads reason itself and for the threads chip to leave `health()`. It is cheap and inside page.html, but it does not change behaviour today, so it is not blocking.
- **`gates_inside=True` followed by `re.split`** (A6). If A's claim holds, deleting both lines and the docstring sentence is a free simplification. Check that `mirror.sections` without `gates_inside` gives the same Report body first, because B6 says this mirrors `jbus.threads._scouts`, which may rely on the flag.
- **Unused defaults on `_threads`** (A7). Make `home` and `day` required and drop the two guards, unless the new tests call `_threads` without them. Grep the tests before changing it.
- **The private `_mtime` import** (B7). Defining the scouts `Source` in state.py next to `SCOUTS` matches how `PASS_FILE` and `MERGE_LOG` are handled. The B1 fix touches this line anyway, so do it there.

### Noted

- **`panels/thread/` outside the Where line** (A8, B4). The `thread/<role>/<slug>` route needs a drawer kind, and panel discovery appears to need a module, so the stub is a plausible necessity rather than scope creep. The PR description should say so. The undocumented `adds.band` hook belongs in `src/jbus/view/panels/__init__.py`, which is outside Where, so that is for later.
- **Three readers of the scout Status line** (B6). A shared "last Report and its Status" helper in `jbus.threads` or `mirror` is the right end state, but it is outside Where, so it is for later. The case-sensitivity part is folded into Act On #2.

### Dismissed
None. No finding was wrong or rested on missing context. The weakest were A7 and B7, which are real but minor, so they sit in Consider rather than Dismissed.

### Agreement Map
The two reviewers converged on structure: the duplicated row and role tables, the `health()` tag, the missing page band, and the extra panel folder. That consensus makes the duplication and the "Done when" gap firm. They diverged on correctness:
- A traced the scout state machine and found two wrong-state paths (A1, A2).
- B traced the source-health plumbing and found it cannot report blind (B1).

Neither saw the other's correctness bugs. The pattern suggests the data layer got less scrutiny than the rendering, and the remaining risk is there. The test fixtures cover only the happy combinations: a waiting scout with no Report, an ended scout with one, and a directory that exists. Each Act On item comes with a fixture for the combination it found missing.
