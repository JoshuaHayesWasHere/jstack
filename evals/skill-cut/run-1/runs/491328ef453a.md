### Intent
> Eliminate the Exec home. Sous Chef is the one orchestrator, jbus's webhook carries escalations to it, and the user's word comes down by `jbus word`. The experts are retired along with Exec. This PR is step 4 of `scouts/exec-home-removal.md`. It strips Exec from the new-home, home and handoff skills, from `jroles`, from jbus's queue, word and cli text, and from the docs and tests. It keeps any behaviour a test still needs, renamed. It is done when `rg` finds only shell `exec` and `make check` passes.

### Act On

**The retired `[exec]` table's URL and key are no longer redacted, and the table now loads silently** (A1, B1)
- Both reviewers traced this independently to the same execution path: `hooks()` now returns `[*self.projects, self.webhook]`, so a leftover `webhook_url`/`webhook_key` drops out of `secrets()`.
- The brief said to "keep any behaviour a test still needs, renamed". The PR deleted the behaviour and its test, and recorded neither the change nor the reason.
- The exposure is narrow. Nothing reads that URL any more, and the user's own config has no `[exec]`. But this is secret handling and the brief explicitly addressed it, so it should not slip through unrecorded.
- Keeping the literal key `"exec"` in source would fail the `rg` Done-when line. The remedy that fits both is generic: warn on any unknown top-level table, and redact `webhook_url`/`webhook_key` found in any table jbus does not read, with a test that loads such a config and checks `secrets()`.
- If the user prefers the deletion, the PR must say so as `Finding: not fixed, … because`.

### Consider

**The `exec-webhook` streak cleanup was deleted, not renamed** (A2, B2)
- B checked the live state: `streaks.json` has no such key and no `exec-sent.json` exists, so this reconciliation is dead on this machine.
- The tradeoff is restoring it under a neutral name (cheap, but it keeps dead code) versus a one-line PR note that the state was checked and the cleanup dropped on purpose.
- I'd take the note. The departure from the brief must be written down either way.

**The party handoff has no real party left** (A3)
- Exec and the experts are retired, and `party_home` never handles a `CHARTER.md` folder. The tests keep the path alive with an invented `desk` party.
- The user said "we are moving from this pattern", which argues the whole section goes.
- The brief, however, asked only to remove the `exec` role and case. Cutting the section is a bigger change in `skills/handoff`.
- This is worth a follow-up brief, not a demand on this PR.

**The new home line adds a rule** (A5)
- "A home sends no other thread a status" goes beyond the one line the brief named. It also reads against the home messaging its own crewmates and scouts.
- If this clause is the scout's section 5c wording, it stays. If not, drop it: "Do not touch" covers home text the brief does not name.

### Noted
- **Files outside "Where"** (A4, B3): `project.py`, the t3 fixture README, `test_jbus_view.py` and `test_home_on_bus.py` are text renames the `rg` Done-when line requires, so they trace to the task. `__init__.py` is the only behavioural one, and it is handled under Act On.
- **The `ROLES` tuple pin in `test_roles.py`** (A6): this is mildly implementation-shaped, but harmless. The suggested fix of refusing `exec:` in the test would itself fail the `rg` Done-when line, so leave `orchestrator` as the refused role.
- **The gauge fixture still uses the removed pair-telling message** (A7, B5): the entry should stay, since `t3_thread_send` is still used. Rewording it as a pass-on message is a cheap tidy-up if the crewmate is in the file anyway.
- **`who()` and docs/jbus.md:279 label every session "the <dir> home", Sous Chef included** (B4): the code behaviour is pre-existing. The changed doc line could say "the name of the directory it ran in" at no cost. The audit-trail labelling is for a later change.

### Dismissed
None outright. Every finding was valid in substance. Where a suggested remedy was wrong, I kept the finding and set that remedy aside (A6's `exec:` test, B1's literal-key option).

### Agreement Map
Both reviewers converged on the same real gap: the PR read "no longer name Exec" as "delete everything Exec touched". That swept away two pieces of behaviour (redaction and reconciliation) that the brief said to keep under new names, and the PR did not record the departure. The consensus is the strongest signal here, and it points to one fix pattern: generic handling where it protects secrets, and a recorded decision where the code is dead.

The two reviewers diverged where reading went beyond the diff. A questioned whether the party pattern survives at all, and B looked at the audit labels. Both are fair follow-ups, not blockers.

Otherwise the findings were mostly scope bookkeeping and nits. The change itself is close: fix or record the redaction, write the streak note, settle the A5 clause, and it ships.
