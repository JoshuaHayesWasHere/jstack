### Intent
> Replace the two pr-review reviewer subagents (A/B) per pull request with one scoped review thread. That thread reads `gh pr diff` itself, keeps the same intent, `SCOPE` text, seven questions and blast-radius proof, and writes one `## Review` section (`Reviewers: 1`) that jmerge's ready rule still accepts as is. jbus archives that thread, not only settles it, on the next pass after the pull request merges or closes, and never archives the review thread of an open pull request. Docs and skills that say "two reviewers" now say one. Tests cover the skill text, the archive behaviour and jmerge readiness. `make check` passes.

### Act On

1. **`shut()` decides "closed" by absence from a 100-item open list, and that decision now archives threads** (A2, B1, merged)
   - **Location:** `src/jbus/threads.py:164`
   - **What happens:** a slug counts as closed when its Result's `Branch:` URL is missing from `world.open`.
   - **Why it fails:** that list is capped at 100 and is compared as raw strings. So any of these gets the review thread of a live pull request archived:
     - the 101st open pull request;
     - a URL in a different form;
     - a renamed repo.
   - This breaks the Done when line "a review thread of an open pull request is never archived" through a concrete path, not a hypothetical. The archive is also destructive and jbus never reverses it.
   - B adds that `watch.pull` already defines MERGED/CLOSED, and the two rules disagree on the test's own `eta` case.
   - **Fix:** remove `shut()`. Derive the ended set from `watch.pull` returning `Pull.MERGED` or `Pull.CLOSED`, so "closed" has one definition. Make sure CLOSED rests on a real state, either a merged-cache entry or GitHub reporting `CLOSED`, and not on absence alone. If `watch.pull` itself infers from absence, confirm the state before archiving.

2. **The jmerge new-shape test never lists a finding, so the findings-answered rule goes untested** (A1)
   - **Location:** `tests/test_pr_review_skill.py:1512-1534`
   - **What happens:** the template's `Findings:` line has no `": "`, so the fill is a no-op and the `- ` item is filtered out. `ready.py` therefore sees `found == 0`.
   - **Why it matters:** the test passes even if matching findings to their `Finding:` answers broke. That is the core of the Done when line "its findings answered."
   - **Fix:** write a real `Findings:` item into the section. Add a negative case: the same section with the `Finding:` line removed must not be ready.

3. **`docs/flow.html:214` still says "Two reviewers… then settles itself"** (A3)
   - The Done when line explicitly covers "any other skill or doc." This page is hand-written, not generated, so nothing will fix it later. It is a one-line fix.
   - It sits outside `Where`, but the Done when line pulls it in, the same as `README.md` and `docs/flow.md`.

4. **Step 4 claims the lead judges "against what the reading was not given," which is false in one thread** (A6, B2, merged)
   - **Location:** `skills/pr-review/SKILL.md:232`
   - The reading and the judgment are now the same thread, and that thread has already read the whole brief. The sentence promises an independent cross-check that no longer exists, which is exactly the false confidence a review skill must not create.
   - **Fix:** reword it to say what the step actually adds: re-checking each claim against the repo and the brief, plus the dismissal discipline.

### Consider

- **The `"archive"` mode key sits inside a map keyed by title prefix** (A4)
  - **Location:** `src/jbus/threads.py:203-208, 363-394`
  - It forces a special case, a copied `shelve` set and a nested loop with `break`.
  - The archive decision could be computed at the call site from `role_of(title)` and `slug_of[at] in ended`.
  - **Tradeoff:** this is a real simplification, and the Act On fix #1 already reworks the code that produces `ended`. Do both together if it's cheap. On its own it would not block.

- **A merged pull request whose last Review is `not run` never gets its review threads archived** (A5)
  - After a merge, nothing waits on the thread any more, and the Done when line says "archives its review thread on the next pass."
  - **Tradeoff:** it's an edge case, since a later scoped pass would have to write `not run`.
  - **Fix options:** archive non-busy review threads for any ended slug regardless of verdict, or document that they are kept on purpose.
