### Intent
> Topic 10, "a way to undo a bad merge into standing.md". The home skill (including `skills/home/scoped-homes.md:7`) and the handoff skill run `jbus snapshot` right after any edit to `$H/standing.md`, so each edit is its own commit in `~/.local/state/home` and is pushed. The twice-daily timer stays. `jbus snapshot` takes `--why <text>`, which goes into the commit message after the time. `docs/state.md` gets an "Undo an edit to standing.md" section built on `git log -p`, then `git show <commit>^:<path> > ...`, then a snapshot with `--why`. Tests run in a temporary tree with a bare remote and prove the commit and the restore. `make check` exits 0.

### Reviewers
- Reviewer A: 7 findings
- Reviewer B: 5 findings
- They agreed on four issues: concurrency, the restore truncating the file, the new handoff duty, and `docs/jbus.md`. A alone raised the mislabelled whole-tree commits as a separate finding (B folded it into its concurrency finding), along with prose duplication and a test-helper nit. B alone raised the test name. Both answered the review skill's questions.

### Act On

**1. `take` has no lock, and snapshots can now run from many homes at any time.** Raised by A1 and B1.

Before this change, the timer was the only caller, so there was a single owner. Now every home and scoped home also calls `take` on the same index. The failure is concrete:
- Two runs collide on `.git/index.lock` and one of them raises `Failed`.
- If the timer's run is the one that fails, `OnFailure` sends a false alarm to the desk and every project.
- A's `git reset -q` between B's `add` and `diff --cached` makes B print "nothing changed", so B's edit gets no commit of its own. That breaks a Done-when line outright.

The fix is cheap and inside "Where": hold an exclusive `fcntl.flock` on a file in `.git` across add, commit and push in `src/jbus/snapshot.py`. Concurrent runs then wait instead of failing.

**2. The documented restore empties the live `standing.md` whenever `git show` fails.** Raised by A2 and B2.

The shell truncates the target before `git show` runs. Three ordinary inputs make `git show` fail:
- a mistyped hash;
- the commit that created the file;
- the root commit.

The doc's next step then snapshots the empty file, and every home after that starts with no standing rules. This is data loss on the exact file the feature exists to protect.

The fix should keep the `git show` form that Done-when names: write to `<path>.tmp && mv <path>.tmp <path>`. The doc should also say what undoing the creating commit means, which is to delete the file. Add a test where `<commit>` is the commit that created the file. The current test (`tests/test_jbus_snapshot.py:309`) only covers a parent that has the file.

**3. The handoff skill gains a rule-writing duty nobody asked for.** Raised by A5 and B3.

The added line at `skills/handoff/SKILL.md:92` reads "One it did not write yet goes there now". That gives handoff a new way to write standing rules. It also contradicts the sentence just before it, and it was invented so the snapshot step had something to attach to.

The task asked handoff to snapshot after an edit, not to start making edits. A behaviour change in a skill that every home runs should go through a gate, not ride in as a side effect. Cut it and keep only the general instruction "after any edit to `$H/standing.md`, run `jbus snapshot --why ...`".

### Consider

**4. A `--why` commit sweeps in the whole dirty tree, so its message describes less than it contains.** Raised by A3, and part of B1.

The path-limited `log -p` and `show` still work, so undo is not broken by this. The lock from item 1 also stops two homes' edits from being lost. It does not stop root and scoped edits to the same `standing.md` from landing in one commit, though, and undoing "the bad one" would then revert both.

Committing only the named path when `--why` is given (`git commit -- <path>`) would make "a commit of its own" literally true. The cost is a new argument and some interaction with the timer's commit. This is worth doing if the user reads the unfiltered `git log`. Otherwise it can wait.

**5. A test name covers only half of what the test checks.** Raised by B5.

`test_a_snapshot_with_no_why_says_only_the_time` also checks the `why=` message, and its no-why half duplicates the test at line 77. Renaming it and dropping the duplicate half costs almost nothing.

### Noted

- **The rule lives in prose in three skill files** (A4). Prose is the design the brief chose ("one flag and one step"). A `jbus standing add` verb would enforce it, but it is outside "Where" and was rightly flagged for later. One cheap piece is worth doing in this PR: handoff hardcodes `added` while the other two copies say `<added, changed or removed>`, so align that wording.
- **`docs/jbus.md` is changed but is not in "Where"** (A6, B4). The edit is accurate and needed, since the new flag would otherwise be undocumented on the commands page. The brief's "Where" line missed this file. Keep the change and record it as "not fixed, because".

### Dismissed

- **`with_origin` duplicates inline setup in older tests** (A7). The only way to "fix" this is to rewrite tests this PR didn't touch, which is out of scope. The migrate-callers principle is about internal APIs, not a test fixture helper.

### Agreement Map

The two reviewers converged on the three Act-on items independently. Each of those has a concrete execution path, so the agreement is a real signal and not shared noise.

The main divergence is framing:
- A split concurrency (A1) from mixed commits (A3).
- B combined them in B1.

Separating them is useful. The lock is a correctness fix that is clearly in scope. Path-scoped commits are a design improvement with a real cost.

Severity calibration also diverged. A rated the handoff duty a warning and B rated it a nit; I side with A because it changes skill behaviour. Neither reviewer padded its findings with style complaints.

Overall the feature meets its Done-when lines except under concurrency and the restore edge cases. With items 1–3 fixed, it can ship.
