### Intent
> The user asked from the grill page to make threads more obvious per project, and to be able to follow scouts and crewmates. The task adds a Threads band to each project's row and page: threads by role, out first with liveness and last write, ended-today dimmed, the rest folded, all from `pass.json`. It adds a `#/<project>/thread/<role>/<slug>` drawer that shows the task step or scout request a thread works on. It adds one new read-only source, `scouts/` requests' `## Report` and `Status:`, to say researching, reported or blocked. A pass with no thread list is shown as a blind spot, never as none. It needs fixture tests and a passing `make check`. Everything stays vanilla, read-only, and within `state.py`, `view/__init__.py`, `panels/threads/`, `page.html` and the tests.

### Reviewers
- Reviewer A: 8 findings
- Reviewer B: 7 findings
- They agreed independently on three things: the duplicated row renderer and role tables, the missing band on an empty project page, and the `health()` tag. Both also flagged the `thread/` folder outside "Where". The review skill's questions were asked of both.

### Act On

1. **An ended scout with no Report still reads "researching"** (A1). `request()` derives state from the file alone, and `threadChip` puts that state ahead of liveness. A scout thread that crashed or was settled early shows "researching", dimmed, and its drawer says "researching" under an "ended" heading. This is the one case where the user most needs the band to be honest, and the path is concrete.
   - Fix: say `researching` only while the thread is out. Show an ended scout with no Report as a distinct amber state.
   - Test: add a fixture of an ended scout with no Report.

2. **`Status: not done` renders as a green "reported"** (A2, with the concrete parse gaps from B6). Anything but `blocked` maps to `reported`, which uses the `ok` chip. The scout template allows `done | not done | blocked`, and jbus's settle check treats anything but `done` as unfinished. The view therefore contradicts jbus.
   - Fix: map `done` to reported, `blocked` to blocked, and anything else to a non-`ok` not-done state.
   - While in there, match case-insensitively and take the Status line the way the settle check does (the last one in the Report region).
   - Test: a last Report whose Status is `not done`.

3. **The thread row and the role tables are each written twice** (A3, B3: consensus). `about()` copies `threadRow()` line for line. `ROLE` in `page.html` and `ROLES` in the threads panel are two positional tables whose column meanings differ, and they already disagree on wording ("crews" and "Crewmates"). Both copies are new in this PR, so they should collapse now, before they drift.
   - Fix: keep one row renderer with a title parameter.
   - Fix: keep one ordered role list with named fields, and derive band and filter order from it.
   - Moving the helpers out of the page shell (B3's last point) is fine but optional.

4. **A project page with an empty thread list draws no band** (A5, B2: consensus). "Done when" says each row **and page** has a Threads band. The row draws a calm "0 out" band for the same data, and the page draws nothing.
   - Fix: delete the special case and its comment, and let `band()`'s calm state handle zero.
   - This removes code rather than adding it.

5. **The `scouts/` source can only ever report "ok", and a read error becomes "no request"** (B1, single reviewer but a concrete path).
   - `seen` never passes `read`/`path` to `_source`, so a missing or unreadable `scouts/` cannot surface.
   - `request()` folds every `OSError` into `missing`, so the drawer says the request doesn't exist when it couldn't be read.
   - That is exactly the "blind spot shown as none" the task forbids. `at` is also a directory-mtime proxy that does not move when a Report is appended.
   - Fix: pass `read`/`path`. Treat only `FileNotFoundError` as missing and anything else as unreadable. Add a test with no `scouts/` directory.

### Consider

- **The `"threads"` tag in a fourth `health()` slot, filtered out only by `projectRow`** (A4, B5). This is a stringly-typed special case in a shared helper, with prose to explain it.
  - Simplest fix: drop the chip from `health()` and let `amber()` add the threads reason itself.
  - Tradeoff: it works today, and only one caller draws chips. It is cheap enough that I'd do it alongside fix 4.
- **The `thread/` panel folder outside "Where", with an empty `panel.py` stub and an undocumented `adds.band` hook** (A8, B4).
  - The route plausibly needs a drawer kind, but "Where" anticipated route needs living in `view/__init__.py`.
  - Either register the drawer from `threads/` and drop the stub, or say in the PR why a second folder is required.
  - Documenting `adds.band` in `panels/__init__.py` is outside "Where", so it is noted for later.
- **`gates_inside=True` then re-split at `## `** (A6). This is likely a no-op pair, and deleting both lines and the docstring sentence simplifies the parser. Check it against B6's point that this mirrors `jbus.threads._scouts` before cutting, since the mirroring may be deliberate.
- **Optional `home`/`day` defaults on `_threads` that no caller uses** (A7). Making them required removes two guard branches. This is small, but it is dead flexibility added in this PR.

### Noted

- **A shared "last Report and Status" helper in `jbus.threads`/`mirror`** (B6). This is the right long-term home, but it is outside "Where", so it is for later. The parts fixable now are folded into Act On 2.
- **The private `_mtime` imported across modules** (B7). This is minor. If fix 5 moves the scouts `Source` into `state.py` next to `SCOUTS`, it goes away on its own.

### Dismissed

- None outright. Every finding traced to a changed line with a concrete consequence or a cheap deletion. Nothing was reviewer filler.

### Agreement Map

The reviewers converged on structure: the duplicated renderer and role tables, the empty-page band, the `health()` tag, and the extra panel folder. Those are high-confidence, and two of them remove code.

They diverged on correctness, and each found a different real gap in how honestly the band reports scouts:
- A read the scout state semantics: ended-but-unreported, and `not done`.
- B read the source health: missing or unreadable shown as ok or none.

That pattern means the structural cleanup is safe to take as given. The scout-status logic is under-tested: every correctness finding is a case the fixtures don't exercise, because the "researching" scout is always live and the `not done` Report is always superseded. The fixes there should land with their tests.
