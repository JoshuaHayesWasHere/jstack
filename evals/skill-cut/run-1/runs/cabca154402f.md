### Intent
> Every gate is act-unless-stopped. The thread acts on its default at once, the user is shown the question as already acted on, and a differing answer is carried back. After 2 hours a pass closes a plain open question by its default and by silence, with a basis that says it is not the user's word. A later differing answer is still taken. A gate whose default deletes data, rewrites history, spends money, touches prod or real users, changes access or secrets, or publishes must carry `Holds:` and a `Fail-safe:`. It does not act and is never closed by silence. `jbus gate` refuses a gate with no default, a default that is not the recommended option, and a `Holds:` with no fail-safe or an unknown case. The skills, template and docs state the rule and the table. Fake-clock tests cover all of it, and `make check` exits 0.

### Act On

**1. Re-piping a silence-closed question returns "already answered" and drops a new `Holds:` (A1)**
- `ask` treats any record with an answer as settled, and a silence close now counts as an answer.
- A thread re-pipes the same gate at a later head, which the module docstring says threads do, and adds `Holds: deletes data`. It gets `already answered`, the `Holds:`/`Fail-safe:` lines are thrown away, and the crew and scout skills tell it "Go by it."
- A destructive action then goes ahead with nobody's yes. That is exactly what the fail-safe half of the task forbids.
- The path is concrete, and the test at :768 asserts the bad reply.
- Fix: `ask` should treat `_open(one)` records as replaceable, and a re-pipe that adds `holds` should clear the silence answer. Add the fake-clock test A1 describes.

**2. A held gate answered with its default never reaches its thread (B1)**
- `tell` and the page's carry path skip `keeps` answers. That rested on the old assumption that the default was already done.
- A `Holds:` gate's default has *not* been done. So the user's "yes, the recommended default" sends nothing, and the held action waits forever. Only a differing answer moves it.
- This breaks the core of the fail-safe design.
- Fix: carry `keeps` answers when `one.holds` is set, with a go-ahead message. Fix the CLI and page wording, and fix docs/jbus.md:132.
- Add a test: a `Holds:` gate answered `--default` sends one message.
- `View._carry` is outside "Where", but `tell` and the docs are inside it. The page side could be noted for later, but this is the user's main answer path, so I'd fix both here.

**3. Silence closes the stack-conflict questions that ask the home, so the stack parks (A2)**
- `_quiet` closes every open record without `holds`. That includes the link-conflict questions the home's own table says are for the home, not the user.
- The home's jq picks them by `.answer == null`, so after 2 hours they drop out of `$LINKS` and the rebase line is never sent.
- It is a concrete path, and it produces parked work, the opposite of the task's goal.
- Fix: in `questions.py`, exempt them from `_quiet`.

**4. Nothing the user reads shows "already acted on" or the fail-safe (A4, B2)**

- The item's `line` is unchanged. The home's jq block (in "Where") pulls none of them. The page panel and `waiting._blocks` drop them.
- Two Done-when lines are unmet: "shown to the user as already acted on" and "with the dry-run, plan or bundle attached".
- The only test reads the JSON file, which is a proxy for what the user sees.
- Fix inside "Where": put the state in `line`, and add `.holds, .fail_safe` (and `acted`) to the home's jq and printf. Note the page panel for later.

### Agreement Map
The reviewers agreed on the surface issues: display of the new state, and the redundant marks. Each found a *different* critical bug, A1 in `ask` and B1 in `tell`, and A found a third (A2) in `_quiet`.

All three come from one cause. The change added two new states, "held" and "closed by silence", but the existing paths still assume only two: "answered = settled" and "default = already done".
- `ask` still treats every answer as settled (A1).
- `tell` still treats every default as done (B1).
- `_quiet` still treats every open question as a user gate (A2).

So the "code judo" fix is to name the states explicitly: open, held, closed-by-silence, answered. Then make `ask`, `tell`, `_quiet` and the item `line` each branch on that one state, rather than patching each path separately. That fixes Act On 1–4 together and gives the fake-clock tests one thing to assert. Once it's in, the redundant-marks cleanup and the expert-skill question can be decided on their own.
