### Intent
> The user said the UI/UX "feels subpar" and lacks a header, sidebars, navbars or helpers. This PR adds:
> - a header showing the name, where you are, and the time of the last read
> - a sidebar with "All" first, then each project with its waits count and a health dot, becoming chips under 900 px
> - the machine's Room, jbus and Runners drawn once, never inside a project
> - a Bus card that no longer wraps, and no sideways scroll at 1440, 900 and 390, checked by browser tests
> - empty lanes folded
> - green `make check` and `jgauge test-slot`
>
> It works within the user's decisions: overview first, hash routes, one vanilla file, a 250-word cap for the overview and 150 for a project, retired projects shown as "no such project", and tips on hover.

### Act On

1. **The word caps were loosened by moving the header and sidebar out of what they measure** (A4, B1, B2, merged).
   - `words` now counts only `<main>`. The machine row moved into the sidebar, so it is no longer counted at all. The new `SHELL = 30` cap is fixed, even though the docstring says the shell grows with each project, so it already sits near its limit at three projects.
   - The user set 250/150 for what the first screen shows. This is a proxy check: the new content was moved out of the count instead of being made to fit.
   - Fix: count main + header + side against `WORDS`/`EVERY`. If a shell figure is kept, make it a diagnostic or base + 2 × projects, and test it with more than three projects.

2. **The header's "read" time shows the current time once the server is gone** (A3).
   - The path is concrete: `lost()` sets `NOW = Date.now()`, then `render`, then line 752.
   - This breaks the "Done when" line "the time of the last read" in exactly the case where that time matters.
   - Fix: keep the last-answer time from `took`/`tookStack` and show that.

3. **The sidebar's health dot and the overview row's chips use two rule sets, and they already disagree** (A2, B5, merged).
   - A project with blind spots gets a green dot but an amber "Blind 6" chip.
   - `troubles` prints "0 failed wakes, last error: X", while the row chip guards against that case.
   - The user's steer was that every mark's tip tells the truth, and here two marks contradict each other.
   - Fix: one helper per health fact, read by both the chips and the dot/tip.

4. **The sidebar stays empty for up to 15 s on a link to a project that doesn't exist** (A1).
   - This happens when the 404 arrives before `/stack.json`, which is a likely order. The `if (S) render()` guard then skips the redraw.
   - The "no such project" link is a case the user explicitly steered on.
   - Fix: drop the `S` guard, since `put` already skips parts that didn't change, and add a test that loads `#/nope` and checks the sidebar items at the first poll.

5. **On a project page, the jbus machine item says "passing" when `/stack.json` failed or is stale** (B3).
   - `unwell` comes from `STACK.machine.unwell`. If the stack request fails, the failure handler is silent, `STACK` is null, `unwell` becomes `[]`, and the item reads ok.
   - That is a false health claim, the same kind of error as item 2.
   - In-scope fix: derive `unwell` from `S.sources` if it can be done in the page. Otherwise, show "unknown" rather than ok when there is no stack read.
   - Adding a server-side `machine` flag would be outside the "Where" line, so it is noted for later.

### Consider

- **The machine row is missing on the no-such-project view** (A7, B6).
  - It contradicts the test docstring "drawn once, on every view", and the fix is one line in `machineOf`, next to item 4.
  - Tradeoff: low impact, but cheap to fix in the same pass.
- **`page.html` grows from 979 to 1067 lines** (A5, B4).
  - The user asked for "one vanilla file", but B's point holds: the panels are inlined server-side, so a `shell` script in `panels/` would still be served as one file with no build step.
  - Tradeoff: if wiring it in touches `__init__.py`/`state.py`, that is outside the "Where" line. Either split within the panels mechanism or say in the PR why it stays.
- **The theme control became a cycle button with no test** (A8, B9).
  - Nothing in the task asked for this change.
  - Fix: either keep the three-button group inside the header, or justify the change by header space and add a click test covering auto → light → dark → auto and the stored value.
- **The sidebar's sticky offset is hard-coded to 50 px** (A6, B8).
  - The header wraps, so the sidebar slides under it at 900–1100 px wide when the crumbs are long.
  - Tradeoff: cosmetic, but a shared CSS variable fixes it cheaply.
- **A stale comment, "One request a poll"** (B7).
  - This change made the comment false, and it is a one-line fix.
