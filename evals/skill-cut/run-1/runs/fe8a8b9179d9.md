### Consider
- **A leftover `[exec]` table now loads silently, and its `webhook_url`/`webhook_key` are no longer redacted** (A1, B1). Both reviewers found this independently, and it touches secrets, so it gets a careful look. The tradeoff: the user ordered Exec "completely gone", the live config has no `[exec]` or `exec_watch`, and nothing reads that table anymore, so the URL would reach output only if some other text happened to quote it. The real exposure is a restored or older config on another install, and that is thin for a personal stack. My recommendation is not to rebuild a renamed "retired table" mechanism. Instead, record in the PR that the notice and redaction were dropped on purpose and why ("Finding: not fixed, …, because"). If the user wants protection against this, B's broader idea of redacting any `webhook_*` key in any unread table is the version worth building, and it belongs in a follow-up because `__init__.py` is outside "Where".
- **The `exec-webhook` streak and `exec-sent.json` cleanup was deleted rather than renamed** (A2, B2). This departs from the brief's "keep any behaviour a test still needs, renamed". The crewmate also deleted the test that needed it. B checked the live state: there is no `exec-webhook` streak and no `exec-sent.json`, so the reconciliation guards nothing on the only machine that matters. Deleting it fits "completely go". The departure from the brief still has to be stated in the PR, with the check that justified it, so it does not read as an oversight.
- **The gauge fixture still uses the removed pair-tell message** (A7, B5). In `tests/test_home_gauge.py`, the `t3_thread_send` entries are correct to stay, because the mail pass-on still uses that tool. Their example text, "the home of demo is another now", is from the step this PR deleted. Changing it to a pass-on-shaped message is cheap and keeps the test describing calls a handoff still makes. It does not block.

### Noted
- **Files outside "Where"** (A4, B3): `project.py`, `tests/fixtures/t3/README.md`, `test_jbus_view.py` and `test_home_on_bus.py` are wording changes the `rg` Done-when line requires, so they trace to the task. The `__init__.py` change is the one with behavioural effect, and it is covered under Consider above.

Cutting the whole party pattern goes beyond this brief, which asked only that the `exec` role and case go. Raise it with the user as a follow-up brief.
- **`who()` and `docs/jbus.md:279` label every session as "the <dir> home", Sous Chef included** (B4). The code behaviour predates this PR. The doc line could be reworded to "the name of the directory it ran in" in a follow-up about how Sous Chef is identified in the audit trail.

### Dismissed
- **The roles test pins the tuple and should refuse `exec:`** (A6). The `ROLES` tuple is the role set `jroles` exposes, so pinning it is a fair behavioural check that `exec` is absent. Using `exec:` as the refused input would put `exec` back into `tests/` and break the `rg` Done-when line.

### Agreement Map
The reviewers converged on the one real tension in this PR: the brief said "rename behaviour a test still needs", and the crewmate deleted both the behaviour and its tests. That happened for the retired-config notice and redaction, and for the streak cleanup. Both reviewers also checked the live machine and found it clean. Together these say the deletions are safe here but were not recorded, so the remedy is disclosure in the PR rather than code. They diverged where each looked beyond the diff. A went after scope, in both directions: the orphaned party pattern, and the extra clause in the home skill. B went after the orchestrator's identity. The single Act On item is a scope slip in the skill text, which suggests the code side of the removal is sound.
