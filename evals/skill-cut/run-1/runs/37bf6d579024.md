I don't edit the README myself. **"The home does not do the work"** says a home never edits the repo or reads its code, even for one word. I tell the user that in one line and hand the fix to a crewmate, which takes about as long.

1. **Write the brief** (Handing a task to a crewmate, step 1) at `$H/tasks/readme-typo.md`, in the shape of `$T/brief.md`:
   - `Task: fix the one-word typo on line 3 of README.md`
   - `Done when: line 3 of README.md has the word spelled correctly; nothing else changes`
   - `Proves it: git diff shows one word changed on line 3, and the repo's check passes in CI`
   - `Size: S`, `Where: README.md`, `Review: none` (text only), `Playbook: none`, `Design: none`, and no `Home:` line, since this is the root home.
2. **Check the machine:** `uv run --project "$T/.." jgauge room`.
3. **On `go`, launch:** `t3_thread_launch {"title":"crew: readme-typo","workspaceStrategy":{"type":"worktree","baseRef":"<default branch>","branch":"readme-typo","startFromOrigin":true},"message":"/crew readme-typo"}`.
4. **Record and report** (step 3): add `Thread: <id>` with the block, add the queue row with `jbus queue add`, and give the user the link. Because the brief says `Review: none`, I'll tell them the pull request will wait for their word to merge.
