### Act On

**1. The grandfather cutoff is earlier than the merge** (A1, B1)
`SHAPED_SINCE = "2026-10-15 11:15 ET"` (`src/jbus/dispatch.py:60`) is earlier than the PR's own commit (11:22). Any brief written from the old template and approved between 11:15 and the merge will be gated with "no size". Adding the line changes the brief's sha, which then gates it again as "brief changed after approval". The row is stranded, and that directly breaks the "no approved row stranded" requirement.

Both reviewers found this independently and traced the same concrete path through the code. The live queue is clean today (the latest approval was 11:06 ET) only because of timing. The window stays open until the merge.

The fix should tie grandfathering to when the change actually lands, not to a guessed wall-clock time. Add a test for a row approved after the constant but before the merge.

**2. Briefs written by a scout always gate on the Size placeholder** (A3)
In home step 1, a scout-written brief skips straight to step 2 (`skills/home/SKILL.md:494`), so it never reaches the new `Size:` paragraph at :498. The scout skill does not fill `Size:`, so the brief keeps `Size: S | M | L | XL`. `parse.sized` rejects that text as the template's own wording.

This is a concrete path, not a hypothetical one: every scout brief approved after the cutoff would be gated, and fixing the brief forces a new approval (the same chain as #1). The fix belongs in the home skill, which is inside "Where": have the home set `Size:` from the plan entry, the same way it already checks `Home:`. The matching change to the scout skill is outside "Where" and is noted for later.

### Consider

**3. Times are compared as text in a hard-coded "ET" shape** (A2, B2)
`at >= SHAPED_SINCE` is only correct when jsettings is configured for New York with the label `ET`. That is true for the user's config and for conftest today, so nothing is broken right now. Still, the code is a prose rule standing in for a real instant, which is exactly the kind of proxy check the review asks about, and both reviewers raised it.

Tradeoff: the fix is small, because `digest.py:149` already parses `ran_at`. Whatever replaces the cutoff in #1 should do the comparison with aware datetimes, so this one folds into that fix at almost no extra cost.

**4. Any file in `playbooks/` passes, including ones a crewmate never runs** (A4)
A brief naming `orchestrate`, `investigation`, `expert-*` or `opening-a-pr` passes the new check. The crew block then prints "not a crewmate's" and runs with no playbook, which is the failure the task set out to stop. The literal "Done when" line is met, but what the user wanted is not fully met.

Tradeoff: the failures actually observed were `fix` and `feature.`, and no misrouted brief like this has been seen yet. On the other hand, the fix is one `elif` reading `Run by:`, inside `parse.py`, and it uses the rule the crew block already applies. I'd take it.

**5. `_head` duplicates the loop in `proves_it`** (A5, B4)
`_head` is new in this PR, and the same head-scan loop sits just above it. Having `proves_it` call `_head` is cheap, stays inside "Where", and leaves one definition of a brief's head. Both reviewers flagged it. Cleaning up `dispatch.designed` is out of scope and noted for later.

The exact wording is already pinned with literals in `test_briefs.py`, so this coupling only means the dispatch test is checking routing, not wording. That is acceptable.
