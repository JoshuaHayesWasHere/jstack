### Intent
> The feature playbook's step 4 (size) has never fired: no brief carries a size. Also, briefs naming `Playbook: fix` or `Playbook: feature.` launched with no playbook. Add `Size: S|M|L|XL` to the brief and plan-entry templates. Have `parse.py` and `dispatch.py` refuse a brief with no size, or with a playbook that is not a file in `playbooks/` (or `none`), with one line each. Grandfather rows approved before the merge. Cover it with parser tests. `make check` and `jgauge test-slot -- make check` must pass, with no approved row stranded.

### Act On

**1. The grandfather cutoff is fixed before the merge, so it can strand approved rows** (A1, B1)
`SHAPED_SINCE = "2026-10-15 11:15 ET"` falls before the PR's own commit. Any brief written from the old template and approved between 11:15 and the merge has no `Size:` line, so it gets gated. Adding the line changes the sha, which re-gates the row as "changed after approval". That is the stranding the Done-when forbids. Both reviewers traced the same concrete path.

The live queue passing today, with the last approval at 11:06, only proves the state at the moment the check ran. Tie the grandfathering to the change actually landing. A cutoff set at merge time works. A better option is a rule that does not depend on a guessed wall-clock time, such as grandfathering an approval that predates the first launch pass running the new code. Add a test for a row approved after the old constant but before the merge.

**2. Scout-written briefs reach launch with the template placeholder, so every one gates** (A3)
Home step 1 sends a scout's brief straight to step 2 after checking `Home:`, which skips the new `Size:` paragraph. The scout skill doesn't fill `Size:`. Its briefs therefore keep `Size: S | M | L | XL`, and `parse.sized` rejects that. This is a concrete, recurring path to the same stranding as #1.

The fix is in the home skill, which is inside **Where**: check and set `Size:` from the plan entry on a scout's brief, as step 1 already does for `Home:`. The matching scout-skill change falls outside **Where** and is noted for later.

**3. Any file in `playbooks/` passes, including ones no crewmate runs** (A4)
The words of the Done-when are met, but its purpose is not. A brief naming `orchestrate`, `investigation`, `expert-*` or `opening-a-pr` still passes. The crew block then prints `not a crewmate's` and runs the work with no playbook, which is exactly the failure this task exists to stop. The fix is cheap: one more check in `playbook()` that reads `Run by:` and requires `a crewmate`, using the same rule the crew block already applies.

### Consider

**4. The cutoff compares stamp strings that depend on the configured zone and label** (A2, B2)
This is a real proxy problem. The comparison is correct only when jsettings is `America/New_York` with the label `ET`. That holds for the user's config and the tests today, so it is not broken now. Nothing enforces it, though, and an unset label (`EDT`) or another zone silently shifts the cutoff.

If the fix for #1 moves away from a timestamp constant, this issue goes away. If it keeps a time, compare aware datetimes the way `digest.py:149` already parses `ran_at`. The fix for #1 rewrites this line anyway, so fixing #4 at the same time costs almost nothing.

**5. The new `_head` helper duplicates the loop in `proves_it`** (A5, B4)
`_head` is new in this PR, and it leaves two copies of "the head ends at `## `" side by side. Having `proves_it` call `_head` costs one line. It is low-stakes, but it is new code creating new duplication, so it is cheap to do now. The copy in `dispatch.designed` is unchanged code, so that one is noted for later.

### Noted
- **Hand-typed `_SIZES` string** (A6): it could drift from `SIZES`, but there are four fixed sizes and the parser tests pin the wording. This is low impact.
- **The gate test takes its expected messages from `parse.sized`/`parse.playbook`** (B3): the test still executes dispatch and checks that the row gates, so it is not a wording-only test. Message drift is already caught by the literal strings in `test_briefs.py`. Pinning literals here as well would be marginally stronger.

### Dismissed
- None. No finding was wrong or made from missing context. The two nits are valid but minor.

### Agreement Map
Both reviewers independently converged on the grandfather mechanism. A1/B1 and A2/B2 are the same two problems, described the same way and backed by the same queue evidence. That consensus is the strongest signal in the review: the cutoff as written is the wrong shape, not just the wrong value.

They also agreed on the `_head` duplication, which is a minor point. The divergence matters more. Only A followed the change out to its callers, the scout path and the crew block's `Run by:` rule. That is where the two intent gaps turned up: code that satisfies the Done-when text but still lets an approved row strand, or a brief launch without a playbook. B stayed closer to the diff and caught the test-oracle nit.

Overall, the parser and templates are fine. The risk is concentrated at the edges where the new rule meets existing flows: the moment of the merge, scout-written briefs and playbook ownership.
