### Intent
> Replace the two pr-review reviewer subagents (A/B) per pull request with one scoped review thread. That thread reads only the PR's diff, posts one combined review, writes one `## Review` section that jmerge still reads as ready, and is archived by jbus when the PR merges or closes, never while it is open. Skills and docs that describe two reviewers must say one. Tests cover the skill text, the archive on merge, and jmerge reading the new section. `make check` must pass.

### Reviewers
- Reviewer A: 8 findings
- Reviewer B: 4 findings
- Both reviewers answered the review skill's seven questions. They agreed on three issues and each raised others the other did not.

### Act On

**1. Archive decided by absence from a 100-item open list** (A2, B1, merged)
- `shut()` (`src/jbus/threads.py:164`) treats a slug as closed when its Result's URL is missing from `world.open`.
- That list is capped at 100 and compared as raw URL strings. Both reviewers named concrete ways it misses an open PR: the 101st open PR, a URL in another form, a branch keyed differently.
- The result is an archive that jbus never undoes, which breaks "a review thread of an open pull request is never archived" outright.
- B adds that `watch.pull()` already decides MERGED/CLOSED, and the two rules already disagree in the new test (`eta`/`pull/8`).
- Fix: drop `shut()` and derive "ended" from `pull(...) in (MERGED, CLOSED)`, so the rule lives in one place. If `pull()` also infers CLOSED from absence, archive only on a confirmed state (`world.merged`, or GitHub reporting `CLOSED`).
- This is correctness on a destructive path, and both reviewers found it independently.

**2. The jmerge "new shape" test never lists a finding** (A1)
- A traced it concretely. The template's `Findings:` line has no `": "`, so the filled findings are never written, and `found == 0`.
- So the "findings answered" half of jmerge's ready rule is never exercised. The test would still pass if matching findings to `Finding:` answers broke.
- This test is one of the Done when items, and as written it doesn't prove what it claims.
- Fix: write the `Findings:` line and its `- warning ...` item explicitly, and add the negative case (same section, no `Finding:` line, not ready).

**3. `docs/flow.html` still says "Two reviewers ... then settles itself"** (A3)
- This misses the Done when line "any other skill or doc ... says one".
- It is a one-line fix, and the file is a doc the line covers, even though `Where` doesn't name it.

**4. Step 4 of the skill claims an independent check that no longer exists** (A6, B2, merged)
- At `skills/pr-review/SKILL.md:232`, "Judge it against what the reading was not given: the brief's decisions" was true with blind subagents. With one thread it is false.
- This is the instruction text the reviewer acts on. Telling it there is a cross-check that doesn't exist invites over-trusting its own list.
- Both reviewers caught it, and the fix is cheap and inside `Where`.
- Fix: say that the reading and the judgment are one thread, and point the judgment at re-checking each claim against the repo and the brief.

### Consider

**5. The `"archive"` mode key inside a title-prefix map** (A4)
- A's alternative is concrete: compute `ended` once and decide `("settle", "archive")` from `role_of(title)` and `slug_of`.
- That removes the dict key, the `shelve` copy-down to subagents, and the nested `break` loop.
- It is a real simplification. It also touches the same code as Act On 1, so it is cheapest done in that rewrite. It isn't blocking on its own.

**6. A merged PR's review threads are never archived if the last Review is `not run`** (A5)
- This is a real gap against "archives ... on the next pass".
- It is an edge case: a later scoped pass that didn't run.
- Fix: archive non-busy review threads of an ended slug regardless of verdict, or document that they are kept. Worth deciding while redoing the "ended" logic.

- **`docs/jbus.md:108` wording** (A8): a fair readability nit. That sentence will likely be rewritten anyway once Act On 1 and Consider 6 change the rule.
