First, I don't bolt on `cancelledAt?: Date`. That would add a second optional field to a bag that already allows `status: 'done'` with no `doneAt`. I follow "Make illegal states unrepresentable" (plus "Exhaustive matching is the compiler's job") and replace the type with a sum type:
`type Task = { status: 'open' } | { status: 'done'; doneAt: Date } | { status: 'cancelled'; cancelledAt: Date };`
Next I grep for every use site, `rg -n "doneAt|status ===|\.status" --type ts`, and rewrite each one as a `switch (task.status)` whose `default` arm ends in `const _exhaustive: never = task;`. That way the compiler flags every case I haven't handled.
Last, I update the parser at each boundary (DB row, JSON) so it builds these variants and doesn't cast with `as Task`. Then `tsc --noEmit` shows any spot I missed.
