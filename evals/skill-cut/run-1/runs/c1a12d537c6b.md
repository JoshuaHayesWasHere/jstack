### Intent
> The user wants threads to be easy to see per project, and wants to follow the work of scouts and crewmates. Each project's row and page gets a Threads band grouped by role. Live threads come first, with liveness and last write. Threads that ended today are dimmed and the rest are folded. The data comes from `pass.json` `projects[name].threads`. `#/<project>/thread/<role>/<slug>` opens a drawer showing what the thread works on: a task's step, or a scout's request. The server adds one read-only source, the scout requests under `scouts/`, and reads their `## Report` and `Status:` to say researching, reported or blocked. A pass that listed no threads shows as a blind spot, never as "none". The work is tested with small fixtures, and `make check` and `jgauge test-slot -- make check` pass.

### Reviewers
- Reviewer A: 8 findings
- Reviewer B: 7 findings
- Both reviewers answered the review skill's questions. They agreed on four findings: the duplicated row and role tables, the `health()` tag, the page with no band, and the out-of-Where `thread/` panel.

### Act On

**1. An ended scout with no Report still reads "researching"** (A1)
`request()` judges by the file alone, and `threadChip` puts `q.state` ahead of liveness. A scout that crashed or was settled early shows "researching 2h00" under an "ended" heading. The user asked to track scouts, and this is the one case where they need to step in, yet the page says the scout is still working. The fix is to say "researching" only while `t.out`, give "ended, no report" its own amber state, and add a fixture with an ended scout and no Report.

**2. `Status: not done` shows as a green "reported"** (A2, plus the case point from B6)
The scout template allows `done | not done | blocked`. The scout skill's settle check treats anything but `done` as unfinished. The view paints "not done" with the `ok` chip, so the page says "finished" while jbus says "unfinished". The parser also only matches lowercase `blocked`, so `Status: Blocked` reads as reported. The fix is to map `done` to reported, `blocked` (any case) to blocked, and anything else to a non-ok state. Add a test whose last Report is `not done`.

**3. The `scouts/` source always says "ok", and a permission error reads as "missing"** (B1)
`seen` never passes `read` or `path`, so a home with no `scouts/` directory, or one it cannot read, still shows `scouts/ ok`. That is the "none instead of blind spot" failure this view exists to avoid. `except OSError` also turns an unreadable request into "No request in the home", which is false. `at` is the directory's mtime, which does not move when a Report is appended to an existing file. That makes it a proxy, not the real value. The fix is to pass `read` and `path`, treat only `FileNotFoundError` as missing and other errors as unreadable, and add a test with no `scouts/` directory.

**4. A project's page draws no band when its pass listed zero threads** (A5, B2)
The first "Done when" line says the row **and the page** each have a band. The row draws a calm "0 out" band, but the page draws nothing, and the only justification is a comment. This misses a "Done when" line, and fixing it deletes a special case. Draw `band()` unconditionally and let its calm state handle zero.

**5. The thread drawer duplicates `threadRow`, and the role names live in two positional tables** (A3, B3)
`about(t)` is `threadRow(t)` copied with a different title cell. `ROLE` (page.html) and `ROLES` (threads panel) both describe roles, with different column orders. They already disagree on wording ("crews" vs "Crewmates"), and `band()` reads both by index. Both reviewers found this on their own, and it was introduced in this PR, inside "Where". The fix:
- Keep one row renderer, with a parameter for the title.
- Keep one ordered role list with named fields, and derive the filter and band order from it.

Whether `threadChip`/`LIVESAY` move out of page.html into the panel is the author's call. Both locations are inside "Where".

**6. `health()` carries a `"threads"` tag only so the row can filter it back out** (A4, B5)
This is a magic string that ties a shared helper to one caller through a prose comment. Renaming the string breaks the filter without any error. The fix is cheap: take the chip out of `health()`, and let `amber()` add the "no list of its threads" reason itself.

### Consider

**1. The new `panels/thread/` folder sits outside "Where", and `adds.band` is undocumented** (A8, B4)
The `thread/<role>/<slug>` route is required by a "Done when" line, and panel discovery probably needs the folder. The tradeoff is an empty stub module against registering the drawer from `threads/`. If the folder stays, the PR should say why. Documenting `adds.band` in `panels/__init__.py` is outside "Where" and is noted for later.

**2. `gates_inside=True` followed by `re.split` on `## `** (A6)
If `mirror.sections` without `gates_inside` already ends the body at the gate, the split and its docstring sentence can go. The call was copied from `jbus.threads._scouts` (B6), so check that it behaves as expected before deleting.

**3. Defaults on `_threads(home=None, day="")`** (A7)
If no test calls `_threads` without these arguments, make them required and drop the two guards. This is a small deletion.

**4. Private `_mtime` imported into the threads panel** (B7)
The other sources (`PASS_FILE`, `MERGE_LOG`) define their `Source` in state.py. Moving the scouts source there matches that pattern and fits naturally with the rework in Act On 3.

### Noted
- B6: A shared "last Report and its Status" helper in `jbus.threads`/`mirror` would remove the third copy of this parse rule. That code is outside "Where", so it is for later. The parts that are bugs in the changed lines (`not done`, case) are folded into Act On 2.

### Dismissed
- None. Every finding names a concrete path or a concrete maintenance cost. Neither reviewer padded with style preferences.

### Agreement Map
The reviewers agreed on all the structural findings: the duplicated renderer and role tables, the `health()` tag, the missing page band, and the out-of-Where panel. The consensus makes those reliable. They diverged on correctness, and each found a different scout-status hole:
- A found the cases where the view's state contradicts liveness or the scout skill (an ended scout with no Report, `not done`).
- B found the source's own blind spots (always ok, OSError as missing, the mtime proxy).

The common thread is that the scout status reader, the one new server-side source in this PR, is the weakest part. It hides exactly the cases the user wanted to see, and its tests cover only the happy fixtures. The UI structure is sound but was copied rather than shared. That costs little to fix now, while both copies are new.
