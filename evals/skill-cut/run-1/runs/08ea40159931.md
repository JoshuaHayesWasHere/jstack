### Intent
> Every gate is act-unless-stopped. The thread acts on its recommended default at once, the user sees it as already acted on, and a differing answer is carried back. A pass closes a plain open question by silence after 2 hours. A gate whose default deletes data, rewrites history, spends money, touches prod or real users, changes access or secrets, or publishes must carry `Holds: <case>` and a `Fail-safe:` line. It does not act. It waits for the user with the dry-run, plan or bundle attached, and silence never closes it. `jbus gate` refuses a gate with no default, a default that isn't the recommended option, a `Holds:` with no fail-safe, or an unknown case. The default change and the fail-safe ship together, with fake-clock tests, and `make check` exits 0.

### Act On

**1. A held gate answered with its default never releases the thread** (B1)
A `Holds:` thread does not act. The user then answers `--default` or ticks the default on the page. `tell` and `View._carry` skip every `keeps` answer, because before this change a default had always already been carried out. The thread is never told to go ahead, so a held action can only proceed when the user picks something *other* than the recommendation.
- This is a concrete path through the core new feature, and it breaks "waits for the user's answer".
- Fix:
  - Carry a `keeps` answer when `holds` is set, as a "go ahead with the default" message.
  - Fix the "nothing is sent" wording in `_answer`, on the page and at docs/jbus.md:132.
  - Add a test: a `Holds:` gate answered `--default` sends exactly one message.

**2. Re-piping a silence-closed question discards a new `Holds:` and tells the thread "already answered"** (A1)
The silence close runs, then the thread re-pipes the same slug with `Holds: deletes data`. `ask` sees an answer and keeps the old record. The thread is told "already answered … Go by it" and proceeds with no yes from anyone. This is exactly the failure the fail-safe exists to prevent.
- The faulty line is unchanged, but this PR made it reachable, so it is in scope.
- Fix:
  - Treat a record closed only by silence as open in `ask` (use `_open`).
  - Clear the silence answer when the re-pipe adds `holds`.
  - Add a fake-clock test, and drop the assertion at :768 that blesses the current behavior.

**3. Silence closes the link-conflict questions addressed to the home, parking the stack** (A2)
These questions ask the home, not the user. The home's jq selects `.answer == null`. After 2 hours `_quiet` sets an answer, the rebase line is never sent, and the conflicted link sits. That is the opposite of "no question parks work".
- Fix: exempt them in `_quiet`, which is in `questions.py`, in scope.

**4. "Shown as already acted on" and "fail-safe attached" reach nothing the user reads** (A4, B2)
`acted`, `holds` and `fail_safe` only land in `waiting-on-user.json`. The item `line`, the home's jq/printf block and the page all drop them. The only test reads the raw JSON, which is a proxy for what is shown. Two "Done when" lines are unmet.
- Fix inside "Where":
  - Put the state into `line`.
  - Add `.holds`/`.fail_safe`/`.acted` to the home skill's reader and its "Show the open ones" output.
- The page panel and `waiting._blocks` are outside "Where". Note them for later.

### Consider

- **Redundant `(default)`/`(recommended)` marks** (A5, B5). Under the stated rule the two fields never differ. Treating `(default)` as the pick and refusing `(recommended)` anywhere else still meets the "Done when" line. It also removes a refusal branch, avoids rejecting old-style gates, and undoes fixture churn. The tradeoff: the explicit double mark is what the brief's Decisions line literally reads, and changing it now widens the diff. This is worth a quick call, not a blocker.
- **Stale "only their name closes a question"** (A6), skills/home/SKILL.md:822. A one-line fix in a "Where" file, and it now contradicts the rule the same section states. Do it while in the file.
- **Expert findings now recommend "leave it" and vanish after 2h** (B3). This is a real semantic regression: advice to change something now dismisses itself. But the fix is a design decision about expert gates in skills/expert/SKILL.md, which is outside "Where". Flag it to the user as a follow-up. Don't paper over it further in the test.
- **Silence-closed questions are only answerable from the CLI** (B4). The docs promise a later answer works, and it does via `jbus answer`, but the page no longer lists the question. The cheap fix in scope is to say "CLI only" in docs/jbus.md. Keeping them on the page is follow-up work.
- **Words panel shows a silence close as "Your answer"** (A3). The record is correct (`closed_by=SILENCE`), so the brief's basis rule holds. The misrepresentation is in the panel files, outside "Where". It matters for trust in the user's own record, so queue it for a follow-up.

### Agreement Map
The reviewers converged on the observable gaps: the new fields aren't displayed, and the marks are redundant. That consensus makes item 4 solid.

Each critical came from one reviewer, but both are concrete execution paths, not hypotheticals. They share one root cause: the PR added two new states, *closed by silence* and *holds*, without auditing the existing consumers that assume "answered means settled" (`ask`, the home's jq) and "default means already done" (`tell`, `_carry`, the docs). A2 is the same pattern. Before this lands, walk every reader of `answer`/`keeps` once, rather than patching only the three sites found here.
