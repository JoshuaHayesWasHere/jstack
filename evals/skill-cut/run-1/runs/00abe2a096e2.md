### Intent
> Task: the audit's P6. Once a crewmate has written `fixed and green`, a third rebase forced by main is not made. The crewmate writes one stop line in its Result, pipes a gate, and jbus surfaces the pull request as waiting. The count is kept where jbus or jmerge can read it, and a test drives three rebases and finds the stop on the third. `make check` and `jgauge test-slot -- make check` pass. Where: `skills/crew/SKILL.md` ("A conflict"), `src/jmerge/` or `src/jbus/`, the tests. How a rebase is pushed stays as it is.

### Act On
1. **The held pull request shows as "Rebase, its crewmate", not "Needs you"** (A1, B1). Both reviewers raised this independently and traced the same path: `merge.step` → `work.py:287` → the board. The open gate hides the problem only while the gate stays open. Once the gate is answered with the default, or never parked, the row says the crewmate owns it, but the crewmate is not allowed to act. The skill text at SKILL.md:118 promises the opposite. The fix is one rule in `src/jbus/merge.py:97`, moving `held a third rebase` to the `hold` step, plus the test table at `tests/test_jbus_merge.py:288`. Both files are within Where.
2. **The count reads the whole brief, not the last Result** (B2). This breaks the skill's own rule at SKILL.md:159, "every block reads the last result". The failure path is concrete: a follow-up round starts with `Rebased after fixed:` lines left over from the earlier round, so its first conflict is held at once. The fix is to reset the counters at the last `## Result` heading in the awk at SKILL.md:396-399.
3. **Running the block again on a held head tells the crew to park a second gate** (A3). The task asked about run-twice safety, and this fails it. `mainmoved.py` wakes red pull requests on every main commit, and a held pull request is likely red, so each wake prints `hold:` and the prose then asks for another gate. The fix is to print a different word when the line already exists, and park a gate only on the first `hold:`. When writing this fix, follow the "last hold-or-lift line" rule that `rebase_held` uses (see B5 under Noted). That keeps the block's dedupe and jmerge in agreement.
4. **The tests skip the conflict path and jmerge's `waits()`** (B4, merged with A5). The Done-when test does exist and executes: it drives three rebases and finds the stop on the third. But every rebase in it is clean. This section of the skill is "A conflict", and the `counted` call on a rebase that stops (SKILL.md:443) never runs. The ordering change in `cli.py:703` is also unexercised: `rebase_held` before `short_of`, and the early return. Deleting either one would leave the suite green. The fix is to add one run where main touches the branch's own file, and one assertion through `waits()` that the held head yields `REBASE_HELD`.

### Consider
- **The cap starts at `Fixed:`, not at "fixed and green"** (A2, B3). The consensus is real, and the gap with the Done-when wording is real: `Fixed: none needed` and `Fixed: <commit>` are both written before any check is green. But the PR already gives its reason: `fixed and green` is only sent to the home, never written where a block can read it. Counting from true green would need a new marker that someone writes on the transition. That is more than an S task, and it creates new shared state. The cost of keeping the proxy is mild: a red pull request can use up its two allowed rebases early and then be held, which fails safe toward asking the user. I recommend keeping the proxy and stating the deviation from the Done-when line plainly in the PR description and in the SKILL prose. Add the green marker only if the home wants the literal wording.
- **The hold is recorded at the local HEAD, while jmerge compares GitHub's head** (A4). The path is real but narrow: the push is refused after the second rebase, and then main moves again. When it happens, jmerge shows a different wait reason and not the hold. The gate still surfaces, so the user is not left blind. The fix costs one word, since the block already has `pushed` from `gh pr view`, so it is worth doing alongside item 3.

### Noted

- **A6**: the test helper's `home` argument also switches the slug to `"alpha"`. This is valid test hygiene, but it affects no current caller. Tidy it if you are already in that function for item 4.
