### Intent
> The user found the jbus view's UI/UX subpar: no header, no sidebar, no navigation. This PR adds a header (name, location, last-read time) and a sidebar ("All" first, then each project with its waits count and a health dot; chips under 900 px). Room, jbus and Runners are drawn once as the machine's. The Bus card no longer wraps one letter per line, and there is no sideways scroll at 1440, 900 or 390 px. Empty lanes are folded. All of this stays inside the one vanilla page and its panels, under the user's word caps of 250 for the overview and 150 for a project.

### Reviewers
- Reviewer A: 8 findings
- Reviewer B: 9 findings
- They agreed on six issues: word caps, duplicated health rules, the file size, the machine row on the not-found page, the sticky offset, and the theme control. Both answered the review skill's questions.

### Act On

**1. The word caps were loosened by moving content out of what they measure, and `SHELL = 30` only fits three projects** (A4, B1, B2)
- `words` used to count `document.body`. It now counts only `<main>`.
- The machine row, which used to count toward the 250, now counts toward neither cap.
- The first screen can carry about 280 and 180 words while the tests still pass. That is a proxy check standing in for the user's decision.
- The fixed `SHELL = 30` contradicts the new docstring ("grows by one name and one count for each project"). A fifth project fails a correct page.
- Both reviewers found this independently, and it quietly changes a decision the user made.
- **Remedy:** hold the whole first screen (header, sidebar and main) to `WORDS`/`EVERY`. If the content doesn't fit, trim it. If the author believes the cap was meant for main content only, that question belongs to the user: take the default (count everything) and file it with `jbus gate`.

**2. Health is judged by two rule sets that already disagree** (A2, B5)
- `troubles` (line 670) ignores `h.blind`, so a project with blind spots gets an amber row chip but a green sidebar dot.
- `troubles` also prints "0 failed wakes, last error: X" when only `last_error` is set. The row chip at line 720 guards against that case.
- This is a concrete wrong output today, and the two copies will drift further.
- **Remedy:** one helper per health fact, returning state and tip, read by both the row chips and the dot.

**3. The header's "read" time shows the current time while the server is unreachable** (A3)
- After `MISS` failed polls, `lost()` sets `NOW = Date.now()` and re-renders.
- The header then says "read <now>", advancing on every failure. This is the exact moment the "time of the last read" line from Done when matters.
- **Remedy:** store the time of the last successful answer in `took`/`tookStack` and show that.

**4. The jbus item can show "passing" when the stack read has failed** (B3)
- On a project page, `unwell` comes from `STACK.machine.unwell`.
- `STACK` refreshes only every fourth poll, and its failure handler is silent. When it is null, `unwell` becomes `[]` and the item is green.
- A false green is the worst failure mode for a health view.
- **Remedy:** derive it from the project's own `S.sources`, or at minimum render "unknown" when `STACK` is absent. A server-side `machine` flag would be outside Where, so it is noted for later.

**5. A link to a nonexistent project leaves the sidebar empty for up to 15 s** (A1)
- If the 404 arrives before `/stack.json` (a likely order), the `if (S) render()` guard skips the only redraw.
- The execution path is concrete and the fix is one line.
- **Remedy:** drop the `S` guard; `put` already skips unchanged parts. Add a test that loads `#/nope` and checks the sidebar items.

### Consider

**Split the shell code out of page.html, which grows from 979 to 1067 lines** (A5, B4)
- The panels mechanism already inlines per-part scripts server-side, so a `shell` script would keep "one served file" without a build step.
- Tradeoff: the user asked for "one vanilla file", and the split may need an `__init__.py` change, which is outside Where.
- Worth a sentence in the PR either way. Otherwise note the split for later.

**Draw the machine row on the not-found page and on the first load** (A7, B6)
- `machineOf` returns null whenever `PROJECT && !S`, even though `STACK.machine` is available.
- This contradicts the test's own "drawn once, on every view". It is cheap to fix but low impact.

**Tie the sidebar's sticky offset to the header's real height** (A6, B8)
- `top: 50px` breaks if the wrapping header grows past 50 px at 900–1100 px wide.
- This is plausible with long crumbs. A shared CSS variable is cheap.

**Justify, revert or test the theme control redesign** (A8, B9)
- The control changed from three buttons to one cycling button, and the change doesn't trace to the task.
- Either explain it in the PR (if header space forced it) and add a click test for auto → light → dark → auto, or keep the three-button group.

**Update the stale poll comment** (B7)
- "One request a poll" at line 994 is now false because of this change. It is a one-line fix in the same change.
