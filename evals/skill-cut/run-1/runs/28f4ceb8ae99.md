### Intent
> Every gate becomes act-unless-stopped: the thread acts on its recommended default at once, the user sees it as already acted on, and a differing answer is still carried back. A plain question closes by silence after 2 hours, with a basis saying it was not the user's word. Gates whose default deletes data, rewrites history, spends money, touches prod or real users, changes access or secrets, or publishes must carry `Holds:` and `Fail-safe:` lines. They never act and never close by silence. They wait for the user with the dry-run, plan or bundle attached. The default change and the fail-safe rules ship together in this PR, with fake-clock tests and `make check` passing.

### Act On

**1. A held gate answered `--default` never reaches its thread** (B1)
- `tell` skips any answer with `keeps` set. That rested on the old invariant that the default was already carried out, and a `Holds:` gate breaks it.
- So when the user approves the recommended default on a held gate, nothing happens, and the action stays parked forever. Only a *differing* answer moves it.
- This is a concrete path through `answer()` → `keeps=True` → `continue`. It breaks "waits for the user's answer", and docs/jbus.md:132 now states something false.
- The fix lives in `questions.py` and `docs/jbus.md`, both inside Where. Needs a test: a `Holds:` gate answered `--default` sends exactly one message.

**2. Re-piping a silence-closed question with `Holds:` returns "already answered"** (A1)
- `ask` treats a `closed_by: silence` answer as settled and drops the new `holds`/`fail_safe` lines.
- Threads do re-pipe gates at a later head, and the skills tell them "Go by it". So a destructive action can proceed with no human yes, which is exactly what the fail-safe half exists to prevent.
- `_open()` already exists and is just not used in `ask`.
- Needs the suggested fake-clock test: close at 2h, re-pipe with `Holds:`, expect the question open again.

**3. Silence closes the link-conflict questions that ask the home** (A2)
- These questions are addressed to the home, not the user.
- After 2h, `silent` sets `answer`, so the question falls out of the home's `select(.answer == null)` and the rebase line is never sent. The stack parks, which is the opposite of the stated goal.
- Exempt them in `_quiet` (inside Where).

**4. "Shown as already acted on" and "with the fail-safe attached" are not met** (A4, B2, merged)
- Both reviewers found this independently.
- `acted`, `holds` and `fail_safe` reach only `waiting-on-user.json`. Nothing the user reads carries them: the item `line`, the home's jq/printf, `waiting._blocks`, the page panel.
- The only test reads the JSON file, a proxy for what the user sees.
- The `line` and the home skill's jq are inside Where and should change in this PR. The view panel and `waiting._blocks` can be noted for later, but without the first two, two Done-when lines fail.

**5. The home skill still says "only their name closes a question"** (A6)
- The section the task requires to state the new rule now contradicts it at skills/home/SKILL.md:822.
- The skill is behavior-driving prose for the home, so a contradiction there is not cosmetic.
- It is inside Where and a one-line fix.

### Consider

**Redundant `(default)` + `(recommended)` marks** (A5, B5, merged)
- Both reviewers raised it.
- The rule makes the two marks always equal, yet the PR adds two refusal branches, touches about 12 fixtures, and now refuses old-style `(default)` gates from threads on older skills.
- Treating `(default)` as the pick and refusing `(recommended)` elsewhere meets the Done-when line with less code.
- Tradeoff: worth doing while the format is fresh, but the current version is correct, just ceremonious.

**Expert findings now recommend against themselves and vanish at 2h** (B3)
- The test fixture was edited to mark "leave it" as recommended, so the suite passes while the expert skill's semantics invert.
- This is a real conflict with what the user wanted: no parked work, not discarded advice.
- skills/expert/SKILL.md is outside Where, so this needs the user's call on how expert findings should behave. Flag it rather than paper over it.

**A silence-closed question cannot be answered from the page** (B4)
- The Done-when line ("a later differing answer is still taken") is met via the CLI.
- But the page drops the question, and the docs imply it stays answerable anywhere.
- The cheap move inside Where is to make docs/jbus.md say the CLI takes the later answer. A view state for "closed by silence" is for later.

**The "Your words" panel renders a silence close as the user's own answer** (A3)
- The basis must say it is not the user's word. `basis()` honors that, but the user's own record of what they said does not.
- The panel is outside Where, so note it for a follow-up. It is a misattribution, though, not a nit.

### Noted
