### Intent
> Every gate in every home must carry a default, and that default must be the recommended option. The thread acts on the default at once (act-unless-stopped). The question is shown to the user as already acted on, and a pass closes it by silence after 2 hours, though a later differing answer is still taken. The exceptions are gates whose default deletes data, rewrites history, spends money, touches prod or real users, changes access or secrets, or publishes. Each of those must carry `Holds: <case>` and a `Fail-safe:` line. It does not act, it waits for the user with the dry-run, plan or bundle attached, and silence never closes it. `jbus gate` enforces all of this. The skills, `templates/gates.md` and `docs/jbus.md` state the rule. Fake-clock tests prove it, and the default change ships together with the fail-safe in this one PR.

### Act On

1. **A held gate answered with its default never releases its thread** (B1). A `Holds:` gate doesn't act; it waits. But `answer --default` stores `keeps=True`, and `tell` and the page's carry path skip every `keeps` answer, so the thread is never told to go ahead. The most common answer to a held gate is "yes, do the recommended thing", and that answer now does nothing. This breaks the Done when line "waits for the user's answer", and docs/jbus.md:132 now states something false for held gates.
   - Fix: carry a `keeps` answer when `holds` is set, as a "go ahead with the default" message.
   - Fix the doc sentence.
   - Test: a `Holds:` gate answered `--default` sends one message.

2. **A re-pipe after a silence close can bypass the fail-safe** (A1). `ask` treats any answered record as settled, and that now includes `closed_by: silence`. A thread that re-pipes the same slug and words with a newly added `Holds:` line is told "already answered … Go by it", and its `Holds:`/`Fail-safe:` lines are dropped. The user asked for exactly one guarantee: irreversible actions get a hold. This path lets one through with nobody's yes.
   - Fix: in `ask`, treat a silence-closed record as open (`_open` already exists), and clear the silence answer when `holds` arrives.
   - Test: add the fake-clock test A1 describes.

3. **Silence closes home-directed link-conflict questions, which parks the stack** (A2). `_quiet` closes every open record that has no `holds`, including the "has a conflict, and it is a link of a stack" questions, which the home's own table says ask the home. The home selects them with `.answer == null`. After 2 hours they drop out of `$LINKS`, no rebase line is sent, and the link sits. That is the parking the user asked to end.
   - Fix: exempt them in `_quiet`, or adjust the home's filter. Both are in the Where line.

4. **"Shown as already acted on" and "the fail-safe attached" are not shown anywhere** (A4, B2). `acted`, `holds` and `fail_safe` reach only `waiting-on-user.json`. The item's `line` is unchanged, the home's jq block (in the Where line) drops the fields, and `waiting._blocks` and the page drop them too. Two Done when lines are unmet, and the only test reads the JSON file, which is a proxy for what the user sees.
   - Fix in this PR: put the state in `line`, and add `.holds, .fail_safe` to the home's jq and its printf.
   - Note for later: the page's panel and `_blocks` are outside the Where line.

5. **The home skill contradicts itself** (A6). The edited "Gates" paragraph allows silence to close a question, but :822 still says "only their name closes a question". The home is an agent reading this text, so a contradiction in its instructions is a behavior bug, not a style nit. It is a one-line fix in a file in the Where line.

### Consider

- **Expert findings now dismiss themselves** (B3). To satisfy the new mark rule, the fixture makes the expert "recommend" leaving things alone. After 2 hours, silence then closes the finding, along with a false claim that the expert recommended no change. The test was edited to pass, but the skill was not changed. This needs a decision on how expert gates fit the rule: held, a separate kind, or a recommended-change default. skills/expert/SKILL.md is outside the Where line. At minimum, the PR description should flag it, and the test should not imply the behavior is intended.
- **The words panel attributes a silence close to the user** (A3). It renders `closed_by == SILENCE` as "Your answer 'default'". The intent specifically asks that a silence close says it is not the user's word. The fix is in the panel files, which are outside the Where line. It is small and worth extending scope for, or else following up on promptly.
- **The two marks are now redundant** (A5, B5). `recommended` always equals `default`. The task's line, "refuses one whose recommended option is not the default", is also met by treating `(default)` as the pick and refusing `(recommended)` on any other option. That would remove a refusal branch, the fixture churn, and the hard break for threads still piping `(default)` alone. It is a real simplification, but the current form does meet the letter of the task, so it is not a blocker.

### Noted
- B4: after a silence close, the page no longer lists the question, so a later answer is CLI-only. The Done when line ("a later differing answer is still taken") is met through `jbus answer`. The cheap fix is to say in docs/jbus.md that the CLI is the path.
- B6: `_held` re-implements `mirror.field`'s line scanning. There is some drift risk, but the remedy is in mirror.py, outside the Where line.

### Dismissed
- None. Every finding traces to a concrete path or a Done when line.

### Agreement Map
- Both reviewers flagged that the new states never reach anything the user reads (A4/B2). Both also flagged the redundant marks (A5/B5).
- After that they split cleanly:
  - A followed the **silence-close** state into its consumers: `ask` (A1), the home's link filter (A2), the words panel (A3) and the skill text (A6).
  - B followed the **held** state and other consumers: `tell`/`keeps` (B1), the expert gates (B3) and the page's list (B4).
- Taken together, they show one underlying gap. The PR added two new meanings to a record (silence-closed, held) but kept `answer is None` / `keeps` as the switches every consumer branches on. Each Act On item is a consumer that still reads the old two-state model.
- An explicit state on the record (open / held / closed-by-silence / answered by the user / answered by the home) would fix A1, A2 and B1 together, and would make the display work in A4/B2 straightforward. That is the model-the-domain move worth making before patching each consumer separately.
