### Intent
> Sections 1, 2, 5 and 6 of the /deeper design, based on Felix Rieseberg's "four types of ambition" (Depth). The work has four parts. First, a manual skill (`skills/deeper/`) that answers the four questions and gives a rewritten prompt. A home runs it without blocking: it takes the rewrite as the default and pipes a `jbus gate`. Second, a 25th principle, `depth-over-breadth`, which `jdrift` knows as a jstack source and which every principle count reflects. Third, a credit in `THIRD_PARTY.md`. Fourth, a blind, rerunnable eval in `evals/deeper/` over about 10 past briefs, scored on raw sources, instruments named, and proof outside the agent, plus outcomes for the briefs that merged. Its committed Result says honestly whether /deeper won. `make check` and `jgauge test-slot -- make check` pass.

### Reviewers
- Reviewer A: 5 findings
- Reviewer B: 8 findings
- Both reviewers asked the review skill's questions. They agreed independently on two issues: the uncontrolled `raw` measure, and `write()` wiping the committed runs before any model call. Neither found a gap in the principle, the jdrift source map, the counts or the credit. Nearly all the substance is in `evals/deeper/`.

### Act On

1. **The "outside" measure is a formatting proxy** (A1). Any backtick span on a proof line counts as an outside judge. A rescored the committed run-2 briefs without that branch. The plain-to-deeper rise disappears (0.34 vs 0.33). Deeper briefs use more backticks because the skill tells them to name things by path. The fix: count a backtick span only when it holds a command that is run, or drop the branch. Then rescore the committed briefs, which needs no new model calls. This is fixing a broken measure, not tuning the eval toward a result: A showed the measure doesn't measure what it claims.

2. **The "won" verdict rests on one run of a noisy measure** (B1, reinforced by A1). Between run 1 and run 2, the skill changed only the output format of its rewrite. Outside flipped sign on eight of the ten cases. The README's own rule says only what both runs agree on is a finding, and it still reports "won". The task was explicit that a loss is a finding, not something to rerun around. Combined with A1, the honest Result is: won on raw and instruments in both runs; proof outside not shown; the no-loss condition passed in one run of two. The Result line of a PR is what the user acts on, so it must be right.

3. **The raw-sources claim has no control for copying the skill's list** (A2, B2). This is a consensus finding. Seven of the twelve `RAW` kinds match the examples in question 2 of `SKILL.md` almost word for word. The README says the gain holds "not only by copying the skill's own examples", but only instruments have a `beyond` check. The fix: add a raw `beyond` that excludes the skill's kinds, as `SKILL_EXAMPLES` does for instruments, and rescore. If that is not done, narrow the README sentence to instruments. This decides whether the headline raw gap (0.65 to 3.90) means anything.

4. **`write()` deletes the committed briefs before the first `claude` call** (A3, B3). This is a consensus finding. The one documented command runs `rmtree` on `runs/` and `deeper/` first. Any failed call, any timeout, or a machine without `claude` then leaves a partial `runs/` and a stale `key.json`, and `report` refuses to run. The intent requires the eval to be "rerunnable by one command", and this command destroys the results the PR commits. The fix: write into a temporary directory and swap it in after the key is written. At minimum, check `shutil.which("claude")` before deleting anything.

5. **Redaction fails silently when `XDG_CONFIG_HOME` is set** (B4). There is one reviewer, but this is a privacy finding on a repo meant to be public, so it gets extra weight. `_private` hardcodes `~/.config` while `jleak`'s CLI honours XDG, and it swallows `jleak.Missing` by returning `()`. The result is past task briefs committed with no redaction and no warning. The fix: resolve the path the way `jleak.cli` does, and fail when the patterns are missing.

### Consider

- **`SELF` treats any mention of "review" as self-assessment** (B5). This is real. It skews `rs-parallel-reviews`, whose subject is reviews. It belongs to the same family as A1, so it is cheapest to fix in the same pass while the outside measure is open. It is lower impact because it hits one case.
- **The "Not held" column counts a phrase across the whole brief** (A4). It misses "did not hold", and it counts the Review section and repeats. The README's "Seven of the ten" outcome claim is read off it. The fix (restrict the search to Result and match the tense variants) is cheap, and the outcome half is a "Done when" line. The tradeoff is small either way.
- **The principle card's leans list `perf-issue` and `investigation`, and neither references the principle** (B6). Other cards' leans match real links. Trim the list to `deeper` now. Linking from the playbooks is outside **Where**, so it is for later.
- **The gate's `Context:` placeholder invites four lines, and `mirror.field` keeps only the first** (B7). This is a concrete loss path for the home that follows the wording, and it is a one-line wording fix in `SKILL.md`.

### Noted
- `eval.py` leaves `evals/deeper` and `src` on `sys.path` and registers a top-level `score` module for the rest of the test session (A5). It is valid hygiene, but no collision has been shown. Fix it opportunistically.

### Dismissed
- **`Pinned.own` has an unused default** (B8). This is a style nit with no behavioural effect.

### Agreement Map
The reviewers converged on the eval and nowhere else. Both independently found the uncontrolled `raw` measure and the destructive `write()`. Those two consensus findings are the strongest signals in the review. Their differences complement each other. A tested the measures empirically: the backtick rescore is the single most consequential finding, because it erases the outside gain. B looked at the eval's history and context: the format-only rerun, XDG redaction, and the gate's wiring. Put together, A1 and B1 tell one story: of the three scored dimensions, "proof outside" is both mismeasured and unstable. The PR should report that as the finding the task asked for, not as a win. The skill, the principle, the jdrift change and the credit drew only nits. That part of the PR is in good shape.
