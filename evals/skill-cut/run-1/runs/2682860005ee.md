### Intent
> Topic 10 of the user's re-homing request (2026-10-15 22:31 ET): "A way to undo a bad merge into standing.md." Each edit to a `$H/standing.md` should become a commit of its own in `~/.local/state/home`, and be pushed. To get there, the home skill (including scoped homes) and the handoff skill run `jbus snapshot --why <text>` right after the edit, and the twice-daily timer stays. `--why` adds its text after the time in the commit message. `docs/state.md` explains how to find a bad edit with `log -p`, restore it from `<commit>^`, and snapshot again. Tests run this in a temporary tree with a bare remote, and `make check` passes.

### Act On

1. **Snapshots have no lock against each other or the timer** (A1, B1)
   - Before this change, `take` ran only from the timer. Now any home can run it at any time on the same index.
   - A home's snapshot that overlaps the 08:30 or 17:30 run hits `.git/index.lock`. If the timer is the run that loses, `OnFailure` fires `--alarm` to the desk and every project for a failure that isn't real.
   - A1's interleaving is also concrete: A's `git reset -q` lands between B's `add` and B's `diff --cached`. B then prints "nothing changed" and silently loses the very guarantee the task asks for.
   - Fix: an exclusive `flock` on a file in `.git`, held across add, commit and push, so concurrent runs wait instead of failing. It is a few lines, entirely inside `src/jbus/snapshot.py`.

2. **The documented restore truncates the live `standing.md` before `git show` can fail** (A2, B2)
   - `docs/state.md:108` uses `show <commit>^:<path> > <path>`. A mistyped hash, the commit that created the file, or the root commit leaves the rules file empty. The doc's next step then has the user snapshot that empty file.
   - This is the recovery procedure, so it must not be the thing that destroys data.
   - Fix: document `git -C ~/.local/state/home restore --source=<commit>^ -- <repo>/standing.md`. It writes nothing on failure and reports the missing-path case. Alternatively, write to a `.tmp` file and `mv` it only on success.
   - Say what to do when the bad edit created the file.
   - Add a test that undoes the creating commit. The current test at `tests/test_jbus_snapshot.py:309` only covers a parent that already has the file.

3. **Handoff gains a new duty to write standing rules** (A5, B3)
   - `skills/handoff/SKILL.md:92` adds "One it did not write yet goes there now". The task asked only for a snapshot after an edit.
   - The new line changes agent behaviour, so it is not cosmetic. It also contradicts the sentence just before it ("the home wrote it to `standing.md` when it heard it").
   - Fix: cut the sentence. Keep a generic "after any edit to `$H/standing.md`, run `jbus snapshot --why …`". This also removes the hardcoded `added` that A4 noticed drifting.

### Consider

- **The `--why` commit still sweeps in the whole dirty tree** (A3, B1 part)
  - `git add -A` means the commit labelled "jstack standing rule 28 added" also carries briefs, `merge.log`, handoffs and other repos' files. The test passes only because the fixture is otherwise clean.
  - The undo itself still works, because `log -p` and `show <commit>^:<path>` are path-limited. What suffers is the unscoped history the user reads.
  - Tradeoff: scoping the commit to the named path (`git commit -- <path>` when `--why` is given) makes the message true and fits the "commit of its own" intent. The cost is a path argument, a decision about how the gitleaks scan applies to a partial commit, and a check that the remainder is still picked up by the timer.
  - It is reasonable to do this now since it's all in `snapshot.py`. It is equally reasonable to leave it until the lock lands and see how often the tree is dirty in practice.

### Noted

- **The rule is written in prose in three skills** (A4). The task explicitly asked for these three instructions. A `jbus standing add` verb is the durable fix but sits outside the Where line, so it is for later. The drift in wording is resolved by Act On #3.
- **`docs/jbus.md` is edited, outside the Where line** (A6, B4). The content is accurate, and without it the new flag would be undocumented on the commands page. The brief's Where line missed this file. Note it in the PR rather than revert it.
- **`with_origin` duplicates inline setup** (A7). Migrating the two inline copies is cheap and in the same file, but it is test hygiene, not a blocker.
- **Test name understates the test** (B5). `test_a_snapshot_with_no_why_says_only_the_time` also checks the `why=` path, and its no-why half duplicates line 77. Renaming and trimming it is a valid nit with low impact.
