### Intent
> Add a `Proves it:` line to `templates/brief.md`, right after `Done when:`. The brief parser and jbus's pre-launch checks (beside `dispatch.designed`) accept it only when it names something outside the agent: a test, metric, dataset, external judge or the user. They refuse an empty line, the template's own text, and any proof by the crew, crewmate, reviewer, agent, "self", "the model" or a review alone, with a one-line reason. Briefs already queued without the line are handled so that no approved row is stranded. The change includes tests for each accepted and refused kind, plus doc and home-skill updates. `make check` and `jgauge test-slot -- make check` pass.

### Reviewers
- Reviewer A: 7 findings
- Reviewer B: 6 findings
- Both independently found the same central flaw: the loose "outside" patterns are checked before the self patterns. They also agreed on the duplicated head loop, the unused `Brief.proof`, the `<` template heuristic, and the two Done-when items that only the Result can show. The review skill's questions were asked.

### Act On

**1. Self-referential proofs pass because the loose `_OUTSIDE` patterns win first** (A1, B1, B2 merged)
Raised by A as a warning and by B as critical, with B adding the missing tests. `proof()` returns success on the first `_OUTSIDE` hit and never consults `_SELF`. Each of these lines passes as a test, metric, judge or the user:
- "make sure the reviewer is happy"
- "self-test"
- ``the `reviewer` says so``
- "the reviewer is 100% sure"
- "the model is the judge"
- "the reviewer gives his word"

All of them are things the Done-when line says must be refused. This is the only gate before `_ready` launches, so the feature's purpose is defeated by ordinary phrasing. The suite pins only the happy side of the precedence rule.

Fix:
- Tighten the patterns. A test should need a path (`tests/…`, `test_\w+`) or a backticked known tool or command. `make` should need a real target. `%` should need a metric word near it. Drop the bare "his word/pick/eye" pattern.
- Add a `REFUSED` case for each example above, run through `parse.proof`, so the Done-when tests cover each refused kind.

**2. Grandfathering keys on the line being absent, so omitting it bypasses the gate forever** (A2)
`proven()` returns `""` whenever `proves_it` is None. Any brief written after this change can skip the requirement simply by leaving the line out. The Done-when asked for a decision about *existing queued* briefs, not a permanent exemption. Today the rule survives only through home-skill prose.

The fix stays inside `dispatch.py`. Exempt only rows approved before a cut-off, or rows whose `brief_sha` was already in the queue. Gate a missing line on everything later. This keeps the "don't strand an approved row" property and closes the hole.

### Consider

**3. Two failing checks cost the user two gate rounds** (A3)
A brief that fails both the design check and the proof check surfaces only the design problem first. That means two edits and two re-approvals, and every approval costs the user. Collecting faults from both checks into one gate is a small change in `_ready`.

The tradeoff: it touches the existing `designed` flow's control path. That is in Where, and the line's rules don't change.

**4. Duplicate head-line loop, and a check split across two layers** (A4, B3 merged)
`proves_it` copies `designed`'s loop line for line, and `proven` is a pass-through wrapper. Each future check would add another loop and another branch in `_ready`.

Within this PR:
- Iterate a `(kind, check)` tuple in `_ready`. This pairs naturally with item 3.
- Let `proves_it` return an empty-`why` `Proof` so `proven` can go.

Moving `designed` onto a shared `head_line` helper in `jbriefs.parse` is for later, since that rule is do-not-touch.

**5. Template-text detection by a leading `<`** (A6, B5 merged)
The check fails in both directions:
- **False accept:** the guide text with its brackets stripped passes as "a test", because it contains the word "test".
- **False refuse:** a legitimate metric like `<= 50 ms p95 from jgauge` is rejected.

The Done-when explicitly names "the template's own text", and the template is a single known line. Comparing against it, or matching `^<[^>]*>$`, is exact and cheap.

### Noted
- **`Brief.proof` / `Proof.said` have no consumer outside the tests** (A5, B4). This is new surface with no reader. Drop the property if the code is touched for item 4; it is otherwise harmless.
- **The Result items can't be seen in the diff** (A7, B6). These are the grandfather-or-refuse statement and the real queued brief run through the launch check with the line printed. Verify them in the brief's Result, not the code.

### Dismissed
None. Every finding had a concrete basis. The reviewers' nits stayed rated as nits rather than being inflated.

### Agreement Map
The reviewers converged strongly. Both independently traced the same precedence bug in `proof()` with overlapping concrete bypass phrases. Together with B's test-gap finding, this is the clearest signal in the review: the core gate is porous. Both also flagged the same structural duplication, the same dead property, and the same fragile `<` heuristic, from opposite sides (A on false accepts, B on false refusals). The divergence is in scope. Only A caught the permanent grandfathering hole and the double-gate cost, both runtime consequences in `dispatch.py`. B went deeper on test coverage. The pattern suggests the parser's surface was reviewed thoroughly, while the dispatch integration got one reviewer's attention. The grandfathering finding is a correctness gap that stands on its own merits despite having a single source.
