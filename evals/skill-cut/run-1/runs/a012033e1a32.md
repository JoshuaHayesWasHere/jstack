### Intent
> Step 4 (size) of the feature playbook has never fired: no brief carries a size. Briefs naming `Playbook: fix` or `Playbook: feature.` launched with no playbook. The fix has three parts:
> - Add a `Size: S|M|L|XL` line to the brief and plan-entry templates.
> - Make `parse.py` and `dispatch.py` refuse a brief that has no size or names a playbook that isn't a file in `playbooks/` (or `none`). Each refusal is one line.
> - Grandfather rows approved before the merge, and prove it with parser tests and a live-queue run that strands no approved row.

### Act On

**1. The grandfather cutoff is a fixed time before the merge, so rows approved in between get stranded** (A1, B1)
- `SHAPED_SINCE = "2026-10-15 11:15 ET"` (dispatch.py:60) is earlier than the PR's own commit (11:22).
- Any brief written from the old template and approved between 11:15 and the merge has no `Size:` line, so the gate refuses it.
- Adding the line changes the brief's sha, which re-gates it as "brief changed after approval". That is a stranded row, which the task explicitly rules out.
- Nothing is caught yet only because the latest live approval was at 11:06. The live-queue proof shows one moment, not the window.
- Both reviewers traced the same concrete path independently.
- **Fix:** set the cutoff at the moment of merge, or safely after it, as the last change before landing. Add a test for a row approved after the constant but before the merge.

**2. The cutoff compares strings, and the comparison depends on the configured zone and label** (A2, B2)
- `at >= SHAPED_SINCE` (dispatch.py:180/189) is only correct when jsettings is set to `America/New_York` with the label `ET`.
- That holds today, but only a docstring keeps it true.
- With a different zone the cutoff shifts by hours. With an unset label, the comparison is between "EDT" and "ET".
- This is the proxy and prose-rule pattern the review targets. The fix lands on the same line as #1, so it costs almost nothing extra.
- **Fix:** make the cutoff an aware `datetime`. Parse `ran_at` the way `digest.py:149` does, and compare instants.

**3. Scout-written briefs keep the template's `Size: S | M | L | XL` placeholder, so the gate always refuses them** (A3)
- In the home skill, step 1 sends a scout's brief straight to step 2 (SKILL.md:494). That skips the new `Size:` paragraph.
- `parse.sized` rejects the placeholder text.
- This blocks a whole class of briefs, every one approved after the cutoff, through the same re-approval chain as #1.
- **Fix:** have the home check and set `Size:` from the plan entry on a scout's brief, the same way it already checks `Home:`. The home skill is inside **Where**.
- The matching change to the scout skill is outside **Where**, so it's noted for later.

**4. Any `playbooks/*.md` passes, including playbooks a crewmate never runs** (A4)
- The literal "Done when" ("a file in `playbooks/`") is met.
- But a brief naming `orchestrate`, `investigation` or `opening-a-pr` still reaches crew step 3, which prints `not a crewmate's` and runs with no playbook.
- That is exactly the failure the task set out to stop.
- **Fix:** refuse any playbook whose `Run by:` is not `a crewmate`, reading it with the rule the crew block already uses. It is one `elif` in `parse.playbook()`.

### Consider

**`proves_it` should call the new `_head` helper** (A5, B4)
- This PR adds `_head` right beside the identical loop inside `proves_it`.
- Having `proves_it` call `_head` leaves one definition of "a brief's head", and it's a two-line change in a file inside **Where**.
- The tradeoff: it touches a function the task didn't otherwise need to change.
- I'd do it, since the duplication is the PR's own. `dispatch.designed` has the same loop, but it is unchanged here, so it's noted for later.

### Noted

- **The gate test takes its expected messages from `parse.sized`/`parse.playbook`** (B3). The test's job is to check that dispatch passes on the parser's line, and `test_briefs.py` already pins the literal wording. Pinning a literal here too would add a little, but this isn't a gap.
