### Intent
> Task: sections 1, 2, 5 and 6 of the /deeper design, built on Felix Rieseberg's "four types of ambition" (Depth). It covers four pieces: a manual skill that returns the four answers and a rewritten prompt, the 25th principle (`depth-over-breadth`), a blind eval required before merge, and the credit in `THIRD_PARTY.md`. The eval must be rerunnable by one command, scored blind by something other than the writing agent, and must say plainly whether /deeper won. If it did not, that is a finding, not a reason to tune.

### Reviewers
- Reviewer A: 5 findings
- Reviewer B: 8 findings
- Neither reviewer reported an unmet "Done when" line for the principle count, the jdrift test, `install.sh`, `THIRD_PARTY.md` or `make check`. All findings sit on the eval, the skill's gate wording and the principle card.

### Act On

1. **The "outside" measure rewards inline code, and the verdict rests on it** (A1, B1, merged into one root issue).
   - A1 rescored the committed briefs without the backtick branch of `OUTSIDE` (`evals/deeper/score.py`). Without it, the two arms are level: 0.34 plain against 0.33 deeper. The whole run-2 rise from 0.57 to 0.75 is backticks, and the skill tells deeper briefs to use them.
   - B1 shows the measure flipped sign on 8 of 10 cases between run 1 and run 2. The only skill change between the runs was the output format, from a fence to a block quote. Yet the README calls run 2 "won".
   - Taken together, "won" rests on a proxy that reads formatting, applied to one run of two that disagree. That is the exact outcome the task forbade dressing up.
   - **Why it matters:** the eval is the "Proves it" of this PR.
   - **Fix:**
     - Make a backtick span count only when it holds a run command, or drop the branch.
     - Rescore the committed briefs. This needs no model calls.
     - State the Result as what both runs show: raw and instruments up; proof outside not shown.
     - If that means /deeper did not win under the rule, say so.
2. **The raw-sources measure has no control for echoing the skill's list, yet the README claims one** (A2, B2, consensus).
   - Seven of the twelve `RAW` kinds match the skill's question 2 list nearly word for word.
   - The "What holds… not only by copying the skill's own examples" claim is backed only for instruments.
   - **Fix:** add a raw `beyond` count like `SKILL_EXAMPLES`, rescore offline, or narrow the sentence.
3. **The one documented command wipes the committed results before any model call** (A3, B3, consensus).
   - `write()` calls `rmtree` on `runs/` and `deeper/` first, and `key.json` is written only at the end.
   - Any one failure leaves the committed data deleted and the key stale. Failures include no `claude` binary, a timeout, a non-zero exit, or a missing block quote.
   - This is the crashed-halfway case, and it undercuts the "rerunnable by one command" requirement.
   - **Fix:** write into a temp directory and swap it in after the key is written. At minimum, check `shutil.which("claude")` before deleting anything.
4. **Redaction fails open** (B4).
   - `_private` ignores `XDG_CONFIG_HOME`, which `jleak.cli` respects.
   - It also swallows `jleak.Missing` and returns no patterns. Briefs from private task state then land unredacted in a repo meant to be public.
   - **Fix:** resolve the path the way `jleak.cli` does, and fail when the patterns are missing.

### Consider

- **B7: the gate's `Context:` placeholder.** The placeholder invites four lines, and jbus keeps only the first. The fix is one wording change inside `skills/deeper/`, and without it answers 2 to 4 are silently lost from the gate record. It is cheap enough to just do.
- **B6: the principle card's leans.** The card lists `perf-issue` and `investigation`, and neither references the principle. This is a false claim on a changed line, and the fix ("leans: `deeper`") is inside Where. Linking the playbooks is for later, since they are outside Where.
- **B5: `SELF` disqualifies any proof line containing "review".** It distorts `rs-parallel-reviews`. It is the same class of problem as Act On #1, so fix it in the same pass over the outside measure if it is cheap. It moves only one case.
- **A4: the `not_held` column is a phrase count over the whole brief.** The README reads it as a per-brief fact ("seven of the ten"). Either scope it to the Result section and match the tense variants, or relabel the column as a phrase count. This belongs to the "how it turned out" half of the eval, so it is worth getting right, but it does not change the verdict.

### Noted

- **A5:** importing `eval.py` leaves `evals/deeper` and `src` on `sys.path` and registers a bare `score` module for the test session. This is real hygiene, but nothing collides today.
- **B8:** the `= ()` default on `Pinned.own` is unused. Harmless.

### Dismissed

- None. Every finding traces to a changed line and shows a concrete effect. The two nits I kept low (A5, B8) are valid but not worth a cycle.

### Agreement Map

- **Where they agreed:** both reviewers independently found the raw-copy gap (A2/B2) and the destructive `write()` (A3/B3). That consensus makes both firm.
- **Where they converged from different angles:** on the outside measure, A attacked the scorer (backticks) and B attacked the reporting (re-run noise, a verdict from one run). Each alone is a warning. Together they show the "won" headline is not supported: the proof measure is a formatting proxy, and the only run that passed the rule is the one where that proxy moved.
- **What only B covered:** B ranged wider, into security (B4), the gate contract (B7) and doc accuracy (B6). A went deeper on the eval's internals.
- **What the pattern says:** the skill, principle, jdrift and counting work drew nothing serious. The eval's measurements and its run harness need work before the Result can be trusted.
- **What is likely to happen:** after rescoring, the honest Result is probably "raw and instruments up; proof outside not shown". The task explicitly accepts that as a finding.
