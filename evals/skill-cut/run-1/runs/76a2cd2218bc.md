### Intent
> Run the Size/Playbook/Proves-it and required-field checks at `jbus queue add`, before a brief is put to the user, and keep the launch checks as a backstop. Bind an approval to a deterministic meaning fingerprint over the scope fields, so typos, formatting, reordering and edits outside the scope fields keep the go, while scope, risk, path, number or value changes ask again. The approval record holds the fingerprint, the full `brief_sha` and the basis (the user's word or message id), and `verify` prints them for other bots. Old full-sha rows keep working. The docs and the PR state the method and its limit. Tests prove each case, and `make check` passes.

### Act On

1. **`queue add` accepts the template's own text for Task, Done when, Pull request and Review** (A1, B1).
   - `_filled` only treats a value starting with `<` as unfilled. The template's quoted Task, `- <a check>`, and the `a | b` choice lines all pass.
   - This breaks the core Done-when line ("an incomplete brief can't be queued"). The docs and the home skill also promise something the code doesn't do.
   - The existing test writes the Task line without the template's quotes, so it misses the gap.
   - Fix: strip quotes and list markers, then reuse `_template`. Add a test that runs `queue add` on an unedited `templates/brief.md` and expects every required field to fault.

2. **A negation keeps the go** (A3, B2).
   - Stripping the apostrophe turns `shouldn't` into `shouldnt`, which is within two edits of `should`. So "should fire" changed to "shouldn't fire" on a Done-when line keeps the user's approval.
   - The two-edit rule comes from the task. Joining contractions was the author's choice, and it puts a negation inside the typo allowance. That defeats "still catching real changes to intent or scope" on the most important field.
   - Fix: turn `n't` into a separate `not` token, and add a test that `should` changed to `shouldn't` re-asks.
   - The limit section in the docs and the PR must also name the residual cases that follow from the spec: near-antonyms like `include`/`exclude`, and swapped direction once fillers are dropped and words sorted. The Done-when line requires the known limit to be stated, and right now it is understated.

3. **The add check and the launch check are separate lists** (A4, B3).
   - Keeping `faults` in step with `CHECKS`/`ASKED` relies on a docstring. A check added to dispatch later would gate at launch but never refuse at `add`, which is exactly the problem this task exists to remove.
   - The only parity test covers the Design case alone.
   - Fix: keep one tuple of `(kind, check)` in `jbriefs.parse`, used by both. Dispatch keeps only its grandfathering logic. The redundancies in A7 go away with this change.

4. **The home skill discards the "its go does not hold" line** (A2).
   - On a successful add, the skill prints only `added: …`. A scope change that voids the go then looks like plain success, and the user is only asked again when a launch pass gates the brief.
   - The task is about surfacing problems before launch, and the skill is inside Where.
   - Fix: echo `$said` when it contains the void line, and say that the home then puts the brief to the user again.

### Consider

- **`scope` is stored and printed but never checked** (A5).
  - The strongest part: after a typo fix, `verify` shows a different `scope` with `holds: true`, so a bot comparing hashes would refuse a brief jbus launches. At minimum, the docs should say `holds` is the verdict and `scope` equality is stricter.
  - A method/version field is cheap insurance against later changes to `FILLER`. The tradeoff is a small amount of schema now versus silent mismatches later.
  - The tampered-`meaning` case is weaker, since hand-editing `queue.json` is outside the trust boundary.
- **The CLI matches the end of a string to decide what to print** (A6, B5).
  - Rephrasing either constant silently breaks the CLI output.
  - Returning a structured value from `queue.add`, or always printing the line, is a small change. It only matters if the wording is ever changed.
- **The PR says the launch checks are unchanged, but they now reject non-crewmate playbooks** (A8).
  - The change is intended by the task. But already-approved rows with such playbooks will now gate at launch, and the PR description should say so. It's a one-line PR text fix.

### Noted
- **A7:** `designed` is called twice, the `Size` `_filled` result is discarded, and `ROUTING` is dropped twice. These are folded into Act On #3.
- **A9:** changing an old row's priority needs a complete brief. This is theoretical, since every row queued today has all fields.
- **B4:** `approve` doesn't run `faults`. It only matters for pre-existing incomplete rows (none today), and the launch backstop catches them.
- **B6:** greedy pairing in `_pairs` can re-ask when a valid pairing exists. It only errs toward asking, so it is safe. Worth a docstring tweak at most.

### Dismissed
- **B7 (asks.py outside Where):** the queue verbs live in `asks.py`, not `cli.py`. The brief's Where line was imprecise, and the change put the code where it belongs.
- **B8 (PR description unverifiable):** Reviewer A read the PR body and found the limit section incomplete. That gap is covered by Act On #2, so this adds nothing.
