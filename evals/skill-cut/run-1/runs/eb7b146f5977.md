I don't run the suite. Running tests starts processes and writes caches and build output, which breaks the read-only rule.

1. **What I follow:** "Research", the bullet that says *"If a question needs such a run to answer, say so in the report and leave the run to a crewmate"*, along with *"A question that cannot be answered gets the reason and what would answer it, not a guess."*
2. **What I do first:** I find the exact full-suite command by reading the repo's docs and config, without running anything. That means the README, `package.json`/`Makefile`/`pyproject.toml`, and CI workflows.
3. **What I write:** a line under "Findings" in `$H/scouts/<slug>.md` `## Report`. For example: `Q<n> suite time on this machine: unanswered. It needs a test run, which a scout may not do. To answer it, a crewmate runs \`time <the suite command from step 2>\` from a clean checkout. No recent number exists in the docs, logs or history.`
4. **What I don't do:** I don't open a gate, because the user has no answer to give here. If the request asks for a brief, I put that `time …` run in its "Done when" list or its steps.
