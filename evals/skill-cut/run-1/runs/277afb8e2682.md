### Intent
> Give the user a way to undo a bad edit to a repo's `standing.md`. The home skill (including scoped homes) and the handoff skill run `jbus snapshot` right after editing `$H/standing.md`, so each edit becomes its own pushed commit in `~/.local/state/home`. `jbus snapshot` takes `--why <text>`, which is appended to the commit message after the time. `docs/state.md` explains how to find an edit (`git log -p -- <repo>/standing.md`) and how to restore it (`git show <commit>^:<repo>/standing.md > ...`), then snapshot again with `--why`. Executing tests cover one-commit-per-edit and the documented restore. The twice-daily timer stays, and `make check` passes.

### Reviewers
- Reviewer A: 7 findings
- Reviewer B: 5 findings
- The two reviewers independently agreed on the four substantive issues: concurrency/whole-tree staging, the truncating restore, the invented handoff duty, and the file outside Where. They split only on smaller items and on severity.

### Act On

**1. `take` has no lock, and snapshotting on every edit makes concurrent runs normal** (A1, B1)
Until now the timer was the only caller. This change makes every home and scoped home a caller on the same index. Two concrete failures follow:
- An overlap hits `.git/index.lock`, and `_must` raises.
- If the timer loses the race, `OnFailure` fires `--alarm` to the desk and every project for nothing.

A1's interleaving is worse: A's `git reset -q` lands between B's `add -A` and `diff --cached`, so B prints "nothing changed" and its edit gets no commit of its own. That breaks the first "Done when" line directly. The fix is an exclusive `flock` on a file in the tree's `.git`, held across add, commit and push in `take`. It is small and inside `snapshot.py`, and it deserves a test with two overlapping takes, or at least one that holds the lock and shows the second run waits.

**2. The documented restore empties `standing.md` when `git show` fails** (A2, B2)
The shell truncates the target before `git show` runs. Three ordinary cases make `git show` fail:
- the bad edit is the one that created the file (`<commit>^` has no such path);
- `<commit>` is the root commit;
- the hash is mistyped.

In each case the live rules are left empty, and the doc's own next step snapshots that empty file. This is a correctness bug in the deliverable the user asked for. The fix keeps the brief's `git show <commit>^:...` form:
- Write to `<path>.tmp` and `mv` it into place only on success.
- Say that undoing the edit that created the file means removing it.
- Add the missing test case where `<commit>` created `standing.md`.

**3. The handoff skill gains a rule-writing duty nobody asked for** (A5, B3)
"One it did not write yet goes there now" is new behaviour. It was invented to give the snapshot step something to attach to, and it contradicts the sentence before it. Cut it, and keep only the general instruction: "after any edit to `$H/standing.md`, run `jbus snapshot --why ...`". The same fix removes the hardcoded `added`, so handoff's wording matches the other two copies (the drift A4 noticed).

### Consider

**4. A `--why` commit sweeps in whatever else is dirty in the tree** (A3, B1's "mixed commits")
The undo still works, because both `log -p --` and `show <commit>^:<path>` are path-limited. The remaining costs are:
- An unscoped `git log` shows messages that describe only part of each commit.
- Rarely, two homes' edits to the same `standing.md` share one commit, so undoing one also undoes the other.

Scoping the commit to the named path (`git commit -- <path>` when `--why` comes with a path) would make the message honest and the edit truly its own commit. The tradeoff is a second argument and a slightly different commit path in `take`. The lock in item 1 already removes the race-driven failures, so this is the user's call on how literal "a commit of its own" should be.

### Noted
- **A4.** The snapshot rule lives in prose in three skill files. The brief asked for exactly that. A `jbus standing add` verb that writes and snapshots in one step would be the durable fix, but it is outside Where and noted for later. The wording drift is handled under item 3.
- **A6 / B4.** `docs/jbus.md` is changed, though it is outside Where. The edit is accurate, and without it `--why` would be undocumented on the commands page. Keep it, and record it under "Noticed" so the brief's Where can be judged.
- **A7.** The `with_origin` helper duplicates inline setup in older tests. Migrating those tests means touching unchanged lines, so it is outside this review's scope.
- **B5.** `test_a_snapshot_with_no_why_says_only_the_time` also checks the `why=` message, and its no-why half overlaps line 77. Renaming it or dropping the duplicate half is cheap, but it is a nit.

### Dismissed
- None. No finding was wrong. The rest are scope or style questions, already placed above.

### Agreement Map
The reviewers converged independently on the same three real problems: concurrent snapshots on a shared tree, the truncating redirect in the restore, and the handoff's invented duty. That consensus is a strong signal, and these three make up the Act On list. They diverged mostly on severity. A rated the handoff duty a warning and B rated it a nit; I side with A, because it changes what the handoff does. A went further on structure (a prose rule, a test helper), and B on test naming. Neither line affects correctness. The pattern is a sound feature with an unhardened edge: the new call frequency, which the code was never built for. One lock and one safer doc command close most of it.
