### Intent
> The feature playbook's size step has never fired (0 briefs carry a size), and briefs naming `Playbook: fix` or `Playbook: feature.` have launched with no playbook. Add `Size: S|M|L|XL` to the brief and plan-entry templates. Make `parse.py` and `dispatch.py` refuse a brief with no size, or with a playbook that isn't a file in `playbooks/` (or `none`), each with one line. Rows approved before the merge are grandfathered. Add parser tests for `fix`, `feature.`, no size and a good brief. `make check` and `jgauge test-slot -- make check` pass, and no approved row is stranded.

### Act On

**1. The grandfather cutoff is a fixed time that comes before the merge** (A1, B1)
`SHAPED_SINCE = "2026-10-15 11:15 ET"` (src/jbus/dispatch.py:60) is earlier than the PR's own commit.
- Any brief written from the old template and approved between 11:15 and the merge will be gated "no size" once this lands.
- Adding the `Size:` line changes the brief's sha. The row is then gated again as "brief changed after approval".
- That leaves the row stranded, which the "Done when" rules out.

Both reviewers found this independently and traced the same concrete path. The live queue check (latest approval at 11:06) only shows that nothing is stranded *yet*.

Fix: tie grandfathering to when the change actually lands, not to a guessed time. Two options:
- Set the cutoff at merge.
- Exempt any row approved before the first dispatch pass that runs the new code.

Add a test for a row approved after the constant but before the merge.

**2. Scout-written briefs reach launch with the template placeholder `Size: S | M | L | XL`** (A3)
- The home skill's step 1 sends a scout's brief straight to step 2, skipping the new `Size:` paragraph (skills/home/SKILL.md:494–498).
- The scout skill doesn't fill `Size:`.
- `parse.sized` rejects the placeholder, so every scout-written brief approved after the cutoff gates. Fixing it needs a re-approval, which is the same stranding chain as item 1.

Only one reviewer raised this, but the path is concrete and it defeats the point of the change for one whole source of briefs. Fix it in the home skill's step 1 (inside **Where**): set `Size:` from the plan entry, as is already done for `Home:`. The matching scout-skill change is outside **Where** and is noted for later.

### Consider

**3. The cutoff compares stamp text against a hard-coded "ET" string** (A2, B2)
`at >= SHAPED_SINCE` is only correct when the jsettings zone is America/New_York with label `ET`. That holds for the user's config and the test conftest, so there is no actual breakage today. It is still a proxy check, kept correct only by a docstring.
- Tradeoff: the fix for item 1 rewrites this constant anyway.
- Making it an aware datetime and parsing `ran_at` the way `digest.py:149` does costs a few lines.
- Do it alongside item 1 rather than as separate work.

**4. Any file in `playbooks/` passes, including ones a crewmate never runs** (A4)
The "Done when" wording is met. But a brief naming `orchestrate`, `expert-*` or `opening-a-pr` would still reach the crew skill, print "not a crewmate's", and run with no playbook. That is the failure the task set out to stop.
- No such brief has been observed. The cases actually seen are typos (`fix`, `feature.`), and those are now caught.
- The fix is a single `elif` on the `Run by:` line.
- It's cheap and closes the gap fully, but it goes slightly past the literal task. That's the user's call.

**5. New `_head` duplicates the loop in `proves_it`** (A5, B4)
`_head` is new in this PR and sits right below an identical walk. Having `proves_it` call it is a two-line change inside **Where**. It's not a blocker, but it is duplication this PR introduced. The copy in `dispatch.designed` is unchanged code, so that one is for later.

### Noted
- **A6**: `_SIZES` repeats the `SIZES` tuple by hand. The drift risk is real but small for a four-value enum that won't change.
- **B3**: the gate test gets its expected `why` from `parse.sized` / `parse.playbook`. The test's job is to show that dispatch wires those functions in, and `test_briefs.py` already pins the literal wording. A literal would be marginally stronger but isn't needed.
