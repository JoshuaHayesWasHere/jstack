### Intent
> The user found the UI/UX subpar: no header, sidebar, navbars or helpers. Done when: a header shows the name, the current location and the time of the last read. A sidebar lists "All" first, then each project with its waits count and a health dot, and becomes a row of chips under 900 px. Room, jbus and Runners are drawn once, as the machine's, and project facts stay out of the machine row. The Bus card no longer wraps at 1440, and the browser tests check for no sideways scroll at 1440, 900 and 390. Only the steps that hold a task are drawn, and the rest are folded. `make check` and `jgauge test-slot -- make check` pass. Decisions set on the grill page include word caps of 250 for the overview and 150 for a project, one vanilla file, and hash routes. A link to a retired project says there is no such project.

### Reviewers
- Reviewer A: 8 findings
- Reviewer B: 9 findings

Each also found something the other missed: A the read-time bug and the sidebar race, B the stale `unwell` source and the "0 failed wakes" text.

### Act On

**1. The word caps were met by moving content out of what is measured** (A4, B1, B2)
`words` now counts only `<main>`. The machine row moved into the sidebar, so it no longer counts toward either cap. The header and sidebar get a separate fixed cap, `SHELL = 30`, which already holds about 26 words with three projects.
- This makes the cap a proxy check. The user set 250/150 for what the first screen shows, and the tests now allow about 280/180.
- The fixed 30 contradicts the docstring's own claim that the shell grows with each project. Two more projects will fail the test while nothing on the page is wrong.
- Fix: hold the visible first screen (main, header and side) to the user's caps. If a shell figure stays, make it a base plus a per-project allowance, and test it with more than three projects.

**2. The sidebar dot and the overview row judge health by two different rule sets** (A2, B5)
`troubles()` restates the row-chip logic, and the two already disagree:
- A project with only blind spots gets an amber chip on its row and a green dot in the sidebar.
- When only `last_error` is set, the sidebar tooltip prints "0 failed wakes".

The health dot is a "Done when" item, and a dot that disagrees with its own row defeats it. Fix: one helper per health fact, read by both the row chips and the dot. This also removes the duplicate code.

**3. "read HH:MM" shows the current time while the server is unreachable** (A3)
`lost()` sets `NOW = Date.now()`, so the header's last-read time moves forward on every failed poll. That is the one case where the value matters. The "Done when" line asks for the time of the last read, and this shows something else under that label. Fix: keep the time of the last successful answer as its own value.

**4. The sidebar stays empty on a link to a missing project** (A1)
The path is concrete:
1. The 404 from `/state.json` arrives first and sets `S = null`.
2. `render()` runs while `STACK` is still empty, so the sidebar has no projects.
3. `STACK` then arrives, but `if (S) render()` skips the redraw.

The sidebar stays empty for up to 15 s, on exactly the route the user asked to handle ("no such project"). Fix: drop the `S` guard, since `put` already skips unchanged parts. Add the test A1 describes.

**5. The jbus machine item can claim "passing" when its source is stale or missing** (B3)
On a project page, the rest of the machine row comes from the fresh `/state.json`. The `unwell` part alone comes from `STACK`, which is fetched every fourth poll and whose failures are swallowed. When `STACK` is null, `unwell` is `[]` and the item shows ok/"passing". That is a false all-clear.
- Fix: derive `unwell` from `S.sources`.
- If that needs a `machine` flag added on the server, that change is outside "Where" and is noted for later.
- Within scope, at minimum, the item must not report ok when no stack read exists.

### Consider

- **The machine row is missing on the no-such-project page and on first load** (A7, B6). The new test docstring promises the row "on every view". The fix is a one-line fallback to `STACK.machine`, which pairs naturally with Act On 4. The cost is low, and the impact is small but visible.
- **The theme control became a cycle button** (A8, B9). This was not asked for, and its cycling is untested. Either revert to the three-button group inside the header, or keep it and add a test that clicks through auto → light → dark → auto and checks the stored value. Which one depends on whether header space forced the change.
- **The sidebar's sticky offset is hard-coded to 50 px** (A6, B8). The header wraps between 900 and 1100 px, and the sidebar then slides under it. That is a real visual defect in a PR whose point is UX polish, and a shared CSS variable fixes it cheaply.
- **page.html goes past 1,000 lines (979 → 1067)** (A5, B4). The user chose "one vanilla file", but the panels already use an inline-at-serve pattern that keeps the output a single file. A `shell` panel would fit that pattern. If it needs changes in `__init__.py`/`state.py`, those are outside "Where" and noted for later. Otherwise, the PR should say the overrun is intended.
- **The "one request a poll" comment is now false** (B7). The PR made it wrong, so it should be fixed in passing.

### Noted
- None beyond the above.

### Dismissed
- None. Every finding traced to a changed line, and none was a pure style preference.

### Agreement Map
The reviewers converged independently on the two things that most undercut the "Done when" lines:
- **The word-cap proxy:** the test was reshaped around the new content, instead of the content being fitted to the cap.
- **The split health logic:** the sidebar dot can disagree with the row it summarizes.

That consensus makes both firm blockers. Their solo findings, A's read-time and empty-sidebar bugs and B's stale `unwell`, share one root: the shell renders whatever state is lying around (`NOW`, a stale `STACK`, a null `S`) instead of what was actually read. That makes it worth reviewing the shell's data flow as a whole while fixing them. The remaining overlap (sticky offset, theme cycle, file size) is minor and sits correctly below the line.
