First, I'd replace the optional-field shape with a discriminated union, because `doneAt?: Date` already allows illegal states (`open` with a `doneAt`, `done` without one), and adding `cancelledAt?` would only multiply them.

This follows the opening rule, "Make illegal states unrepresentable" / "make the compiler reject impossible states… and unhandled variants." The file's bullets (branding, parsing, schemas) don't cover this case. The line I write:

`type Task = { status: 'open' } | { status: 'done'; doneAt: Date } | { status: 'cancelled'; cancelledAt: Date };`

Then I'd make every `switch (task.status)` exhaustive with `default: const _x: never = task;` so the compiler flags each handler that's missing `cancelled`. If a schema or DB migration owns `Task`, I'd change it there and derive the type instead.
