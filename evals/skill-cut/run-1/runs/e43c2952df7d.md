The principle doesn't apply here: its "When this applies" section requires "No external users depend on backward compatibility". This public npm library has thousands of external users, so that condition fails.
So I don't delete `parseConfig` in this release. First I keep it as a deprecated wrapper over the new API, and I migrate only our own internal callers and tests to the new API.
Line I write above `parseConfig`: `/** @deprecated Use parseConfigV2 instead; parseConfig will be removed in the next major version. */`
I also add a one-time `process.emitWarning('parseConfig is deprecated; use parseConfigV2', 'DeprecationWarning')` and a CHANGELOG entry. Deletion waits for the next semver-major release.
