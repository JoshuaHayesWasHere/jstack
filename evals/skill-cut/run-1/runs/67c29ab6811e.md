The principle doesn't apply. Its first "When this applies" condition is "No external users depend on backward compatibility." A public npm library with thousands of outside users fails that check.

So I do not delete `parseConfig` this release. I check `package.json` for the current version and find the callers inside the repo, then migrate those internal callers to the new API. I keep `parseConfig` as a thin wrapper that calls the new API, and I mark it deprecated.

Line I write above it: `/** @deprecated Use <newApi> instead; parseConfig will be removed in the next major version. */`
I also add a CHANGELOG entry for the deprecation. Deleting it waits for the next semver-major release.
