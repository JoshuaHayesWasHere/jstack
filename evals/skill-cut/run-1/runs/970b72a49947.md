**I don't delete `parseConfig` this release, because the principle doesn't apply here.**

1. **First:** check the file's **"When this applies"** section. Its first condition, "No external users depend on backward compatibility," fails: this is a public npm library with thousands of outside users.
2. **Instead:** keep `parseConfig` as a thin wrapper over the new API and mark it deprecated. I'd write: `export const parseConfig = util.deprecate((src) => parseConfigV2(src), "parseConfig is deprecated; use parseConfigV2. Removal in next major.", "DEP_PARSECONFIG");`
3. I'd add `/** @deprecated Use parseConfigV2 */` above it, plus a CHANGELOG entry and a migration note.
4. I'd still migrate the repo's own callers and tests to the new API now. That part of the principle is safe.
5. I'd delete `parseConfig` in the next semver-major release, after checking with the maintainers.
