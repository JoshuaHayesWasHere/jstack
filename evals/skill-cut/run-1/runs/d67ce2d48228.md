I don't run the suite. Running tests writes caches and artifacts and starts processes, so it isn't a read-only call. "Research" covers this case: *"If a question needs such a run to answer, say so in the report and leave the run to a crewmate."* It isn't a gate either, because the user can't answer it any better than a run can.

First I gather read-only evidence that bounds the number. For example, `gh run list --limit 5` and `gh run view <id>` give CI durations, which I label as CI and not this machine. I also find the exact test command in the README, Makefile or package scripts.

Then, under "Write it down", I write in the report's Findings: `Q<n> (suite time on this machine): not answered. Needs a run, which a scout does not make. Answer it with: time <exact test command>, run by a crewmate. CI gives <x> min (gh run view <id>), not this machine.`

If the request asks for a brief, that `time …` run goes into its "Done when" or first step. Then I go on to the next question. This is described, not run.
