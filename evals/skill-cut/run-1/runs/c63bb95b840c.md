### Act On

**1. The tick's catch-up conflicts with "One tick" step 4, so each hourly reply would repeat old news** (A1, B1)
- Step 5 still sends the home to "One tick". That section's step 4 says the reply covers only what this tick changed, "Nothing that an earlier message said".
- Ketchup covers everything since the user's last message.
- Autopilot runs while the user is away. Followed literally, the new sentence makes every tick re-report every earlier tick, and the reply grows each hour.
- This is a concrete execution path, not a hypothetical. Both reviewers found it independently.
- **Fix in this PR:** scope the step-5 catch-up to what this tick changed, and nothing an earlier message said. The two rules then agree.
- **For later:** making "One tick" step 4 itself point to ketchup, the way upstream has it, changes `skills/home/queue-and-its-hourly-audit.md`. That file is outside "Where", so it is noted for later, not asked for here.

**2. Hand over requires content that ketchup tells the writer to cut** (A3, B2)
- Both Hand over lines (`autopilot-full.md:32`, `autopilot-stack.md:33`) now require two things at once:
  - "what merged, with the commit", together with each entry's link, state and pull request;
  - writing it "per ketchup", which says to leave out hashes, stay well under 150 words, and cut what happened before cutting the action items.
- With a queue of any real size, ketchup's own cutting order removes the per-entry account that step 7 requires.
- The hand-over is the record the user lands from, so losing entries there is a correctness problem, not style.
- **Fix in this PR:** say which one wins. For example: "account for every entry as step 7 says, whole and not cut for length; catch the user up per ketchup on the rest."

**3. "Changed something for the user" leaves some ticks covered by neither sentence** (A2, B3)
- "Done when" says "a tick or reply that changed something". The diff added "for the user".
- That creates a third case, such as a launch, a re-sent stuck thread, or a pickup, which neither sentence covers.
- Ketchup's "leave out work that changed nothing for the user" could then let such a tick end silently, although One tick step 4 explicitly requires reporting launches and stuck threads.
- **Fix in this PR:** drop "for the user". This is a one-word change, and it brings the line back to the stated "Done when".

### Consider

**4. No test covers the new behaviour** (A5, B4)
- "Where" includes the playbooks' tests, but the diff changes none.
- The existing checker only confirms that `skills/ketchup/SKILL.md` exists. A later edit could drop the catch-up sentence or the silent-tick sentence, and every test would still pass.
- **Tradeoff:** for prose playbooks, any test is close to a wording check. One that runs the existing playbook parser in `tests/test_playbooks.py` is worth having if it is cheap:
  - check that step 5 and both Hand over sections name ketchup;
  - check that step 5 still holds the no-reply ending.
- A5's stronger version, checking that step 5 agrees with "One tick", would also catch item 1 if it regresses. Weigh that against the effort.
- It is not a blocker: the "Done when" lines require existing tests to pass, not new ones.
