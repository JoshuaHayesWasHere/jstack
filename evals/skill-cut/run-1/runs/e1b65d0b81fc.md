> **Merge-result check.** Settle from the code, with a test, whether jmerge's "fails over today's main" check runs the checks on the merge result. If it does not, make it do so whenever main changed a caller or a dependency of the PR's files, or a lockfile.

### Act On
- **The effort shape is not backed by the schema.** Raised by A1 and B4. The repo's T3 schema types `options` as `anyOf [{}, null]`, so the `{"id":"effort","value":...}` list is asserted, not read from the schema. The schema test passes any shape. A wrong shape would silently launch every Claude role at `high`, which is the exact rule this half of the task protects. This also misses two lines of the task:
  - The "Done when" line says the answer must be "read from T3's own tool schema".
  - "Proves it" asks for the schema to be quoted.

  The fix is either:
  - cite the real source (T3's provider/options contract, or a captured launch that was accepted) and test against a fixture that pins the shape, or
  - pipe the question to `jbus gate` and say so in THIRD_PARTY.md.
- **Rename/move misses callers main added under the old name.** Raised by B1. This is a concrete path through the case #613 exists for: the PR moves `core.py` to `engine.py`, and main adds `from pkg import core`. `left` is passed to `stale_paths` but not to `related`. The fix is cheap: feed `left` into `ours` with empty text. Add a Kitchen test with a `git mv`.
- **Bare-name sibling imports in `tests/` are never matched.** Raised by A4 and B2 (consensus). This is a real pattern in this repo: about ten test files use it, including the PR's own `test_jmerge_callers.py`. Main changing `Kitchen` would leave a stale green check. Add the bare-name form for files in pytest import roots, and a test for it.
- **An unreadable head makes the check pass.** Raised by A3. If `git show <head>:<path>` fails, every PR file is read as empty and no dependency can match. That lets a merge through where every other git failure in jmerge blocks it. Elsewhere in `cli.py`, jmerge fetches `refs/pull/<n>/head` for exactly this case, so the case is real. The fix: confirm the commit exists, fetch it if needed, and otherwise return a stale reason. Add a test.
- **The "never above medium" claim is wider than what was verified.** Raised by A2. THIRD_PARTY.md and the docstring say the rule holds for every role, but Codex and Grok lines send no effort and their defaults were not checked. Not sending an effort is not *raising* it, so the code is fine. The written claim is unverified, though. The cheap fix is to narrow the wording to Claude lines and gate the Codex/Grok default question, as the Decisions line already prescribes.

### Consider
- **Prose mentions of a path count as a dependency.** Raised by B3. This fails closed, so it is safe. The cost is unnecessary staleness and reruns: any docs or THIRD_PARTY.md PR goes stale whenever main touches a path it names, and this PR is such a case. Limiting path matches to files the check executes or loads (code, Makefile, CI config) is a modest change. The tradeoff is that some precision would be bought with a file-type list that someone has to maintain.

### Noted
- **Substring path match and suffix-based `conftest.py` match.** Raised by A5. These fail closed and cause rare extra noise. They are cheap to tighten, perhaps alongside B3.
- **One `git show` per file and pairwise `ast.parse` calls.** Raised by A6 and B5. This could matter against the 300 s jbus limit, but there is no evidence it is close to it. Parsing once per file, or `cat-file --batch`, is worth doing if it ever shows up in timings.
- **Three docs files outside the "Where" line.** Raised by A7: `docs/configuration.md`, `docs/jmerge.md` and `docs/jroles.md`. Each one describes the new behaviour, and dropping them would leave the docs wrong. Keep them and mention them in the Result so the person who set the "Where" line sees them.

### Dismissed
None. No finding was wrong or mere preference.

### Agreement Map

Where they diverged, they complemented each other rather than conflicted:
- A looked at failure handling: the unreadable head, and the providers outside Claude.
- B looked at match coverage: renames, and prose paths.

Together the findings show that the new dependency check is a text/import heuristic that is still open in three ways that matter:
- renames (B1),
- non-`src` import roots (A4, B2),
- read failures (A3).

Each of those is a fail-open path. The remaining findings fail closed or concern speed.

Neither reviewer confirmed the `make check` and `jgauge test-slot` lines. The Result should show those outputs.
