### Intent
> Every gate in every home becomes act-unless-stopped. The thread acts on its recommended default at once, the question is shown to the user as already acted on, and a pass closes it by silence after 2 hours. A later differing answer is still carried back. Gates whose default is irreversible or slow to revert (deletes data, rewrites history, spends money, touches prod or real users, changes access or secrets, publishes) must carry `Holds: <case>` and a `Fail-safe:` line. They do not act, wait for the user's answer with the dry-run, plan or bundle attached, and are never closed by silence. `jbus gate` refuses a missing default, a recommended option that is not the default, a `Holds:` with no fail-safe, and an unknown case. The default change and the fail-safe rules ship together in one PR, with fake-clock tests and `make check` green.

### Act On

**1. A `Holds:` gate answered with its default never releases the held action** (B1)
- `tell`, `_answer` and the page's carry all skip `keeps` answers. They assume the default was already carried out, and that is no longer true for a `Holds:` gate.
- The concrete path: crewmate gates `Holds: deletes data` → the user runs `jbus answer N --default` → nothing is sent → the action stays parked forever.
- A held gate can only move when the user says something *other* than the recommended default. That breaks the core of the fail-safe design.
- docs/jbus.md:132 is now false for held gates.
- Fix: carry a "go ahead" message when `one.holds` is set, fix the doc sentence, and add a test that answers a `Holds:` gate with `--default` and expects one message.

**2. A silence-closed question re-piped with `Holds:` is told "already answered", and the hold is lost** (A1)
- `ask` treats any answered record as settled, including `closed_by: silence`, so new `Holds:`/`Fail-safe:` lines are discarded.
- The skills then tell the thread "Go by it", so an irreversible action proceeds with no yes from the user. That is exactly what the fail-safe exists to prevent.
- `_open()` already models "open or silence-closed", but `ask` doesn't use it. The existing test at :768 enshrines the wrong reply.
- Fix: replace silence-closed records on re-pipe, reopen when `holds` is added, and add the fake-clock test A1 describes.

**3. Silence closes the link-conflict questions addressed to the home, and the stack parks** (A2)
- The home's own table says these ask the home, not the user. Its jq selects `.answer == null`.
- After 2 hours `_quiet` answers them, they drop out of `$LINKS`, and the rebase line is never sent.
- This is a concrete regression against "no question parks work", and both files are inside **Where**.
- Fix: exempt them from `_quiet` at minimum.

**4. "Shown as already acted on" and "with the fail-safe attached" reach no screen** (A4, B2)
- `acted`, `holds` and `fail_safe` land only in `waiting-on-user.json`:
  - the item `line` is unchanged
  - the home's jq and printf pull none of them
  - `waiting._blocks` and the page drop them
- Two Done-when lines are unmet. The only test reads the JSON, which is a stand-in for what the user actually sees.
- In scope: put the state in `line`, and add `.holds, .fail_safe` (and `acted`) to the home's read block and display. The page panel and `_blocks` changes are outside **Where**, so note them for later.

**5. Home skill still says "only their name closes a question"** (A6)
- skills/home/SKILL.md:822 contradicts the rule this PR adds, in a file the Done when requires to state that rule.
- A reviewer called this a nit. It is a one-line fix to instructions threads actually follow, so it goes here.

### Consider

**Collapse the redundant `(default)`/`(recommended)` marks** (A5, B5)
- Under the new rule the two always coincide. Two refusal branches, a dual field, about 10 rewritten fixtures, and outright refusal of old-style `(default)` gates all come from enforcing redundancy.
- The Done when line is equally met by treating `(default)` as the pick and refusing `(recommended)` on any other option.
- Tradeoff: a simpler and backward-tolerant parser, against a PR that already works and a spec phrased around two marks. Worth doing if the parser is touched again for the fixes above.

**Expert findings now recommend against themselves and vanish at 2 hours** (B3)
- The test fixture was edited to mark "leave it" as recommended. As a result, every expert finding claims the expert recommends no change, then closes by silence.
- That isn't what the user asked for, but skills/expert/SKILL.md is outside **Where**, and the right semantics need the user's call:
  - held,
  - a separate kind, or
  - the recommended change as the default.
- Flag it to the user rather than leave the fixture papering over it.

**Silence-closed questions can be re-answered only from the CLI** (B4)
- The Done when line ("a later differing answer is still taken") is met through `jbus answer`, but the page drops the question and the docs imply any path works.
- Cheap in-scope fix: say plainly in docs/jbus.md that later answers go through `jbus answer N`. The page state is for later.

**Words page shows a silence close as the user's own answer** (A3)
- Misattribution in the user's own record of what they said, which runs against the task's "a basis that says it is not his word".
- The panel is outside **Where**, so note it for a follow-up and don't fix it here.

### Noted
- `_held` duplicates `mirror.field` line scanning (B6). The drift risk is real but small. The fix lives in mirror.py, outside **Where**, so leave it for later.

### Dismissed
None. Every finding names a concrete path or a real mismatch with the spec. The two nits were judged on their merits (one promoted to Act on, one Noted), not on their labels.

### Agreement Map
- **Where they agreed:** the display gap and the redundant marks. The display gap is the stronger signal: two independent reads found that the user-facing half of two Done-when lines was never built.
- **Where they diverged:** each found a different hole in the same underlying problem. A traced what *silence-closed* does to other consumers (`ask`, home links, words panel). B traced what *held* does to the send path (`tell`, view carry, expert gates).
- **What the pattern says:** the PR added two new states, "closed by silence" and "held, awaiting yes", as fields on the record. It did not model them as states that every consumer of a question must handle. Each consumer still assumes the old two states, open or answered-and-already-done.
- **What to do about it:**
  - Act-on items 1–3 are all that one gap.
  - A first-class lifecycle for a question (open-acted, held, closed-by-silence, answered), checked wherever `answer`/`keeps` is read, would close them together.
  - An end-to-end fake-clock test of a `Holds:` gate (ask, wait, answer with the default, the thread is told) is the test this PR most lacks. Neither reviewer found one.
