### Intent
> Make threads obvious per project and let the user follow scouts and crewmates. Each project's row and page gets a Threads band by role (crewmates, scouts, reviewers, home), built from `pass.json` `projects[name].threads`: threads that are out come first with liveness and last write, threads ended today are dimmed, and the rest are folded. `#/<project>/thread/<role>/<slug>` opens a drawer showing what the thread works on. The server reads one new read-only source, the scout requests under `scouts/`, to say researching, reported or blocked. A missing thread list is a blind spot, never "none". The change ships with fixture tests, a green `make check`, and a passing test-slot run. Everything stays inside the Where line and the view stays read-only.

### Reviewers
- Reviewer A: 8 findings
- Reviewer B: 7 findings
- Both read the diff against the brief's questions. They agreed independently on four findings (the duplicate row and role tables, the `health()` tag, the missing band on the page, the `thread/` folder outside Where). Each also found correctness issues the other did not.

### Act On
- **An ended scout with no Report still reads "researching"** (A1). There is a concrete path: a thread is `live: "ended"`, its request has no `## Report`, and the chip and drawer say "researching" under an "ended" heading. This is the case the user most needs flagged, a scout that stopped without reporting, and the page tells them it is still working. No test covers it. Fix: say researching only while the thread is out, give an ended thread with no Report its own amber state, and add a test for it.
- **`Status: not done` shows as a green "reported"** (A2; B6's capital-`Blocked` example belongs here too). The scout template allows `done | not done | blocked`, and jbus's own settle check treats anything but `done` as unfinished. The view therefore shows green where jbus says "stay". Fix: map `done` to reported, `blocked` to blocked (case-insensitive), and anything else to a non-`ok` not-done state. Take the Status line the same way the settle check does (the last one in the last Report). Test a last Report whose Status is `not done`.
- **The `scouts/` source always says "ok", and an unreadable request reads as "missing"** (B1). `seen` never passes `read` or `path`, so a home with no `scouts/` directory, or one it cannot read, still shows `ok`. That breaks "a blind spot, never none" for the one new source this PR adds. Catching every `OSError` as missing makes the drawer claim that an existing but unreadable file is absent. The directory's mtime is also a proxy: appending a Report does not change it, so it cannot show when a report was written. Fix: pass `read`/`path`, treat only `FileNotFoundError` as missing, and add a test with no `scouts/` directory.
- **One thread row is written twice and roles live in two tables** (A3, B3). This PR introduced both copies. `about()` duplicates `threadRow()`. `ROLE` and `ROLES` are positional arrays with different column orders and already disagree on names ("crews" vs "Crewmates"), and `band()` reads one table to index the other. Fix: keep one ordered role table with named fields and one row renderer that takes a title parameter, used by both panels. This is cheap now and will drift if left.
- **A project page whose pass listed zero threads draws no band** (A5, B2). This goes against the Done-when line "each project's row **and page** has a Threads band", and the row draws a calm "0 out" band for the same data. An empty list is not the blind-spot case, which is an absent list, so nothing justifies the special case. Fix: draw `band()` unconditionally and let its calm state handle zero, which deletes the conditional and its comment. Test the empty list.
- **The `"threads"` tag in `health()` exists only for `projectRow` to filter it back out** (A4, B5). This is a magic string in a shared helper, with prose explaining the exception and nothing tying the string to the filter. Fix: take the threads fact out of `health()` and let `amber()` (or the band) add its own reason. Both files are in Where.

### Consider
- **The `panels/thread/` folder sits outside Where, and `adds.band` is undocumented** (A8, B4). The route likely needs a registered `thread` drawer kind, and an empty `panel.py` stub is the cost of that. Tradeoff: if the threads panel can register the drawer itself, the stub goes away. If it cannot, keep the folder and record why under "Noticed". Documenting `adds.band` in `panels/__init__.py` is outside Where and is for later.
- **`gates_inside=True` followed by a `re.split` that undoes it** (A6). If `mirror.sections` without the flag ends the body at `## Gate`, as A6 says, two pieces of code and a docstring sentence go away. Confirm `mirror`'s behaviour before deleting. B6 notes that `jbus.threads._scouts` uses the same flag, so check that there is not a case where they differ.
- **Optional `home`/`day` on `_threads` that no caller omits** (A7). Making them required removes two guards. It is small, but it is complexity this PR added.
- **The panel imports the private `_mtime`** (B7). The B1 fix rewrites this `Source` anyway, so moving it into `state.py` next to `SCOUTS`, as `PASS_FILE`/`MERGE_LOG` are, costs nothing extra.

### Noted
- **One shared "last Report and its Status" reader for jbus and the view** (B6). This is the right end state, but it lives in `jbus.threads`/`mirror`, which is outside Where and outside "the view only reads". Note it for later. The local Status rule is fixed under A2.

### Dismissed
- None. No finding was wrong or missing context. The lighter ones are low-cost cleanups of complexity the PR itself introduced, not style preferences.

### Agreement Map
The reviewers converged on structure: duplicate tables and renderer, the `health()` tag, the missing band on the page, and the out-of-scope folder. They weighted these differently (A called the page band a nit while B called it a warning; for the `health()` tag it was the reverse), but they agreed on the facts and the remedies, which is a strong signal. They diverged on correctness, and each found what the other missed. A traced the meaning of the scout states (an ended scout with no Report, `not done`), and B traced the honesty of the new source (always `ok`, unreadable read as missing, the mtime proxy). Each of these has a concrete path, and together they show that the scout status, the one new server-side read, is the least settled part of this PR. Its tests cover only the happy layout. The front-end work largely meets the brief, apart from the empty-band case.
