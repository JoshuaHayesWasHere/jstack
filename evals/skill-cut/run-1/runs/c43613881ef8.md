### Intent
> The user asked that threads be more obvious per project, and that scouts' and crewmates' work be trackable. Each project's row and page gets a Threads band from `pass.json` `projects[name].threads`, grouped by role. Threads still out come first, with liveness and last write; threads that ended today are dimmed; the rest are folded. `#/<project>/thread/<role>/<slug>` opens a drawer of what the thread works on. The server reads one new read-only source, each scout request's `## Report` and `Status:` under the home's `scouts/`, to say researching, reported or blocked. A project whose last pass left no thread list shows a blind spot, never "none". Tests use small fixtures, and `make check` and `jgauge test-slot -- make check` pass. The work stays vanilla, read-only, and inside the Where line.

### Reviewers
- Reviewer A: 8 findings
- Reviewer B: 7 findings
- Both worked through the review's seven questions. They converged on four issues and split on the rest: A covered scout-status meaning, B covered whether the new source reports honestly.

### Act On

1. **An ended scout with no Report still reads "researching"** (A1). `request()` decides the state from the file alone, and `threadChip` shows that state ahead of liveness. A scout that crashed or was settled early is shown as working, dimmed, under an "ended" heading. This is the case the user most needs to see, and it is the opposite of tracking scouts' work. Only say `researching` while the thread is out. Give an ended scout with no Report its own amber state, such as "ended, no report", and test it.

2. **`Status: not done` is drawn as a green "reported"** (A2, with the case point from B6). `state.py:734` maps everything except `blocked` to `reported`. The scout template allows `done | not done | blocked`, and jbus's own settle check treats anything but `done` as unfinished. So the page says finished when jbus says not finished. `Status: Blocked` with a capital B also falls through to "reported". The fix:
   - Map `done` to reported and `blocked` to blocked, case-insensitively.
   - Give anything else a non-`ok` state.
   - Add a fixture whose last Report is `not done`.

3. **The page doesn't get a band when the pass listed zero threads** (A5, B2). `page.html` (`S.threads && !S.threads.length ? "" : band(...)`) breaks the "row **and page**" Done-when line, and it disagrees with the row for the same data. The fix is deleting the special case and letting `band()`'s calm state draw "0 out". Keep the separate case where there is no list at all (blind spot), and test the empty list on both surfaces.

4. **The `scouts/` source always says `ok`** (B1). Its `seen` passes only `at`, so `_source` can never report missing or unreadable. This is a proxy check on a page whose whole point is naming blind spots:
   - A home with no `scouts/` shows `scouts/ ok`.
   - `request()` turns a permission error into "missing", so the drawer says no request exists for a file that does exist.
   - `at` is the directory's mtime, which an appended Report doesn't change.

   Pass `read` and `path`. Treat only `FileNotFoundError` as missing. Take `at` from the newest request file rather than the directory. Add a fixture with no `scouts/`. While rewriting this source, define it in `state.py` next to `SCOUTS`; that also resolves B7.

5. **The thread row is rendered twice and the roles are in two tables** (A3, B3). Both reviewers found this independently. `about()` in `thread/panel.js` copies `threadRow()` except for the title cell. `ROLE` (page.html) and `ROLES` (threads panel) are positional arrays with different column orders, and they already disagree on wording ("crews" vs "Crewmates"). The fix:
   - Keep one row renderer with a title parameter.
   - Keep one ordered role list with named fields, and derive the band and filter order from it.
   - Put both where both panels can reach them, which is page.html next to `threadChip`. B3's suggestion to move `threadChip`/`ROLE`/`LIVESAY` into the threads panel conflicts with the drawer also using them, so I'm not taking that part.

### Consider

- **The `"threads"` tag in a fourth tuple slot of `health()`** (A4, B5). This is a prose rule: the row filters on a string that nothing enforces. The cheap fix is to drop the threads fact from `health()` and let `amber()` add that reason itself. It's worth doing, but it's a small fragility rather than a bug today.
- **`gates_inside=True` followed by a `re.split` that cuts at the gate again** (A6). If `mirror.sections(whole)` really gives the same body, this is free deletion. Confirm with a fixture that has a Gate inside a Report before removing it, because the call mirrors `jbus.threads._scouts` on purpose.

### Noted
- **Unused defaults on `_threads`** (A7). This is a trivial cleanup. Check that tests don't call `_threads` without `home` first.
- **New `panels/thread/` directory outside Where** (A8, B4). The `thread/<role>/<slug>` route plausibly needs its own drawer kind, which fits the Where line's "if a route needs it". Say so in the PR description. The undocumented `adds.band` hook belongs in `panels/__init__.py`, which is outside Where, so it's for later.
- **Three readers of the scout Status line** (B6). A shared "last Report and its Status" helper in `jbus.threads`/`mirror` is the right end state, but it's outside Where and for later. The Act On fix in item 2 covers the user-visible part.
- **Private `_mtime` imported across modules** (B7). This is resolved by moving the Source into `state.py` as part of item 4.

### Dismissed
- None outright. The one part I'm rejecting is B3's sub-suggestion to move `threadChip`/`ROLE`/`LIVESAY` out of page.html: the drawer uses them as well as the threads panel, so the shell is their natural shared home.

### Agreement Map
The reviewers converged on four structural issues: the duplicated row and role tables, the `health()` tag, the missing empty-list band, and the extra panel folder. That consensus makes the duplication and the missing band clear calls. They disagreed on severity, though: A called the missing band a nit where B called it a warning, and A called the `health()` tag a warning where B called it a nit.

Their unique findings are the more important ones. Both concern whether the band tells the truth:
- A traced what the status words mean against the scout skill and found two concrete wrong states (A1, A2).
- B traced the new source's plumbing and found it cannot report its own blind spot (B1).

Neither reviewer padded with style nits. The PR's shape is sound. What remains is the truthfulness of the one new source and the duplication that will otherwise drift.
