### Intent
> Section 3 of the /deeper design: a step inside the home skill's brief writing, not a separate file. It runs on its own for research, perf, analysis and outcome briefs and carries its own copy of the four questions. Answer 2 goes to the scout's `Read:` or the request's sources, answer 3 to the brief for the crew, and answer 4 to `Proves it:`. Mechanical fixes, docs changes and bug fixes with a known cause skip it. Text tests pin the step. `make check` and `jgauge test-slot -- make check` pass. `skills/deeper/`, the principle, `templates/brief.md` and the parser stay untouched.

### Act On

**1. The step names an `Instruments:` line nothing defines, and a `Read:` line the brief template forbids on home briefs** (A1, B1)
The step says a home-written brief carries `Read:` (answer 2) and `Instruments:` (answer 3).
- `templates/brief.md:17` tells the home to leave `Read:` out of its own briefs.
- `Instruments:` exists nowhere outside this diff. It is not in the template, the scout skill, the crew skill or the parser.

The phrase "though the home wrote it" acknowledges the clash without settling it. A home that reads the template first gets the opposite instruction. A scout following its own skill drops answer 3.

The intent never asked for a new line. It asked for answer 2 in the *scout's* `Read:` (or the request's sources) and answer 3 "in the brief for the crew". Since the template is under "Do not touch", the fix stays inside "Where":
- Put answer 3 in lines the template already has: the task body or Done-when items.
- Drop the claim that a home brief carries `Read:`.
- If a real field is wanted later, note `templates/brief.md` and the scout skill as a follow-up in the Result.

**2. The skip is decided by the playbook name, not the kind of work, and that breaks the boundary** (A2, A3, A4, B2, B3; merged)
The kind of work is consulted only when the playbook is `none`. Four concrete failures follow:
- **`bug-fix` always skips.** That playbook is for reproducing and root-causing defects, including ones whose cause is unknown. The boundary exempts only a fix whose cause is already proven. The test then pins this wrong behaviour as "known bug".
- **Outcome work skips** whenever it carries `feature` or `autonomous-run`, so it gets the step only with no playbook at all.
- **Scout requests always run the step**, because both scout playbooks are in the deeper arm. That holds even when the request's Deliver asks for a brief for a docs change or a refactor.
- **The ten-name list will drift.** It duplicates what each playbook's `Run by:` row says, and the one-directional test cannot notice a new research playbook falling to `skip`.

One remedy removes all four:
- Make the stated kind of work the input in every case: `research|perf|analysis|outcome` versus `mechanical|docs|known-cause-fix|other`.
- For a request, use the kind of the task being briefed, not the scout's playbook.

The hand-kept list then disappears, and so does the test that guards it. Change the `bug-fix` skip test into one that runs the block with each kind. Do not delete it.

### Consider

**3. A request with no brief in its Deliver list has nowhere to put answers 3 and 4** (A5, B4)
The answers are worked out and then dropped silently. B's remedy is cheap and uses an existing home: write 3 and 4 as `Questions:` items in the request. The tradeoff is one more sentence in an already long step. Given the Done-when mapping, it is probably worth it.

**4. No test ties the lines the step names to the templates** (A6)
Once finding 1 is fixed, a small executing test is cheap: take each brief line the block echoes and assert it appears in `templates/brief.md` or `templates/scout-request.md`. That test would have caught finding 1. It is worth adding if it is not much code.

**5. "Skip it too when Done when already names data, instruments and judge" lives only in prose, after the block has printed `deeper`** (B6)
This is a rule the home has to remember. If finding 2 is reworked around a kind input, fold this in as an input value so the block prints the skip itself. On its own, it is not worth a separate change.

- They also converged on the same remedy for the hand-kept list (key on kind) and the same out-of-Where alternative (a marker in `playbooks/`). That suggests the kind-keyed reframing is the "code judo" move here: it collapses three findings into one edit.

- A alone saw the scout-request mis-trigger (A3), and B alone saw the prose-only skip clause and the dangling reference. These are complementary rather than conflicting.
- The overall pattern is that the step's wording is fine, but its decision input and output targets are wrong. Fix those two and the PR is close.
