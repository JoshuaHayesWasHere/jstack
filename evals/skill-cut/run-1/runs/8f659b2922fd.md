### Act On

1. **The effort shape is asserted, not proven, so a wrong shape would silently launch at `high`** (A1, B4). The fixture's schema types `options` as `anyOf [{}, null]`, so the conformance test passes whatever jroles emits. "Done when" asks for the answer to be read from T3's schema, and "Proves it" asks for that schema to be quoted. The schema in the repo does not contain this answer. If the shape is wrong, every Claude role falls back to the default, which the PR itself says is `high`. That breaks the user's rule with no signal. Both reviewers found this independently.
   - Fix: cite the real source of the `{"id": "effort", "value": …}` shape (T3's provider or model-options code, from the clone) and pin it in the fixture so a different shape fails the test.
   - If no source exists, gate it with `jbus gate`. Do not claim the shape in THIRD_PARTY.md as settled.

2. **A PR that renames or moves a module misses callers main added under the old name** (B1). This is a concrete path and the core case of #613: `git mv core.py engine.py` on the branch, while main adds `from pkg import core`. `left` reaches `stale_paths` but not `related`, so the old module name is never compared, and the PR merges onto a broken import. The new test only covers renames inside a file that keeps its path.
   - Fix: pass `left` into `related` as empty-text entries, and add a Kitchen test for `git mv` plus a new caller of the old module on main.

3. **Bare-name sibling imports are invisible to `modules`** (A4, B2). Both reviewers found this independently, and the repo depends on the pattern. At least ten test files do it, including the PR's own `tests/test_jmerge_callers.py` importing `Kitchen` from `test_jmerge_fresh`. A change on main to a shared test fixture is exactly the "main changed a dependency" case, and it is missed.
   - Fix: also name files under the pytest import root (`tests/`) by their bare module name, and add a sibling-import test.

4. **An unreadable head fails open** (A3). If `git show <head>:<path>` fails in the main checkout, the PR's files read as empty and no dependency can match, so the check stays green.
   - This is real: the reviewer points to existing jmerge code that fetches `refs/pull/<n>/head` precisely because heads can be missing. Every other git failure in jmerge blocks the merge, and a merge gate must fail closed.
   - Fix: verify the head with `cat-file -e`, fetch the pull ref if needed, and treat "still unreadable" as stale. Add a test for a missing head.

5. **The "never above medium" claim overreaches for Codex and Grok lines** (A2). THIRD_PARTY.md and the docstring say the rule holds for every role the map names. The PR only established it for Claude lines, and its own reasoning (T3's default is above medium) is a reason to doubt the other providers too.
   - Fix (cheap, inside the Where): narrow the wording to Claude lines and gate the Codex/Grok default question. Capping them would need each provider's option shape, which is not established, so it stays out of this PR.

### Consider

- **Prose mentions of a path count as a dependency** (B3). A PR that edits THIRD_PARTY.md or `docs/jmerge.md` goes stale whenever main touches any path those docs name. That forces a rebase on guarded PRs and a full re-run elsewhere. It fails closed, so it is a cost, not a hole.
  - The tradeoff: limiting matches to "executable" files has to keep the Makefile, `ci-paths.txt`, CI config and lockfiles, which are text that genuinely matter.
  - A simple form: only let a PR's code and config files pull in main's changes, not its markdown.
