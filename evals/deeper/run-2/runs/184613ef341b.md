# check-parallelism: set `make check`'s pytest worker count so concurrent runs use the whole machine without tripping `room` or pbus's gate
Task: "I want to push my machine as hard as I can without going over the edge" and "run the test in parallel". "Set `make check`'s parallelism so the machine is used to the full and never refuses work."
Done when:
- the hyperfine table (`hyperfine --runs 5 -L n 1,2,3,4,6,8,12 'pytest -q -n {n}'`) shows the chosen worker count within 10% of the fastest, with spread;
- three concurrent runs finish within 1.3× one alone;
- in the replay of three concurrent `make check` runs plus a crew load, CPU "some avg10" stays under `room`'s threshold, `room` says go, and pbus's own log shows `gate pp-doctor` launching its 10 passes.
Where: the `check` target in the Makefile and #339's diff; the pytest/xdist settings it uses; `room`'s source and log (read only); pbus's log (read only)
Do not touch: `room`'s thresholds and signals, and pbus's `gate pp-doctor` logic (the fix is in `make check`, not in the gates that refused it); other crews' runs and system-wide settings beyond installing `perf`, `sysstat` and `hyperfine`
Decisions: "Start from the raw record, not the remembered numbers": the `check` target and #339's diff, `nproc` and `lscpu`, `sar -u -q -r -f /var/log/sa/sa12` and `journalctl` for 21:20 to 22:10 on 2026-10-12, `room`'s source and log to see which signal and threshold refused, pbus's log line, and `pytest -n 6 --durations=0` to see whether the suite is CPU-bound. Then measure with hyperfine as above, `perf stat -e task-clock,context-switches,cpu-migrations -- make check`, and the replay with `/proc/pressure/{cpu,memory,io}`, `vmstat 1` and `pidstat -u -w 1` recorded throughout. "Install `perf`, `sysstat` and `hyperfine` with pacman if they are missing." "Define 'the edge' by pressure stall, not load average." "Budget workers against the whole machine, not one run." "If tests must yield, use `systemd-run --user --scope -p CPUWeight=` rather than a fixed cap."
Design: none, the user has already set the approach (edge by pressure stall, a whole-machine budget, yield by `CPUWeight` scope), and what is left is measuring and choosing a number
