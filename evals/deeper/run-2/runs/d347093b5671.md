# homes-over-limits: Make homes stop at their configured limits instead of running past them
Task: "Fix the homes running past their limits"
Done when:
- A home that reaches any of its configured limits stops starting new work and stops itself, with no further turns, spawns or tool calls after the limit is hit.
- The limit check also covers a home started by another home, so a scoped home stays inside its own limits and its parent's.
- When a home stops on a limit, it reports which limit it hit and what work is left.
- A test reproduces a home running past a limit, and it fails before the fix and passes after.
- The existing test suite passes.
Where: the home skill and its playbooks, and the Python commands that track and enforce a home's limits (counting, checking and stopping)
Do not touch: the limit values themselves and their defaults; how scouts, crewmates and reviewers work, except where they report usage back to the home
Decisions: none
Design: none, it is a bug fix that makes the existing limits hold and adds no new behaviour
Pull request: ask first
Review: review
Playbook: none
