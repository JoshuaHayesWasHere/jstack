# check-workers-fit-room: size `make check`'s pytest workers to the room the machine has, so parallel tests stop starving pbus

Task: "I want to push my machine as hard as I can without going over the edge" (the user, 2026-10-10), and "run the test in parallel" (2026-10-12)
Done when:
- `make check` still runs pytest in parallel, but picks its worker count from the machine's free capacity (cores and current load, as `room` judges them) rather than a fixed six.
- With three `make check` runs plus a crew's own test run going at once on the 12-core machine, the one-minute load stays under the core count, and `room` still gives a go so pbus can launch (no `gate pp-doctor: no room for 10 passes`).
- On an idle machine, `make check` uses at least as many workers as it does now, so a lone run is not slower than after tests-parallel (#339).
- When there is no room, `make check` falls back to one worker (or waits) instead of adding load. A test covers this, with load and core count injected rather than read from the live machine.
- The full suite passes under both the parallel and the single-worker setting.
Where: the `check` target in the Makefile; the pytest parallel setting #339 added (`-n 6` or its config); the `room` command and the load and core reading it uses; tests for these.
Do not touch: `room`'s thresholds and pbus's gate (do not loosen them to let launches through); the tests' own content beyond what the worker change needs; going back to running the suite serially.
Decisions: "run the test in parallel"; "push my machine as hard as I can without going over the edge"
Design: none, a contained change to how `make check` picks its worker count, reusing `room`'s existing judgment
