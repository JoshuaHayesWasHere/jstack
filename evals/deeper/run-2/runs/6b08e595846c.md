# release-audit: turn "every audit" into a finite, named checklist in `docs/release-audit.md`, run it over all history, and report readiness to go public
Task: "We should not take jstack public until it passes every single audit that we could potentially throw at it for what would make a good public repository."
Done when:
- `docs/release-audit.md` lists a finite set of named audits, one line each, with its command, its pass threshold, its result and its date.
- The audits run against the raw material, not just the current checkout: the full history (`git log --all -p`, `git rev-list --all`), the author and committer identities across it, a history-wide grep for home paths, `.claude/projects` and personal emails, `LICENSE`, `THIRD_PARTY.md` and every vendored or quoted file, the CI logs, and a fresh clone in an empty container.
- `gitleaks detect --log-opts="--all"` and `trufflehog git --only-verified` both report zero findings over all history.
- `git filter-repo --analyze` has been run and its results recorded. Any finding has a proposed rewrite, held for the user's go-ahead.
- `reuse lint` passes, and `licensee`/`scancode` show that every third-party file is credited in `THIRD_PARTY.md`.
- The history grep and the identity list show nothing the user hasn't chosen to publish. Every hit is listed for the user to rule on.
- `scorecard` is at least 8.0, and `actionlint` and `zizmor` are clean on every workflow.
- `shellcheck` is clean on every shell script.
- The repo's own tests pass.
- Someone who has never seen jstack gets from clone to a working first command in a clean container, using only the README, in under 10 minutes. This is timed and recorded.
- The filled checklist is reported to the user with a ready / not-ready verdict and every failing line named. Visibility is unchanged.

Where: `docs/release-audit.md`; all refs and history of the repo; author/committer metadata; `LICENSE`; `THIRD_PARTY.md`; vendored and quoted files; `.github/workflows/`; shell scripts; `README`; CI logs; the test suite
Do not touch: the repo's visibility. Also do not run a history rewrite, force-push or rewrite any ref without the user's go-ahead. Propose the rewrite in the report instead.
Decisions: "Do not flip visibility yourself. Report the filled checklist and let the user decide." A rewrite happens "before publishing if anything turns up." The pass thresholds are:
- "both secret scanners report zero findings over all history"
- "`reuse lint` passes and every third-party file is credited"
- "the history grep shows nothing the user hasn't chosen to publish"
- "Scorecard is at least 8.0 with clean workflow lints"
- "someone who has never seen jstack gets from clone to a working first command in a clean container using only the README, in under 10 minutes"

Design: none, the task is an audit and a checklist document with the tools and thresholds already chosen by the user, so there is no design call to make
