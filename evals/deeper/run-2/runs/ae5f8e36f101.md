# parallel-tests: Run the test suite in parallel
Task: "run the test in parallel"
Done when:
- One documented command runs the whole suite in parallel across workers, for example `pytest -n auto` through pytest-xdist.
- The parallel run passes with the same set of tests that pass in a serial run, with none skipped, lost or deselected.
- The parallel run passes three times in a row, with no order-dependent or shared-state failures.
- The parallel run is faster in wall-clock time than the serial run, and both timings are reported.
- A serial run still works for debugging.
Where: test configuration (`pyproject.toml` / `pytest.ini` / `conftest.py`), test dependencies, `tests/`, and any script or doc that says how to run the tests
Do not touch: the Python commands, skills and playbooks under test; test assertions, except to isolate shared state such as temp dirs, ports or fixed file paths
Decisions: none
Design: none, adding a parallel test runner is a configuration change with no design call
Pull request: ask first
Review: review
Playbook: none
