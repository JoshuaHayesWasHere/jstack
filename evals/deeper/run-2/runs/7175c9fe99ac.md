# make-check-slowdown: find what makes `make check` slow, and why, without fixing it

Task: "Figure out what is slowing down make check and why."

Done when:
- What `check` actually runs is listed from `Makefile`, its includes and `make -n check`, not from impressions.
- The baseline comes from `hyperfine --warmup 1 --runs 10 'make check'`, run separately on a clean tree and a warm tree, and is reported with its mean and spread.
- A timed trace from `make --trace check | ts -s` is recorded.
- The test runner's own per-test timings are captured (`pytest --durations=0 --setup-show` or the ctest log).
- `pidstat -u -d -r 1` and `/usr/bin/time -v` output is captured during a run.
- A breakdown table assigns the wall time to recipes and tests, and the named parts add up to the measured total within 10%.
- Each part that matters is profiled before it is explained. Use `py-spy record --subprocesses` or `perf record -g`, plus `python -X importtime` and `strace -f -c`.
- Each such part is classed as bound by CPU, I/O, sleeps, process spawning or serial steps.
- If `make check` has gotten slower over time, the change that did it is found with `git bisect run` and a time threshold, not guessed.
- Each cause is proven by an experiment on a scratch branch that is discarded afterward. Stubbing or skipping that one cause must drop `hyperfine`'s mean by the attributed amount, and the drop must fall outside the spread.
- The report gives:
  - the baseline with its spread
  - the breakdown table
  - each cause with its profile and its experiment
  - the time `make check` would take with all the causes removed, compared to the 10-second target

Where: `Makefile` and every file it includes; the recipes behind the `check` target; the test suite and its runner config (pytest config, `conftest.py` files, fixtures) or the ctest setup; git history of these files, for a bisect.

Do not touch: any fix to the build or the tests. Experiments go only on scratch branches, which are deleted afterward. Nothing is committed to or pushed from the working branch or the default branch.

Decisions: "Do not fix anything." "Start from the source data, not from impressions." "Prove each cause with an experiment on a scratch branch that is discarded afterward." The target is "10 seconds".

Design: none, this is a measurement and diagnosis task that changes no code.
