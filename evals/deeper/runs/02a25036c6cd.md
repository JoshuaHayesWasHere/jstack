# enforce-home-limits: Stop homes overrunning their limits by enforcing them before each model call and from outside via cgroups
Task: "Fix the homes running past their limits."
Done when:
- A baseline table (home, limit, actual, overrun %) exists, built from the raw record:
  - per-turn token usage in `~/.claude/projects/*/*.jsonl`, summed by session
  - each home's launch, crewmate launches and last message, taken from `jbus log`
  - both joined against the limits as written in each brief and home config
- For each limit, the one place it is checked is named, with why it misses (checked only between turns, crewmates' spend not counted, or advisory only).
- A home launched with a tiny limit is shown overrunning before any fix.
- A test that launches a home with a small limit fails before the fix and passes after. After the fix:
  - the home stops within one model call of its limit (≤5% over)
  - it posts a jbus message saying why it stopped
- The census rerun on the following week's transcripts shows 0 homes over their limit, against the baseline.
- Any home that still pushes past its limit is stopped by the cgroup, and the stop is recorded in journalctl.
Where: home code and jbus code (find the checks with `rg -n 'limit|budget|max_'`); the limits in each brief and home config; how homes are launched, so they can be wrapped in systemd-run/timeout; a new test for a home with a small limit
Do not touch: any limit beyond the ones the homes already have ("Do not widen the work beyond the limits the homes already have"); the transcripts and `jbus log` records, which are only read
Decisions: "Start from the raw record, not from impressions"; "Reproduce it first: launch a home with a tiny limit and show it overrunning"; "Fix it at that check: count spend before each model call, include crewmates, and enforce wall-clock and memory from outside the home with systemd-run/timeout limits, so a home cannot decide to keep going"
Design: none, the user already set the approach: fix each existing check in place and add outside enforcement with systemd-run/timeout
