# public-readiness-audit: Audit jstack against every public-repo standard and fix what fails before it goes public

Task: "We should not take jstack public until it passes every single audit that we could potentially throw at it for what would make a good public repository"

Done when:
- A secret scan of the working tree and full git history (gitleaks and trufflehog) reports no findings, and any hits are rotated and purged or shown to be false positives.
- No personal or machine-specific data remains in tracked files or history, including emails, `/home/<user>` paths, hostnames, thread ids and local config.
- An OSI license is chosen and recorded in `LICENSE`, and every dependency's license is compatible with it.
- `README.md` covers what jstack is, requirements, install, quickstart, how home, scouts, crewmates and reviewers fit together, and status.
- `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, `CHANGELOG.md`, issue and PR templates, and `CODEOWNERS` are present, so GitHub's community profile checklist is complete.
- Python packaging metadata is complete and the package installs cleanly in a fresh venv.
- Lint, format and type checks (e.g. ruff, mypy) pass with no ignores added to make them pass.
- The test suite passes in CI on a clean checkout.
- `pip-audit` and a static security scan (bandit or semgrep) report no unresolved high or critical findings.
- CI workflows exist with pinned action versions and least-privilege `permissions:`.
- An OpenSSF Scorecard run reports no avoidable failing checks, and any that remain are listed with the reason.
- Skills and playbooks contain no hard-coded paths, credentials, or instructions that assume the author's machine.
- Links in the docs resolve.
- A report at `docs/public-readiness.md` lists each audit run, its tool and version, its result, and what was fixed or knowingly accepted.

Where: the whole repo, including git history, `README.md`, the repo-root community files, `.github/`, Python packaging config, the skills, playbooks and commands, and the tests.

Do not touch: the repo's visibility and any remote settings. Do not make it public, push to a public remote, or rewrite published history without asking. Do not add CI ignores or suppressions just to turn a check green.

Decisions: "We should not take jstack public until it passes every single audit that we could potentially throw at it for what would make a good public repository"

Design: none, this is an audit-and-fix pass against established public-repo standards and needs no architecture choice.
