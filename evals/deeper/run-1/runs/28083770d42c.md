# make-check-slowdown: find what slows `make check`, why, and what changes on GitHub's hosted runners

Task: "figure out what is slowing down make check and why", and specifically what changes when CI flips to GitHub's hosted runners.

Done when:
- A table of the dominant steps is written down, with local warm time, local time at the runner's limits, predicted GitHub-runner time, and the cause of each (CPU-bound, IO-bound or waiting on the network), each backed by the measurement that shows it.
- Every timing comes from instruments, never a single run: `hyperfine --runs 10` cold (`--prepare 'make clean'`) and warm, `/usr/bin/time -v`, `perf stat`, `pidstat -u -d -r 1`.
- The runner was reproduced locally first, with `systemd-run --user --scope -p AllowedCPUs=<runner vCPUs> -p MemoryMax=<runner RAM>` or a fresh `docker run --cpus/--memory` container with empty caches. The sizes come from GitHub's published spec for the runner label the workflow uses, set next to this machine's `nproc`, `free -g` and `lscpu`.
- Core-count scaling of the slow steps is measured (`pytest -n 2` vs `-n 4`, `make -j`).
- If the slowdown has an onset in history, it is found with `git bisect run` and a timing threshold.
- The predictions are recorded before a GitHub run of the same commit. That run's step timings (`gh run view --json jobs`) fall within 15% of them for every dominant step.
- The hyperfine range at the runner's limits contains the real run's total.
- The user has read the table and agrees that it accounts for the time.

Where: `Makefile` (with `make -n check` and `make --trace check | ts -s` for per-target wall time); the test suite (`pytest --durations=0`, cold and warm); `.github/workflows/` (cache keys, setup steps, `-j`/`-n` flags); recent CI runs via `gh run view <id> --json jobs`; this machine's hardware.

Do not touch: the Makefile or the workflow. Do not trigger any CI run without asking the user first.

Decisions: "Start from the raw material, not from summaries"; "Measure with instruments, never a single timing"; "Reproduce the runner here before the flip"; "Do not change the Makefile or the workflow as part of this; ask me before triggering any CI run."

Design: none, this is a measurement and diagnosis task that changes no code.
