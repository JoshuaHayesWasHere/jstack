# ci-chrome-hang: Find why the first public check hangs at ~92–95% with Chrome left running, and fix it without raising the time limit
Task: "jstack's first public check never finished: two attempts on `ubuntu-latest` hung after the dots reached 92% and 95% and were cancelled at the job's 15-minute limit, with Chrome processes still running." Find out why and fix it, without raising the time limit.
Done when:
- GitHub's `ubuntu-latest` runner gives 20 consecutive green runs of the check, each under 5 minutes
- The local loop (`docker run --cpus=4 --memory=16g ubuntu:24.04`, 20 runs under `timeout 600`) goes from at least one hang in 20 before the fix to none in 20 after it
- The post-run `ps` shows no chrome/chromedriver left after pytest exits
- The test named in a dump before the fix passes after it
- The pytest step has a `timeout-minutes` under 15, and the job's 15-minute limit is unchanged
Where: `.github/workflows/` (the check's workflow file), the pytest config, the conftest fixtures that start and stop Chrome, the tests at ~92% and ~95% of `pytest --collect-only -q | nl`, the logs of both cancelled runs (`gh run view <run-id> --log`)
Do not touch: the job's 15-minute time limit (do not raise it); no code changes before a dump names the hang
Decisions: "Start from the raw material, not the summary: `gh run view <run-id> --log` for both cancelled runs (last lines and their timestamps), the workflow file in `.github/workflows/`, the pytest config, the conftest fixtures that start and stop Chrome, and `pytest --collect-only -q | nl` to name the tests sitting at ~92% and ~95%." "Make the hang name itself before changing any code. Run pytest with `-v -o faulthandler_timeout=120` (or pytest-timeout with `--timeout-method=thread`). Give the pytest step a `timeout-minutes` under 15. Add an `if: always()` step that records `ps -eo pid,ppid,etime,stat,wchan,cmd --forest` and `py-spy dump`, and uploads Chrome/driver logs as artifacts. Reproduce it locally in `docker run --cpus=4 --memory=16g ubuntu:24.04` in a 20-run loop under `timeout 600`, with `--durations=0`, and compare a fixed order against a random one. Fix the cause the dumps show, not a guess."
